## 人工主验证

每张证据记录执行时间、代码提交、测试角色、商品或事项的测试标识、观察结果和证据文件。页面证据按 `Axx-01` 命名，关联接口时保留方法、路径、状态码和必要的脱敏响应字段。数据库查询只使用隔离测试数据，保留必要列和行数。遮盖验证码、密码、邮箱完整地址、Cookie、Authorization、上传签名和私有对象标识。

### 环境与准备

- 用 `backend/.env.dev` 的隔离 PostgreSQL、Redis、私有 OSS 和测试 SMTP。保留探针摘要，包含数据库迁移版本、Redis 检查、OSS 写入／读回／删除结果、邮件送达时间及遮盖后的邮件截图。
- 在同一工作树用 `python3 scripts/dev.py start --env-file=backend/.env.dev` 启动。此轮使用原工作树的同一 `.env.dev`，已核实 API、两端页面、调度器及两个 worker 就绪。详见[启动与回归日志摘录](evidence/verification.txt)。通过用户端分别创建卖方、买方 A、买方 B 和无关用户，维护 CLI 创建管理员，管理端创建基础分类。

### 测试技术栈

| 层级 | 技术及用法 |
|---|---|
| 后端单元与 Web 测试切片 | Java 27、JUnit Jupiter（JUnit 5）、AssertJ、Mockito。Spring Boot Test 和 MockMvc 覆盖部分 HTTP 控制器与请求边界，由 Maven Surefire 执行。 |
| 后端集成 | JUnit Jupiter、Spring Boot 应用上下文、Java `HttpClient`、Spring `JdbcClient`，使用实际 PostgreSQL 和 Redis，由 Maven Failsafe 的 `integration` profile 执行。JaCoCo 收集覆盖率。 |
| 前端 | Vue 3 和 TypeScript 项目中直接使用 Node.js 原生 `node:test` 和 `node:assert/strict`，通过项目的 `register-ts.mjs` 加载 TypeScript。仓库内模拟接口及测试替身用于验证路由、API 封装和前端状态。两端另以 `vue-tsc --noEmit` 做类型检查。 |
| 运维脚本 | Python 标准库 `unittest`。 |

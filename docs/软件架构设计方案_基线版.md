# 软件架构设计方案（基线版）

本版按 2026-11-28 的 [`main@00a3367c`](https://github.com/iy88/se-course-project-1/commit/00a3367c86a8f4012fc6b9e1fe59266634b14159) 核对，覆盖 S1—S4 已合入实现。需求范围、决定、接口与证据由[基线索引](design/基线索引.md)统一定位。测试和验收采用各自登记的执行版本、环境及结论。

## 架构与交付

- 统一仓库交付用户端响应式网页与 PWA、管理端网页、Java／Spring Boot 后端及部署脚本。后端共用 PostgreSQL，通过 Flyway 管理迁移。Redis 支持会话、实时连接与任务协调，私有 OSS 保存媒体，SMTP 投递账户验证码。
- API、IM、worker 和 scheduler 按职责独立运行。Nginx 负责静态资源和 HTTP／WebSocket 入口，systemd 管理服务。Jenkins 以明确提交构建和发布，执行迁移及就绪检查；部署维护人按环境变更执行 OSS 前置探针。详见[运行与部署说明](design/运行与部署说明.md)。
- 主体模块保存各自拥有的状态。跨模块写操作在统一数据库事务内编排资格、锁、幂等、审计和事件意图，提交后由实时及任务组件投递。接口类型由 OpenAPI 契约生成。细节见[接口与关键设计说明书](接口与关键设计说明书.md)及[决策索引](design/decisions/01-确认与决策索引.md)。

## 业务交界

| 领域 | 当前采用的设计 | 主要验证入口 |
|---|---|---|
| 账户与公共能力 | 邮箱验证建立或恢复账户，凭据变更刷新 Session 资格；私有文件按已核验引用授权读取；通知、会话已读及待办各按自己的业务动作推进。 | [公共能力](design/test-cases/公共能力.md)、[批次 A、D](design/test-cases/reports/汇总.md) |
| 商品与交易 | 有效请求建立交易分支并保存购买快照，接受时锁单并保存受理快照。用户取消释放占用并恢复商品公开生命周期；交易完成或管理终止释放占用并下架。卖方按当前资格重新上架已下架商品。 | [商品与交易协同](design/detailed-design/key-designs/商品与交易协同.md)、[商品案例](design/test-cases/商品与分类.md)、[交易案例](design/test-cases/交易与评价.md) |
| 消息与治理 | 普通私聊按双人复用，逐笔交易与事项线程各自归档。事项按固定认领人、受影响账户及举报人投影；决定前合并同对象举报，决定后独立受理；按同事项证据执行处置、申辩和解除。 | [事项与会话案例](design/test-cases/会话与处置事项.md)、[批次 B、D](design/test-cases/reports/汇总.md) |

# AI-13 按用户故事重写多页 HTML 原型

- 日期／阶段：2026-10-23，按用户故事组织HTML原型。
- 操作者／决定者：袁尚峰。
- 工具及已知模型：DeepSeek Harness；deepseek-flash。

## 必要上下文

原 P-01—P-07 纸面原型按规则组织，页面内大量文字是第 4 章规则的转述；该原型没有成为任何用户故事、场景或验收条目的输入，原型走查也未开展，材料本身不产生评审或验收作用。操作者据此要求：改为按用户故事组织的多页 HTML 原型，一个 HTML 文件只做一个页面。

## 关键贡献与人工取舍

1. 按用户指定的多页与单文件单页面约束，组织目录页及14个故事页：一个文件一页、页面间链接跳转，不使用单页应用路由，不做前后端与状态存储。
2. 依据 US-01—US-14 的详细文档与验收条件，为 14 个故事页设计用户目标区、界面示意（用户端与管理员端分别用移动端／管理后台版式）和关键验收要点，页面不引用 BR／TR 编号，避免把规则条文重复进界面。
3. 统一 15 个页面的视觉与组件（设备框、卡片、状态标签、列表、表格、时间线、进度），补齐少量演示交互（标签页、开关、提示条），使页面可用于后续人工评审。

原型描述同步及旧文件清理属于维护，不另计AI实质贡献。

### 人工取舍

- 操作者明确要求以用户故事为依据、多个 HTML 文件、一个 HTML 一个页面，并排除单页应用方案；AI 按此实现，不再沿用规则驱动的纸面线框。
- 操作者确认示例数据与无后端的边界；原型人工观察与走查部分待写。

- 原型为界面补充材料，不改变用户故事、用例、场景、规则与验收条件；与需求正文冲突时以正文为准。
- 原型人工观察、走查及问题处理内容待写，不登记已完成结论。

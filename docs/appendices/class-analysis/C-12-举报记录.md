# C-12 举报记录

## 职责与边界

描述一次举报的对象、理由、可选证据及处理进度，并与 C-13 处置记录关联。举报由未被封禁的登录用户提交，被举报对象不因举报自动判定违规（BR-25）；处理结论由认领该事项的管理员记录，结果确认后隐去用户与管理员信息向所有已登录用户公开（BR-25、BR-26）。

边界：举报可指向商品、评论、消息、评价或用户；对象和原因必填，说明／截图等证据可选。举报记录不等于处置记录，也不代替交易争议。

同一用户对同一对象的举报在决定前合并补充说明或证据；决定后符合当前资格的举报另建事项。各事项保留各自的处理依据与归档记录。

提交举报须明确被举报对象并填写举报原因；补充说明、截图等证据可选，不强制上传截图才允许举报。认领管理员可在事项必要范围内查阅平台已有相关记录，材料不足不自动认定违规。

本期采用逻辑删除并保留历史记录；业务上的删除或失效不物理抹除已有记录及关联依据。对象删除或失效前已经提交的举报继续关联原对象并可处理，举报人可在本人已有举报事项中查看所关联的被举报内容；不因此开放对象其他私人记录或对方申辩内容。对象已删除或失效后尚未举报的用户再发起举报时，告知举报失败，不新建举报。

## 主要业务属性

举报者、对象及类型、原因及可选证据、处理进度、结论及公开结果。

## 关联与数量约束

| 关联 | 关联重数 | 说明 |
|---|---|---|
| 举报记录—举报者（C-01） | `0..* : 1` | 未被封禁的登录用户 |
| 举报记录—被举报对象 | `0..* : 1` | 对象可为商品、评论、消息、评价或用户 |
| 举报记录—处置记录（C-13） | `0..1 : 0..1` | 每项举报至多一份关联处置记录（与 C-13 及第 3 章一致），归属认领管理员 |
| 举报记录—账户限制记录（C-14） | `0..* : 0..*` | 处置涉及封禁时关联 |

同一用户对同一对象在原事项决定前补充材料。决定后符合资格的举报另建事项，原事项结案后归档。

## 关联规则、场景与用例

- 未被封禁的登录用户可举报商品、评论、消息、评价或用户，提交理由及可选证据：BR-25。
- 管理员按举报核查，记录结论及理由，可不予处理、移除违规内容或封禁账户；证据不足记录无法认定：BR-26。
- 举报结果须经管理员确认后匿名公开，确认前不可见：BR-25、BR-26、DT-05。
- 涉及私聊证据时，仅认领管理员查看该事项处理所需的相关消息：BR-19、BR-34。
- 违规处置涉及交易时按冻结规则处理，并撤销涉事商品公开访问：BR-33。
- 封禁期间禁止新增举报，已有记录保留只读：BR-32。
- 场景：SC-07；用例：UC-C07。

## 状态归属

进度：待处理（进入共享待处理池）、处理中（已认领）、无法认定、认定违规并处置（可含移除内容或封禁）。结果公开以管理员确认为前提，确认前不可见。状态说明见[对象状态分析](../scenarios/index.md#举报记录)。

## 补充业务约束

- 处置与申诉：需说明或实际受处置者经本人事项入口与 C-13 协作，保护举报人身份。
- 举报提交内容已定：明确对象、必填原因，补充说明和截图等证据可选。
- 举报处理时限：不承诺（BR-26），不在本类增加倒计时或自动关闭。

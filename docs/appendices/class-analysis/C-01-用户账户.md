# C-01 用户账户

## 职责与边界

承载校园用户的账户身份与登录入口，并作为其他业务对象的参与方：商品发布者、交易买方或卖方、评论作者、会话参与方、评价者、举报者、确认人、认领事项的管理员。账户负责提供身份，不代替各业务对象保存业务结果。

边界：买方、卖方是相对于商品或交易的身份，同一账户可随商品或交易担任不同身份，也不另立为类；管理员由管理资格区分，其处理具体事项另须满足认领关系；首版不核验校园身份或学籍；账户不承担站内通知（C-15）与处置沟通内容（C-13）。

## 主要业务属性

用户ID〔唯一、稳定〕、邮箱〔唯一、登录〕、显示名称、账户状态、管理资格、限制期间。

## 关联与数量约束

| 关联 | 关联重数 | 说明 |
|---|---|---|
| 用户账户—商品 | `1 : 0..*` | 作为发布者；一人可有多件商品 |
| 用户账户—收藏记录 | `1 : 0..*` | 仅本人清单可见 |
| 用户账户—商品评论 | `1 : 0..*` | 作为作者 |
| 用户账户—IM 会话／分支 | `1 : 0..*` | 作为双方之一参与；普通私聊按双人复用，交易 IM 按笔区分，冻结仅影响对应用户组合的聊天 |
| 用户账户—交易记录 | `1 : 0..*` | 分别作为买方、卖方 |
| 用户账户—评价 | `1 : 0..*` | 作为评价者或被评价者 |
| 用户账户—举报记录 | `1 : 0..*` | 作为举报者 |
| 用户账户—账户限制记录 | `1 : 0..*` | 多次封禁与解除分别记录 |

注册成功时系统为账户分配唯一用户 ID。邮箱已被其他账户使用时，注册或更换邮箱均拒绝；各账户以唯一用户 ID 区分，审计记录以用户 ID 关联实际操作者（BR-20、BR-21）。

## 关联规则、场景与用例

- 注册、登录、退出、自助重置、修改密码、更换绑定邮箱及修改显示名称：BR-20—BR-22、FR-01；邮箱及密码规则见第 4 章 4.19。
- 封禁期间禁止业务写操作，保留只读访问与管理沟通；仅交易冻结不扩大为账户封禁：BR-32、BR-33。
- 评价与举报资格：已完成交易、未被封禁；BR-24、BR-25。
- 管理访问限本人认领事项及必要范围：BR-19、BR-34。
- 场景：SC-01、SC-07；用例：UC-C01、UC-C08、UC-C12。

## 状态归属

账户限制状态：未限制、封禁生效、已解除（记录保留），依据 BR-32。账户本身不设“管理员”状态；账户生命周期覆盖注册、登录、退出、密码重置与资料维护。

## 补充业务约束

- 账户规则：改密须验证当前密码，更换邮箱须验证新旧邮箱，用户可主动退出登录。
- 受处置账户与认领管理员经 C-13 沟通，封禁／冻结不阻断该渠道。
- 管理资格与事项认领分别校验：具有管理资格才能认领，认领只授予该事项必要范围的处理权。

## 依据

[领域与数据](../../requirements/03-领域与数据.md) 3.2—3.3、[规则与权限](../../requirements/04-规则与权限.md)、[行为与状态](../../requirements/05-行为与状态.md) 5.2。

用户修改显示名称后，日常展示使用当前名称，同时保留操作发生时的名称记录及原用户归属供追溯；改名不产生新身份，不改变历史操作、举报或处置的归属。

更换账户邮箱时，必须同时验证旧邮箱和新邮箱均由本人控制，两项验证通过且新邮箱未被其他账户占用后才生效。更换邮箱后使用新邮箱登录，用户 ID、历史业务对象及审计记录的归属保持不变。

已登录用户主动修改密码时，须验证当前密码，通过后才可设置新密码；忘记当前密码时，使用绑定邮箱验证后的自助重置流程，不绕过验证直接修改。

本期显示名称允许用户自行修改，不设修改次数、修改间隔或人工审批要求；名称内容仍须遵守平台内容规则，违规时由管理员有依据处理。改名不改变账户身份及历史业务归属。

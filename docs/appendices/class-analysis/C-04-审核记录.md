# C-04 审核记录

## 职责与边界

记录认领管理员对某件商品及其内容范围的审核结论、拒绝理由与执行者，作为商品展示资格的依据之一。审核记录负责留痕，不直接改写商品生命周期；商品状态由审核结论与其他条件汇总得出。

边界：审核记录不能与商品状态混同（BR-13）；审核记录只承载商品审核，不承担举报处理（C-12／C-13）。

## 主要业务属性

商品及当次内容、认领管理员、审核时间、结论及拒绝原因。

## 关联与数量约束

| 关联 | 关联重数 | 说明 |
|---|---|---|
| 审核记录—商品 | `0..* : 1` | 首审、拒绝重提可形成多条结论，历史保留 |
| 审核记录—管理员 | `0..* : 1` | 限该事项认领人 |

## 关联规则、场景与用例

- 商品发布后由认领管理员审核，通过后才公开：BR-10、BR-13、BR-34。
- 审核不通过须显示拒绝原因：BR-10、TR-02。
- 审核检查描述与图片清晰、分类与价格合理完整、是否含明显违规或与二手交易无关内容：BR-13。
- 审核结论记录审核者、时间及拒绝理由：BR-13。
- 场景：SC-02；用例：UC-C02、UC-C08。

## 状态归属

结果表述：待处理（进入共享待处理池、尚未认领）、通过、不通过（含拒绝理由；退回补充作为不通过原因记录）。审核记录不设“商品状态”，也不因处置解除而改写。同一商品每次拒绝后重提均形成独立审核记录，关联当次被审核内容，保留审核者、时间、结果及拒绝原因；新记录不覆盖历史记录。

## 补充业务约束

- 每次重提形成独立记录并保存当次被审核内容，访问限本人及认领事项的必要范围。
- 同一事项由认领管理员处理，认领归属按 BR-34 保持。

## 必要行为与协作

| 行为职责 | 关联业务属性 | 协作目标 |
|---|---|---|
| 保存当次审核内容 | 商品及当次内容、认领管理员、审核时间、结论及拒绝原因 | UC-C02、UC-C08 |
| 记录审核结论 | 商品及当次内容、认领管理员、审核时间、结论及拒绝原因 | UC-C02、UC-C08 |
| 保留每次重提历史 | 商品及当次内容、认领管理员、审核时间、结论及拒绝原因 | UC-C02、UC-C08 |

业务动作由关联用例的当前主体、对象归属和状态资格触发；协作顺序见[完整用例索引](../use-cases/index.md)。

- 待审核期认领前后均允许卖方修改内容或分类，不重新排队；审核结论及当次被审核内容必须对应提交结论时的最新内容。撤回商品仅限认领前，撤回后重提进入新一轮审核，历史记录保留（BR-10、D-46）。

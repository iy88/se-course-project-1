# C-10 交付确认记录

状态：候选类分析初稿，负责人张新悦；未开展人工模型评审，不表示类职责已确认。

## 职责与边界

保存交易双方各自的完成确认：确认人、确认时间及可选交付说明，并区分“当前确认标记”与已保留的历史记录。平台外交付由双方自行完成，本类只记录确认，不核验实际交付、不强制上传凭证、不记录精确位置或支付信息（BR-32、BR-44）。

边界：双方记录分别保存，不允许覆盖对方记录；用户不得删除已提交历史（BR-43）；提交后不支持用户自行更正，确有更正需求时由管理员按处置记录处理并留存理由（BR-49）。本类不承担交易状态，也不决定商品是否售出。

## 主要业务属性

所属交易、确认者、确认时间、可选交付说明、当前标记与历史状态。属性为业务口径描述，不写字段类型或索引。

## 关联与数量约束

| 关联 | 重数（候选） | 说明 |
|---|---|---|
| 交付确认记录—交易记录（C-09） | 0..2 : 1 | 每方一条有效确认记录，历史记录保留 |
| 交付确认记录—确认者（C-01） | 0..* : 1 | 必须是本笔交易的买方或卖方 |

## 关联规则、场景与用例

- 双方各自确认，仅双方均确认后交易完成、商品已售出：BR-03、TR-16。
- 确认记录独立保存，不覆盖对方；用户不得删除历史：BR-32、BR-43。
- 争议解决恢复进行中时清空双方当前确认标记、保留历史，重新单方确认后才重启完整 7 天计时：BR-30、TR-21。
- 交付说明提交后不自行更正，更正走管理员处置并留理由：BR-49。
- 私人交付记录仅交易双方可查看，管理员限认领事项所需：BR-18、BR-25。
- 场景：SC-05、SC-06；用例：UC-C06。

## 状态归属

可表达的是“当前确认标记”：未确认、已确认（含确认人与时间）；历史记录只增不减。本类不设独立生命周期状态，也不与交易状态或异常交易状态混同；争议恢复只清标记、不清历史。

## 待决与边界

- P-14 已决待模型：恢复清空当前确认、保留历史、重新确认重启计时的衔接，需在状态图与场景中体现。
- 更正流程的处置记录细节（谁发起、如何留痕）属 P-22 相关范围，本类只引用，不自行设计交互。
- 交付确认与评价、统计的关系：评价以交易完成为前提，统计只按交易结果计数，不由本类派生。

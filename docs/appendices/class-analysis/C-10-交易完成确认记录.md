# C-10 交易完成确认记录

## 职责与边界

保存交易双方各自的一次交易完成确认，同时表达本人对交付与支付均已完成的声明，不设独立支付确认步骤：确认人、确认时间及可选交付说明，并区分“当前确认标记”与已保留的历史记录。平台外交付由双方自行完成，本类只记录确认，不核验实际交付、不强制上传凭证、不记录精确位置、实际支付流水或资金凭证；事先约定的支付安排由交易记录保留（BR-28、BR-30）。

边界：双方记录分别保存，不允许覆盖对方记录；用户不得删除已提交历史（BR-29）；提交后不支持用户自行更正，确有更正需求时由管理员按处置记录处理并留存理由（BR-29）。本类不承担交易状态，也不决定商品是否继续上架。

## 主要业务属性

所属交易、确认人用户ID、确认时间、可选说明、当前有效标记。

## 关联与数量约束

| 关联 | 关联重数 | 说明 |
|---|---|---|
| 交易完成确认记录—交易记录（C-09） | `0..* : 1` | 历次确认均保留；当前有效确认每方至多一条，共至多两条 |
| 交易完成确认记录—确认者（C-01） | `0..* : 1` | 必须是本笔交易的买方或卖方 |

## 关联规则、场景与用例

- 双方各自确认，普通双确认后交易完成、商品按结束后的上架选择处理；管理员状态调整不伪造用户确认：BR-04、TR-15。
- 确认记录独立保存，不覆盖对方；用户不得删除历史：BR-28、BR-29。
- 争议解决恢复进行中时清空双方当前确认标记、保留历史；恢复不启动计时，一方重新提交完成确认后才开始完整 7 天计时：BR-07、TR-19。
- 交付说明提交后不自行更正，更正走管理员处置并留理由：BR-29。
- 私人交付记录仅交易双方可查看，管理员限认领事项所需：BR-27、BR-34。
- 场景：SC-05、SC-06；用例：UC-C06。

## 状态归属

可表达的是“当前确认标记”：未确认、已确认（含确认人与时间）；历史记录只增不减。本类不设独立生命周期状态，也不与交易状态或异常交易状态混同；争议恢复只清标记、不清历史。

## 补充业务约束

- 恢复进行中时清空当前确认、保留历史；恢复不启动计时，重新提交完成确认后才开始完整 7 天，已在状态图与场景体现。
- 用户不能自行改写完成声明历史；认领管理员调整须保留前后状态、主体、时间及依据，不伪造确认。
- 交付确认与评价、统计的关系：评价以交易完成为前提，统计只按交易结果计数，不由本类派生。

## 约定变更与当前确认

单方确认后仍可由双方明确同意变更约定；变更生效时当前确认标记清空、原等待计时结束，原确认历史保留。未同意提案不清空或重置；生效后须重新提交完成确认才开始完整7天计时（第4章4.15、D-49）。

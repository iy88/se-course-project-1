# C-02 商品

状态：候选类分析初稿，负责人张新悦；未开展人工模型评审，不表示类职责已确认。

## 职责与边界

承载一件逻辑闲置物品的信息、业务生命周期与展示资格，并作为审核、收藏、评论、咨询会话及交易的关联对象。商品负责自身信息的维护与状态变化，不替审核记录保存结论，也不替交易记录保存确认结果。

边界：本项目按一件逻辑商品建模，一次交易完成即退出在售；多件逻辑商品与成交后保持在售仅为扩展候选。商品不承载付款、资金或物流信息。

## 主要业务属性

标题、描述、图片、价格、分类、发布者、当前展示状态；其中标题、描述、图片、价格、分类为关键内容（BR-12）。属性为业务口径描述，不写字段类型或索引。

## 关联规则、场景与用例

- 首次审核通过后才对其他用户公开：BR-10、BR-33。
- 信息修改不触发二次审核、不暂停公开、不关闭已有请求，且仅限微调：BR-11、BR-31、TR-04。
- 审核不通过须显示拒绝原因，可修改重提：BR-14、TR-02、TR-03。
- 交易中、已售出禁止修改关键内容：BR-15。
- 交易中与已售出退出在售列表与搜索，但登录用户仍可查看详情并显示状态：BR-24、BR-46。
- 待接受请求不使商品进入交易中；接受一条请求后其余请求关闭：BR-28、DT-01。
- 交易中允许评论及卖方回复，已售出禁止请求、评论与回复：BR-46、BR-47。
- 违规处置撤销涉事商品公开访问，解除后恢复原展示资格且不改变原在售与否：BR-53、TR-10、TR-11。
- 场景：SC-02、SC-03、SC-05、SC-06；用例：UC-C02、UC-C03、UC-C09。

## 状态归属

业务生命周期：待审核、审核未通过、公开可交易、交易中、已售出、已下架（转换见 [5.2 商品](../../requirements/05-行为与状态.md)）。展示资格（是否对登录用户可见）作为条件单独表达：违规撤销公开访问、处置解除后恢复、封禁账户商品停止展示，均不新增互斥状态。

## 待决与边界

- P-15／P-16：主动下架关闭待接受请求并说明原因；超时异常按冻结规则限制双方，均需在状态图体现，已决待模型。
- P-18：分类维护、停用或删除后既有商品与筛选的处理。
- TR 缺口：公开可交易→已下架、已下架→公开可交易两条转换目前只有 BR-31 依据，TR 未单列，待组长决定是否补编号。

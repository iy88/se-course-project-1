# C-07 IM 会话（普通私聊／交易分支）

## 职责与边界

区分普通私聊与交易 IM 两类，可在同一双人 IM 入口下组织；消息分别归属普通私聊或具体交易分支。

普通私聊以一对用户为参与者，双方可从卖方个人页等入口主动发起，不要求购买请求，不随某笔交易结束自动归档。交易 IM 由有效购买请求联动，每笔 C-09 请求／交易对应自己的分支及系统请求通知，随该笔生命周期管理；请求拒绝、撤回、关闭，或交易终止、完成后，分支默认归档、保留历史，并可引导普通私聊。引导由用户选择，不自动搬移交易记录或创建普通私聊。

冻结归属于具体交易，但其 IM 禁发作用于对应用户组合：p、q 的交易 A 冻结，两人之间普通私聊及所有交易 IM 分支（含交易 B）全部禁发、历史可读；p–s、q–t 的两类 IM 不受 A 影响。账户封禁另行适用，仍有任一有效的 p、q 交易冻结时，两人间禁发保持；冻结不等于交易结束或归档。管理员处置沟通仍由 C-13 承担。

## 主要业务属性

会话类别、参与双方、交易分支所属请求／交易、建立时间、归档标记。

## 关联与数量约束

| 关联 | 关联重数 | 说明 |
|---|---|---|
| IM 会话／分支—用户账户（C-01） | `0..* : 2` | 每会话两个不同用户；同一对用户普通私聊复用 |
| 交易 IM 分支—请求／交易记录（C-09） | `1 : 1` | 每笔有效请求有自己的交易分支，不复用其他交易分支 |
| IM 会话／分支—消息（C-08） | `1 : 0..*` | 两类及不同交易分支的历史归属分开 |

## 关联规则、场景与用例

- 普通私聊入口与双方主动发起，交易分支按笔联动：BR-01、BR-18。
- 交易结束分支默认归档、历史保留，并可引导普通私聊：BR-18。
- 不向本人发起；接受购买请求须由卖方明确操作，聊天不代替请求或接受：BR-01、BR-02、BR-18。
- 交易冻结下 p、q 之间两类禁发，不影响 p–s／q–t；账户封禁另行适用：BR-32、BR-33。
- 管理访问限认领事项相关必要消息，不因此扩大到普通私聊及其他交易分支：BR-19、BR-34。
- 场景：SC-04、SC-05；用例：UC-C04、UC-C05。

## 状态归属

普通私聊不随某笔交易结束归档。交易 IM 分支随具体请求／交易处于生命周期内或结束后归档，归档保留历史；交易冻结是另行检查的发送限制，不代替交易生命周期状态，也不等同归档。

## 补充业务约束

普通私聊引导由用户主动选择；普通私聊与交易分支分别保留消息归属。通知与消息按实际打开／显示范围分别标读，见第 4 章 4.17。

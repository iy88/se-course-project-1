# C-15 站内通知（支撑性对象）

## 职责与属性

记录事件、接收人、关联业务对象、产生时间及未读／已读。只做提醒和入口，不复制审核／交易／处置结论，不代替C-13的说明申辩沟通。业务提醒通过站内通知中心提供。

## 关联与规则

- 一条通知一名接收人，同一事件可按各方资格分别通知；同一请求在通知中心和交易分支的入口指向同一事项，不重复建请求。
- 触发及接收范围见[规则4.17](../../requirements/04-规则与权限.md#417-通知未读及管理沟通)，覆盖审核、请求、约定及变更、完成、取消、商品编辑、冻结／解冻、管理调整、举报及申辩结果。
- 打开具体通知才已读，列表访问不算；聊天按会话／分支独立已读，通知已读不代消息已读，更不代业务确认。
- 旧通知入口显示当前业务状态，进入时重查资格；通知不授予额外私人访问权。结束记录不因通知已读删除。
- 来源弱关联到C-04、C-09、C-13等对象，只定位，不代替结论。

## 依据

FR-11、UC-C11、SC-11；通知中心与个人业务入口共同定位同一业务记录。

## 主要业务属性

业务事件、接收人、来源业务对象、内容及产生时间、未读／已读标记。

## 必要行为与协作

| 行为职责 | 关联业务属性 | 协作目标 |
|---|---|---|
| 按业务事件产生提醒 | 业务事件、接收人、来源业务对象、内容及产生时间、未读／已读标记 | UC-C11 |
| 按当前资格定位事项 | 业务事件、接收人、来源业务对象、内容及产生时间、未读／已读标记 | UC-C11 |
| 打开具体通知后标为已读 | 业务事件、接收人、来源业务对象、内容及产生时间、未读／已读标记 | UC-C11 |

业务动作由关联用例的当前主体、对象归属和状态资格触发；协作顺序见[完整用例索引](../use-cases/index.md)。

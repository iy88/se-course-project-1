# C-08 消息

## 职责与边界

分别保存普通私聊或交易 IM 分支内的用户文字；系统购买请求通知归属对应交易分支，记录用户发送者或系统来源、时间以及通知关联的商品及请求，并承载访问资格：会话双方可读取；认领事项的管理员仅可读取与该事项相关的必要消息，不得因认领一笔交易而读取双方普通私聊及其他交易分支的全部消息。消息不向非会话成员公开（BR-17）。

边界：首版不支持撤回、编辑、附件及群聊；消息不承载处置通知与沟通单（BR-17、BR-32）。管理访问限于认领事项处理所需的相关消息（BR-19、BR-34）。

## 主要业务属性

所属会话／分支、用户发送者或系统来源、内容、发送时间、接收方已读标记、关联商品及请求。

## 关联与数量约束

| 关联 | 关联重数 | 说明 |
|---|---|---|
| 消息—IM 会话／分支（C-07） | `0..* : 1` | 消息归属各自普通私聊或具体交易分支 |
| 用户文字消息—发送者（C-01） | `0..* : 1` | 必须是会话参与方；系统请求通知由系统产生，不伪装成用户文字 |
| 系统请求通知—购买请求及商品 | 各关联具体业务对象 | 保留发起人及时间，通知与业务记录分别保留；分支归档不删除消息 |

## 关联规则、场景与用例

- 用户文字不提供撤回、编辑与附件：BR-17；系统购买请求通知是业务事件消息，不等同用户聊天：BR-01、BR-18。
- 封禁或涉事冻结期间禁止发送，历史消息保留读取：BR-18、BR-32、BR-33。
- 管理员仅在举报或争议处理时查看相关消息：BR-19、BR-34。
- 场景：SC-04、SC-05；用例：UC-C04、UC-C05。

## 状态归属

消息不设生命周期状态；可表达的是发送资格与读取资格随账户封禁及双方间有效交易冻结变化；p、q 的冻结不限制 p–s 或 q–t 的两类 IM，不由商品展示状态决定。消息一经发送不修改，故不需要状态机。

## 补充业务约束

- 消息仅实际显示范围标为已读；打开列表、其他分支或通知不标读本分支消息，与 C-15 通知已读分开。

## 依据

[领域与数据](../../requirements/03-领域与数据.md) 3.2—3.3、[规则与权限](../../requirements/04-规则与权限.md) 4.4。

普通私聊和各笔交易聊天分支分别计算消息未读；用户打开并查看具体会话／分支时，仅将该会话／分支已展示消息标为已读。仅进入会话列表、查看其他分支或将通知中心提醒标为已读，不自动消除未查看聊天消息的未读标记。消息已读不代替购买请求接受、约定确认或交易完成确认。

## 必要行为与协作

| 行为职责 | 关联业务属性 | 协作目标 |
|---|---|---|
| 保存文字或系统请求消息 | 所属会话／分支、用户发送者或系统来源、内容、发送时间、接收方已读标记、关联商品及请求 | UC-C04、UC-C05、UC-C11 |
| 按实际展示范围标记已读 | 所属会话／分支、用户发送者或系统来源、内容、发送时间、接收方已读标记、关联商品及请求 | UC-C04、UC-C05、UC-C11 |

业务动作由关联用例的当前主体、对象归属和状态资格触发；协作顺序见[完整用例索引](../use-cases/index.md)。

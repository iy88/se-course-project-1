# US-06 记录线下交付

## 用户目标与价值

作为交易双方，我希望在约定生效后分别提交交付及支付均已完成的声明并查看历史，以便保留各自确认人与时间，支持后续核对而不混同平台核实。

| 项目 | 内容 |
|---|---|
| 关联功能 | FR-06 |
| 主用例 | UC-C06，详见[完整用例索引](../use-cases/index.md) |
| 协作用例 | UC-C05、UC-C08 |
| 场景 | SC-05、SC-06 |
| 优先级／批次 | 高／1 |
| 触发规律 | 双方平台外履行后在交易中确认，或查看／申请管理更正已有记录 |
| 规则依据 | BR-04、BR-07、BR-27、BR-28、BR-29、BR-30 |

## 业务内容与操作资格

- 交付及支付的安排随交易约定保存，与完成声明分开。
- 在US-05的同一完成确认入口，用户一次声明两项均已完成，可填写说明；双方分别留存。
- 争议恢复或管理恢复清空当前确认标记、保留历史，再确认形成新的历史记录。
- 确需更正已提交记录时由认领管理员有依据调整，原记录和处理依据继续保留。

各操作按当前账户、对象归属、商品／交易状态及事项权限校验；封禁、冻结与管理沟通例外分别按对应业务规则处理。

## 验收条件

| 编号 | 前置情境 | 用户操作或事件 | 预期结果 | 依据 |
|---|---|---|---|---|
| US-06-AC-01 | 尚无双方明确同意的约定 | 普通用户尝试提交完成确认 | 拒绝；先完成约定确认 | BR-04 |
| US-06-AC-02 | 约定有效、当前资格允许 | 一方提交一次完成确认 | 记录该用户ID、时间和可选说明，同时声明交付与支付完成，不要求第二个交付确认步骤 | BR-28 |
| US-06-AC-03 | 已有一方确认 | 另一方确认 | 两方记录互不覆盖，普通流程更新交易完成 | BR-04、BR-29 |
| US-06-AC-04 | 争议解决并恢复进行中 | 查看当前进度及历史 | 当前确认清空，原历史保留；恢复不启动计时，重新提交完成确认产生新记录并开始相应计时 | BR-07、BR-29 |
| US-06-AC-05 | 完成声明已提交 | 用户自行更正或删除 | 拒绝自行改写；认领管理员处理须留原记录与依据 | BR-29 |
| US-06-AC-06 | 用户或管理员访问记录 | 查看确认历史 | 双方仅本人参与交易可见，管理员限本人认领事项必要范围；记录表示声明而非平台核实 | BR-27、BR-28、BR-29 |

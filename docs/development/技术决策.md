# 技术决策与系统架构

## 系统组成

```text
Mobile PWA / Admin Web
          |
        Nginx
          +---- /api/ ----> API ----> SMTP
          +---- /ws ------> WS

API / WS / Taskiq worker
          +----> PostgreSQL：业务、审计、实时事件
          +----> Redis：实时分发、控制状态、任务队列

Taskiq scheduler ----> Redis 任务队列 ----> Taskiq worker

Mobile PWA ---- 短期签名 PUT ----> 私有 OSS 媒体桶 / 证据桶
API       ---- 对象校验与签名 ---> 私有 OSS 媒体桶 / 证据桶
```

| 组件 | 技术与职责 |
|---|---|
| 移动端 | Vue / Vite PWA，商品、交易、消息与个人业务入口 |
| 管理端 | Vue / Vite，审核、处置、统计与分类维护 |
| API | FastAPI、Pydantic v2、SQLModel，承载业务接口与上传授权 |
| WS | 独立 gateway，管理连接、事件回放、推送、ACK 与心跳 |
| 后台任务 | Taskiq worker 消费任务，单实例 scheduler 派发周期任务 |
| 持久数据 | PostgreSQL，SQLAlchemy 异步引擎与 Alembic 迁移 |
| 共享状态 | Redis 8.2+，连接控制、频率限制、事件流和任务队列 |
| 文件与邮件 | OSS 私有双桶、SMTP 验证码投递 |

API、WS、worker 和 scheduler 共享版本及环境配置，分别建立 SQL 和 Redis 连接池。进程数、池大小、overflow 与连接预算由 dotenv 集中配置。

## 配置与数据库权限

`APP_ENV_FILE` 选择配置文件，`APP_RUNTIME_ROLE` 选择运行角色。配置加载器校验字段、环境和资源组合，再为各角色构建运行参数。生产数据库使用 PostgreSQL；SQLite 支持本地独立运行。

每个数据库环境采用三个角色：owner 持有结构且使用 NOLOGIN，migrator 登录后显式 `SET ROLE owner` 执行迁移，app 获得业务 DML 与必要序列权限。审计表对 app 开放 SELECT/INSERT，对象登记表采用受控回收权限。生产结构更新统一通过 Alembic。

身份认证使用 JWT Bearer 和 bcrypt 密码哈希。客户端退出时清除令牌。价格以整数“分”持久化，界面换算为元；时间统一使用 UTC，历史记录通过独立记录保存。

## 实时事件与任务处理

```text
业务事务 --> 业务记录 + 审计 + 用户事件 + outbox
                                           |
                                    Taskiq outbox 任务
                                           |
                                      Redis stream
                                           |
                          各 WS gateway 独立读取游标
                                           |
                                   用户连接 --> ACK

PostgreSQL 用户事件 ------ 回放 / 周期补偿 ------> WS gateway
```

业务变更、审计和实时事件同事务提交。每个用户以独立 `user_seq` 表示事件顺序。outbox 任务用短事务认领批次，提交后发布到 Redis，再登记投递结果；lease、有限重试与幂等消费支持故障恢复。

WS gateway 分别读取共享事件流，并按用户筛选到本机连接。PostgreSQL 保存事件供断线回放和周期水位补偿；Redis stream 承担实时分发。Taskiq 任务队列使用独立的 stream/group，worker 执行成功后确认任务，SmartRetry 与调度源管理重试。

worker 执行 outbox、交易超时扫描、事件保留和幂等记录清理；scheduler 单实例运行。SQL 池、Redis 控制池、发布池和阻塞读取池分别配置获取及连接超时。outbox 准入按待投递数量与年龄控制写入压力，过载响应携带 `Retry-After`。

## 连接协议

1. 客户端以 Bearer JWT 调用 `POST /api/v1/realtime/ticket`，提交当前游标。
2. API 签发短期一次性 ticket；客户端连接 `/ws?ticket=...`。
3. gateway 校验 ticket、Origin、用户和连接限额，发送 `hello`、补发事件及 `replay_complete`。
4. 客户端按 `user_seq` 连续应用事件，以 `event_id` 去重并 ACK。
5. 断线后从已确认游标重连；遇到 `resync_required` 时重新获取业务快照。

每条连接使用一个 writer 和有界消息/字节队列，统一发送事件及控制帧。心跳、发送超时、帧大小、频率和连接配额共同约束资源使用；慢连接按协议断开并通过重连恢复。

## 事务与业务一致性

交易先锁商品再锁交易，锁后重新读取状态；唯一约束保护同商品锁单和同买方待处理请求。约定、确认、交易转换、通知和成功审计在同一事务提交。冻结使用独立标记，并保存暂停计时信息。

商品发布按对象 key 排序取得登记行锁，完成业务引用后将对象转为 `committed`。上传完成先锁租约再锁对象登记，重复完成返回一致结果。支持幂等键的写入口将幂等结果与业务事务共同持久化，同键不同请求内容返回冲突。

商品审核、举报、争议、异常和封禁由统一处置事项承载，管理员通过条件更新取得唯一认领。普通聊天、交易分支、事项沟通和通知分别保存读取进度与业务状态。

## 文件上传与读取

媒体桶保存商品、头像和聊天图片，证据桶保存举报材料。数据库记录逻辑对象 key，后端根据命名空间选择对应桶。

上传流程为“API 创建租约并登记 staged → 浏览器凭短期签名 PUT 直传 → API 核对 HEAD 与实际内容 → 业务事务建立引用”。PUT 使用租约返回的 URL 和签名请求头；完成校验检查大小、MIME、SHA-256 和图片完整性。读取由 API 按权限签发短期 GET URL。

OSS CORS 列明实际前端 Origin、PUT 方法及 `Content-Type`、`x-oss-meta-sha256`、`x-oss-forbid-overwrite` 请求头。租约有效期内对象受保护；到期且无业务引用的暂存对象通过回收工具清理，证据对象采用专门保护策略。

## SMTP 与审计

API 通过 SMTP 发送注册、找回密码和换邮箱验证码，支持 SSL 和 STARTTLS 证书校验。验证码按用途、收件人和有效期管理；发送失败返回脱敏错误并撤销本次验证码及频控状态。

审计记录 UTC 时间、request_id、操作者、目标、结果、原因码及必要的脱敏变更值。成功变更与业务同事务，拒绝操作通过独立短事务记录。代理来源按显式可信 IP/CIDR 解析，后台任务以 system 身份记账。

## 文本与 Unicode 规则

人类文本采用 Unicode 17 扩展字素簇计数：前端使用 `unicode-segmenter`，后端使用 `regex` 的 `\X`。前后端统一换行为 LF 并去除约定的首尾空白，保留内部内容和组合字符。密码、邮箱、URL、对象键和协议字段按各自 schema 校验。

| 内容 | 字素簇上限 |
|---|---:|
| 显示名、分类名称、分类别名、禁发类别 | 64 |
| 商品标题 | 120 |
| 商品描述 | 5,000 |
| 评论、卖方回复、普通私聊、交易分支消息 | 2,000 / 条 |
| 事项说明、申辩、问询与回复、举报补充 | 2,000 / 条 |
| 评价、争议描述 | 1,000 |
| 举报原因、购买留言、确认备注、审核及处置理由与依据、禁发内容 | 500 |
| 取消及拒绝原因、交付时间/地点/方式、支付时机、处置摘要 | 200 |
| 支付方式 | 100 |

编码容量另按 `min(字素簇上限 × 32, 65536)` 字节校验。输入组件显示数量与上限，超限时保留草稿并显示错误，输入法组合期间保持输入连续。API schema 用 `x-max-graphemes` 和 `x-max-utf8-bytes` 描述约束；数据库人类文本字段采用 TEXT。

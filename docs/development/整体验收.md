## 浏览器人工验收流程

完整人工测试由环境核验、自动化回归、浏览器多角色流程、异常/兼容测试、逐条需求复核及缺陷回归六部分组成。全部必测项完成、阻断缺陷关闭、AC/场景每个子条件有相符证据后才可给出相应范围通过结论。缺界面入口记 BLOCKED-UI，缺账号/数据/设备记 BLOCKED 或 NOT-RUN，预期拒绝且证明未写入可 PASS；N/A 写理由及负责人决定。自动化报告状态不继承为人工 PASS。逐条需求复核按 `docs/requirements` 01—08 与详细 US／UC／SC 材料对照 runner 目录执行；人工记录（步骤、预期、实际、脱敏截图、缺陷号、复核人）由执行者在本轮运行目录留存，结果状态以本文件更新为准。

身份与会话：至少 S/S2 卖方、B1/B2 买方、O 第三方、A1/A2 管理员；封禁等破坏性身份额外准备。初始与第二名管理员由持久化 `app.manage seed` 创建（`--admin-email`），普通身份经注册流程创建；全部账号仅用于 test。A1/A2 必须使用独立浏览器配置文件（不同标签页和隐私窗口通常共享 localStorage）。

数据与证据：对象标题/原因含本轮标识并登记 run_id、分支/HEAD、操作者、浏览器/OS/视口；用 UI 创造正常业务状态，时间与竞态才由测试服务补充。素材覆盖小图/多图/接近与超过上限/空文件/扩展名伪造及边界文本；图片另核对直传租约全链路（PUT 无应用 Authorization、完成校验 `x-oss-meta-sha256`、失败对象不入 `image_keys`）。注册、找回密码、换邮箱须以真实收件箱邮件到达为准。网络证据不公开原始 HAR。

缺陷分级：P0 误用生产/越权/秘密泄漏/数据不可恢复破坏（立即停止相关场景）；P1 主流程不可达、重复锁单/完成、重要状态错误、缺权限控制（修复前不宣告通过）；P2 可恢复局部问题；P3 细节仍记录。建议按"账户及发布 → 检索/消息及完整交易 → 争议/治理/管理 → 异常网络/多浏览器/PWA 与逐条复核"分批执行并保存状态。

## SMTP 与自动化邮件隔离

普通运行固定使用 SMTP：主机、端口、安全模式（SSL/STARTTLS 均验证证书）、账户、密码、寄件人缺失或占位即拒绝启动；发送失败返回脱敏 503 并撤销本次验证码与频控键；接口和前端已移除开发验证码明文显示。自动化从 `.env.dev` 读取基准连接配置，跳过 SMTP 校验后生成本轮私有 capture 配置，邮件仅写入本轮 0700 目录的 0600 邮箱文件，测试从该文件按用途/收件人读取验证码并断言 HTTP 无验证码字段；该文件在成功/异常清理时删除。生产环境及非本轮 schema 不能启用 capture。

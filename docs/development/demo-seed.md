# 演示数据与操作路线

本文按现行需求组织演示路线。预置数据用于历史展示，现场操作用于观察实际行为；改变状态后使用另一条适合的记录或重新准备数据，各分支的完整资格与预期以 `docs/requirements` 01—08 及详细 US／UC／SC 材料为准。

## 准备与启动

先确认 `backend/.env.dev` 指向预期的演示数据库与存储（PostgreSQL + OSS 或 SQLite + local），并准备好相应服务。迁移和演示 seed 作用于所选环境，使用前确认目标：

```bash
(cd backend && APP_ENV_FILE=.env.dev .venv/bin/python -m app.manage migrate)
(cd backend && .venv/bin/python -m app.manage demo-seed --env-file .env.dev)
./scripts/dev.sh start
```

服务读取同一环境文件；若使用其他文件，迁移和 `start` 同样设置 `APP_ENV_FILE`，seed 的 `--env-file` 指向同一文件。默认 manifest 位于 `var/demo/manifest.json`，含演示登录信息，按敏感文件保管；需要独立演示批次时指定 `--manifest <路径>`。manifest 的 `accounts` 给出邮箱和密码，`objects` 给出记录 ID，账户密码以 manifest 为准。中断后用同一 manifest 重跑，命令复用已写入文件并补齐剩余；成功后的重复执行保留人工修改和业务处理结果。

| 身份或对象 | 用途 |
|---|---|
| `admin`、`admin2` | 管理员认领、处理与另一管理员权限检查 |
| `seller`、`buyer`、`buyer2`、`outsider` | 商品发布、购买竞争、咨询和越权检查 |
| `frozen_seller`、`frozen_buyer` | 独立冻结交易及双方沟通限制 |
| `banned`、`ban_seller` | 封禁与关联请求、交易及解除限制 |
| `timeout_seller`、`timeout_buyer` | 单方确认超时和异常处置 |
| `product_listed`、`product_pending`、`product_rejected`、`product_delisted` | 搜索／收藏、待审、拒绝后重提及重新上架 |
| `trade_request_buyer`、`trade_request_buyer2` | 同一商品两条待接受请求，接受一条后观察另一条关闭 |
| `trade_progress`、`trade_confirm`、`trade_completed`、`trade_reviewed`、`trade_disputed` | 待约定、已约定单方确认、完成、已评价及争议历史 |
| `trade_timeout`、`agreement_timeout` | 已超等待阈值的历史确认，启动扫描后观察异常事项 |
| `trade_frozen`、`trade_ban_progress`、`trade_ban_request` | 冻结和封禁关联记录 |
| `category`、`category_unused` | 已使用分类（含别名）及未关联分类 |
| `case_product_review`、`case_report`、`case_report_handled`、`case_dispute_disputed`、`case_dispute_frozen`、`case_ban` | 审核、待处理/已处置举报、争议及封禁事项 |
| `conversation_normal`、交易会话和通知 | 普通私聊与按笔交易分支、独立已读及业务通知 |

建议先查看搜索、收藏及本人业务，再进行审核、请求竞争及交易确认，最后进行举报和限制处置；会改变资格或结束记录的分支使用独立对象。演示账号使用 example.com 地址；注册、找回密码及换邮箱须用真实可收件账号完成邮箱验证；七天超时用 seed 预置的历史确认时间，由现有扫描任务实际判断和转异常。

## 演示路线与需求映射

每行一组故事及其同号主用例；操作由对应角色实际执行并当场观察结果，互斥分支使用不同记录。

| 用户故事／用例 | 触发、分支及预期结果 | 场景 |
|---|---|---|
| US-01 / UC-C01 | 登录、退出、邮箱注册、找回及修改密码、换邮箱和显示名称；错误凭证、重复邮箱或未验证邮箱被拒绝，封禁后保留合格只读及管理沟通。 | SC-01 |
| US-02 / UC-C02 | 查看禁发范围并发布；管理员审核通过或拒绝，看原因后修改重提；编辑、下架关请求、重新上架；锁单期间下架及关键修改被拒。 | SC-02、SC-10 |
| US-03 / UC-C03 | 关键词、多标签及价格组合查询与详情；空结果、别名定位同一分类，受限商品不泄露详情。 | SC-03、SC-10 |
| US-04 / UC-C04 | 收藏、评论、普通私聊；请求后进入交易分支；取消收藏、删除评论、失效收藏、各会话独立未读；越权拒绝。 | SC-03、SC-04、SC-11 |
| US-05 / UC-C05 | 两买方同商品请求，接受一条锁单关闭另一条；拒绝、撤回、约定同意/拒绝/变更、双方确认、取消和争议。 | SC-05、SC-06、SC-09、SC-11 |
| US-06 / UC-C06 | 双方各提交一次交付与支付完成声明；更正经管理事项由管理员留据处理，用户不改写历史。 | SC-05、SC-06 |
| US-07 / UC-C07 | 完成后双向评价，重复或未完成拒绝；举报、补充、结案只读；本人评价与匿名结果查询。 | SC-07、SC-12 |
| US-08 / UC-C08 | 认领审核/举报，记录结论理由；问询、说明、申辩、回复留痕；另一管理员不能重复认领；封禁/解除、冻结/恢复按资格核对。 | SC-02、SC-06、SC-07、SC-09 |
| US-09 / UC-C09 | 对照公开、交易中、下架及受限商品的状态与操作；结束默认下架，有资格可明确继续上架。 | SC-02、SC-03、SC-05、SC-06、SC-09 |
| US-10 / UC-C10 | 统计分别按显式时间范围与全部查询；未选择范围不当作默认全部。 | SC-08 |
| US-11 / UC-C11 | 业务事件触发通知与待办；打开才标已读，聊天已读独立，进入通知不代替业务确认。 | SC-11 |
| US-12 / UC-C12 | 双身份查看我的商品/交易/收藏/评价/举报；结束记录只读，收到举报仅展示已处置且隐举报人。 | SC-12 |
| US-13 / UC-C13 | 分类新建、改名、别名维护；标签申请随审核通过生效；已关联仅停用，未关联可逻辑删除，历史保留。 | SC-10、SC-03 |
| US-14 / UC-C14 | 单方确认超时由系统任务触发异常和冻结；管理员认领、留据处理及通知；恢复清当前确认保留历史；不伪造双方确认。 | SC-09、SC-05、SC-06、SC-11 |

特别检查：SC-04 各会话分别标读；SC-05 多请求关闭、拒绝、撤回、取消及变更确认用独立记录；SC-06 争议恢复保留历史、重新确认才开始完整等待；SC-07 问询、处置与申辩不混同；SC-09 超时用预置历史时间由实际任务触发；SC-10 分类变更保留身份和历史；SC-12 本人入口按权限读取。

## 主用例操作要点

- **UC-C01**：注册须先验证当前邮箱、验证码不可跨邮箱/用途/重用；登录失败不锁定账户；退出后访问需重新登录（服务端吊销暂不处理）；找回密码与换邮箱后 ID 及历史保持。
- **UC-C02**：发布进入待审核并等认领；未通过修改重提生成新审核记录；认领前可撤回（撤回后已下架、旧审核入口失效）；编辑保留展示与未结束请求并通知买方；下架关闭待接受请求；重新上架要求资格与限制允许。
- **UC-C03**：关键词覆盖标题/描述/分类主名与未移除别名；多标签全部匹配、价格含端点；无匹配返回空列表并隐藏非公开商品。
- **UC-C04**：收藏他人不可见，失效商品可取消但不开放内容；评论可回复（仅卖方）、可逻辑删除；普通私聊双人复用，仅已展示消息标读。
- **UC-C05**：接受即锁单并关闭其他待接受请求；约定提议被拒只结束提案；变更经对方同意才替换并清当前确认与旧计时，重确认后完整 7 天等待；取消分约定前买方直接取消/卖方申请需同意/约定后双方同意；争议保持锁单并结束计时。
- **UC-C06**：每方每笔交易一次完成声明；双方确认后完成；确认历史与重置标记分开读取。
- **UC-C07**：评价 1—5 分加文字，完成后每方一次；"我的评价"按发表/收到读取，不公开在商品页；举报未结可补充、已结案只读；公开结果仅管理员确认后可见且匿名。
- **UC-C08**：唯一认领由系统竞争判定，另一管理员 409；问询面向被询问用户，说明/申辩按通知入口提交；处置记录理由并通知；封禁/冻结的解除按依据并保留其他限制。
- **UC-C09**：状态联动——接受锁单、结束默认下架、处置撤展示；恢复公开须卖方有资格且明确操作。
- **UC-C10**：完成交易按结果确认时间统计，状态数按查询时点；范围必须显式选择。
- **UC-C11**：待办来自当前既有事项、办结自动移出；通知已读不办结业务；管理员共享池无个人通知。
- **UC-C12**：本人入口聚合双身份；结束交易只读；我收到的举报仅已处置且隐举报人。
- **UC-C13**：改名保留旧别名，分类身份与历史保持；移除别名不改归属；纠正分类留前后内容并通知卖方。
- **UC-C14**：异常由真实扫描任务触发；管理员留据调整并通知；恢复保留有效约定、清当前确认、解本笔冻结而保留其他限制。

## 场景顺序

| 场景 | 起点与现场顺序 |
|---|---|
| SC-01 | `buyer` 登录、退出、改密改名；真实邮箱注册、重置及换邮箱；`banned` 对照限制及管理沟通。 |
| SC-02 | `seller` 查禁发范围并提交商品；`admin` 审核 `case_product_review`；`product_rejected` 重提、`product_delisted` 上架；锁单商品禁止下架。 |
| SC-03 | `buyer` 检索 `product_listed`，主名/别名/价格组合筛选，收藏并对照下架及空结果。 |
| SC-04 | `buyer`、`seller` 查看评论与 `conversation_normal`，进入 `trade_request_buyer` 分支；比较未读、回复权限及受限发送。 |
| SC-05 | `seller` 接受 `trade_request_buyer` 观察另一条关闭；`trade_progress` 提案确认完成；另建请求演示拒绝/撤回/取消，`trade_confirm` 演示变更及单方确认。 |
| SC-06 | `buyer2`、`seller` 查看 `trade_disputed`；`admin` 处理恢复并检查锁单、约定与确认历史；`trade_frozen` 查限制。 |
| SC-07 | `trade_completed` 互评、`trade_reviewed` 看已有评价；`buyer2` 补充 `report`，`admin` 处置 `case_report`；`banned`、`case_ban` 展示封禁历史与解除。 |
| SC-08 | `admin` 统计按全部及指定范围核对预置计数；对照空范围及无权限角色。 |
| SC-09 | 启动扫描处理 `trade_timeout` 到期历史，`admin` 认领新异常事项；双方检查冻结限制，管理员留据恢复或终止。 |
| SC-10 | `admin` 维护 `category` 主名与别名、停用已用分类；处理 `product_pending` 标签申请；`category_unused` 删除及权限拒绝。 |
| SC-11 | `seller` 打开请求通知对照会话未读，再处理 `trade_request_buyer`；旧入口复查状态。 |
| SC-12 | `seller`、`buyer` 查看本人商品/交易/收藏/评价；`buyer2` 查 `report`、`banned` 查 `case_ban`；对照他人私有记录及只读。 |

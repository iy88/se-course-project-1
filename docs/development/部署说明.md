# 部署说明

本文描述生产部署的实际链路、发布流程与运维入口。私有部署的服务器地址、域名、端口映射、账号凭据、桶名及收件邮箱等可追踪信息不在仓库登记，由负责人在 Jenkins 凭据、生产配置文件与对应系统中管理。发布执行细节以仓库根目录的 `Jenkinsfile` 与 `scripts/deploy/` 为准，本文不重复其脚本内容。

## 总体链路

```text
浏览器 HTTPS
  → 边缘接入层（对外 HTTPS 终止，证书验证委托由 DNS 托管）
  → 公网接入层 Nginx（保留原始 Host，透传 WebSocket）
  → 内网隧道
  → 生产机 Nginx（按 Host 分流）
      ├─ 管理端静态文件：current/admin
      ├─ 移动端静态文件：current/mobile
      └─ /api/、/ws → 127.0.0.1:8001
```

后端由 systemd 服务 `se-course-project1-backend.service` 以 `deploy` 用户运行；生产机本机另运行 PostgreSQL 与 Redis。两个前端构建使用公开参数模式（`PROJECT1_FRONTEND_CONFIG=public`），API 基址默认同源 `/api/v1`，构建产物不含生产配置；正式接入由生产机 Nginx 提供同源反代与 SPA 路由回退（`/index.html`、`sw.js` 等入口文件不缓存，`/assets/` 长缓存）。

## 发布流水线

流水线由仓库 `Jenkinsfile` 定义，main 分支 push 经 Webhook 触发（分支过滤 `refs/heads/main`），禁止并发构建，总超时 30 分钟。阶段顺序：

| 阶段 | 内容 |
|---|---|
| 检出与结构校验 | 检出 main，校验仓库结构 |
| 后端依赖安装 | `uv sync --locked` 安装锁定依赖 |
| 后端验收 | 生成临时 `.env.dev`（SQLite + 本地存储 + 测试邮件捕获，权限 0600，成功失败均删除），以独立端口运行统一业务验收 runner；不使用生产 PostgreSQL、OSS 或业务 SMTP 凭据 |
| 前端构建 | 双前端安装依赖并以公开参数模式生产构建 |
| 锁文件校验 | 构建过程不得修改 uv/npm 锁文件 |
| 打包 | `git archive` 打包 backend，CI 构建产物打包 mobile/admin，生成 `release.txt` 与 `SHA256SUMS` |
| 上传 | 以 `deploy` 用户经 SSH（严格主机公钥校验）上传至生产机 releases 目录并校验和；`release_id` 为 `<完整提交SHA>-<构建号>` |
| 生产准备 | 远端校验 SHA256SUMS，拒绝覆盖已有内容；解包；从 `shared/.env.prod` 复制 0600 副本；`uv sync --locked --no-dev`；校验生产配置（prod 环境、schema、禁止自动建表、OSS 后端、迁移上下文）；写 `PREPARED` |
| 生产备份 | sudo 执行备份脚本，输出 `predeploy-*` 目录；取得唯一 `BACKUP_COMPLETE` 标记，失败阻止发布 |
| 生产迁移 | `app.manage migrate` 后核验数据库 Alembic revision 与代码 head 一致（迁移角色 SET ROLE owner）；写 `MIGRATED`（含 release_id 与备份路径） |
| 生产激活 | 文件锁防并发；记录上一版本；核验监听地址仍与 Nginx upstream 一致；同文件系统原子替换 `current` 软链；重启服务；健康检查（`/api/health` 返回 ok 且 systemd 主进程工作目录位于目标 release）；失败自动回退上一版本并重启复检；成功写 `ACTIVATED` |

失败通知：构建失败及失败后恢复成功时发送邮件，连续成功不发送；通知模板与收件人在 Jenkins 全局配置维护，不写入项目代码。

## 服务器目录布局

```text
/srv/se-course-project1/
├── current -> releases/<release_id>
├── releases/<release_id>/
│   ├── backend/            应用、alembic、.venv、.env.prod
│   ├── mobile/             移动端静态产物
│   ├── admin/              管理端静态产物
│   ├── release.txt、SHA256SUMS
│   └── PREPARED、MIGRATED、ACTIVATED
├── shared/
│   ├── .env.prod           持久生产配置源（0600）
│   └── demo-manifest.json  演示账号清单
└── .activation.lock
```

- 配置生效规则：持久配置源是 `shared/.env.prod`，每次准备阶段复制进 release；只改 shared 不影响运行中版本，只重启也不会重新复制；需要立即生效时显式同步当前 release 副本再重启。
- 版本标记：`PREPARED` 表示解包、依赖安装与配置检查完成；`MIGRATED` 记录迁移完成及备份路径；`ACTIVATED` 记录激活完成、上一版本与时间。当前版本以 `current` 软链为准。

## 运行环境

- 每个 release 自带 `backend/.venv`，由 `uv sync --locked --no-dev` 安装；系统 Python 不被替换。
- systemd 服务（单元文件由管理员在服务器维护，仓库不含）要点：运行用户 `deploy`，工作目录 `current/backend`，`APP_ENV_FILE=.env.prod`，入口 `python -m app.manage serve`，`Restart=on-failure`，并启用 UMask 与 NoNewPrivileges、ProtectSystem 等加固项。
- 配置读取：由应用自身加载器读取 release 内 `.env.prod`；除 `APP_ENV_FILE` 选择器外，继承的系统环境变量不覆盖文件值。
- 健康检查：`http://127.0.0.1:8001/api/health`。
- `deploy` 用户仅有两项受限 sudo：无参数执行备份脚本、重启后端服务；无任意命令权限。

## 数据库、缓存与对象存储

- PostgreSQL：生产禁止自动 DDL，结构由迁移命令建立；应用、迁移登录、owner 三角色分离，迁移显式 SET ROLE 至 owner；迁移对审计等对象设置的细粒度权限不应在迁移后统一补授。建库与角色准备见[开发与人工测试指南](guidance.md)。
- Redis：生产机本机独立实例，键前缀区分项目；连接与认证配置以生产 dotenv 为准。
- OSS：私有媒体／证据双桶，浏览器凭短期租约直传、读取走短期签名 URL；桶名、endpoint 与 AK 以生产 dotenv 为准。媒体桶 CORS 需允许两个前端实际 origin 的 PUT 及对应请求头（见[开发与人工测试指南](guidance.md)）。
- 业务 SMTP 与流水线通知邮件是两套独立配置；业务 SMTP 位于生产 dotenv，不能以构建通知发通认定业务验证码投递已验证。

## 备份与保留

- 备份脚本由 root 维护并安装在系统路径；每份备份包含 PostgreSQL custom 格式归档、Redis 整实例 RDB、元数据、SHA256SUMS 与 `COMPLETE` 标记，输出至 `/var/backups/se-course-project1/predeploy-*`。两个系统分别在线快照，不保证跨系统同一瞬间一致。
- 备份不包含 OSS 对象；代码回退不会自动恢复数据库。
- 自动清理：`scripts/deploy/retention.py` 安装为 root 并由 systemd timer 每日 04:30 左右执行；保留最近 5 个已激活 release 及当前、上一版本，其余超 7 天删除；备份保留 30 天且至少 10 份，被 release 引用的备份继续受保护；清理与激活、备份通过文件锁互斥，无法确认当前版本时拒绝清理。直接运行脚本为预览，经 systemd service 启动才实际执行。

## 生产数据操作与邮件验证

- 生产 reset 与演示数据重建：见[开发与人工测试指南](guidance.md)生产节；reset 不自动备份、不停止服务，执行前须完成 PostgreSQL／Redis 备份。
- SMTP 通道验证：`scripts/deploy/mail-test.Jenkinsfile` 供独立临时流水线验证邮件通道，不执行生产部署；其结果不代表业务 SMTP 投递已验证。

## 常用检查（生产机）

```bash
readlink -f /srv/se-course-project1/current
sudo systemctl status se-course-project1-backend.service --no-pager
sudo journalctl -u se-course-project1-backend.service -n 100 --no-pager
curl --noproxy '*' -fsS http://127.0.0.1:8001/api/health
sudo systemctl status se-course-project1-retention.timer --no-pager
sudo du -sh /srv/se-course-project1/releases /var/backups/se-course-project1
```

本机健康正常而外部访问异常时，按"生产机 Nginx Host 分流 → 内网隧道 → 公网接入层 → 边缘接入层／证书"顺序排查；前端直传失败时检查 OSS 请求状态、签名有效期、桶 CORS 及允许的请求头。

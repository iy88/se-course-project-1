# 开发文档

本目录维护实现设计、环境与资源操作、部署及测试验收，与需求分析交付材料分开。数据库、对象存储与 KV 后端由所选 dotenv 文件明确配置；生产环境由负责人经流水线管理（见[部署说明](部署说明.md)），开发与验收工作不读取生产配置。

- [文本长度与 Unicode 计数](text-limits.md)：字素簇口径、字段上限、输入反馈及数据库兼容
- [开发技术决策](技术决策.md)：技术选型、资源与权限设计、需求到实现口径、待决定事项
- [开发与人工测试指南](guidance.md)：环境文件、PostgreSQL 准备、迁移与 seed、服务托管、数据重置、配置矩阵、直传配置、验收入口
- [部署说明](部署说明.md)：生产链路、Jenkins 流水线、服务器布局、备份与保留
- [整体验收](整体验收.md)：统一测试结果、浏览器人工验收流程、覆盖率、邮件隔离、验证边界
- [演示数据与操作路线](demo-seed.md)：demo-seed 命令、共享场景目录、只读核验、预置身份与对象、演示路线

当前测试只有一套 UC/US/SC 全量业务验收：自动化按 runner 内置目录经真实 HTTP 执行，浏览器人工按需求基线材料逐条走查，两类结果独立记录，互不继承状态。自动化 seed 只在 runner 内创建，测试建立的数据库、存储和 Redis 资源按本轮标识隔离，成功或失败均要求清理；清理复验完成前不记录为通过。持久化部署管理员和必要参考数据由 `app.manage seed` 独立初始化，供浏览器人工登录使用。

仍未验证或未实现：本轮自动化资源清理的最终复验、业务 SMTP 真实收件箱人工投递验收、多实例 WebSocket 广播、备份恢复演练、OSS 生命周期/WORM 归档；自动化验收对应 2026-10-30 源码状态，其后端变更尚未重新全量复跑（见[整体验收](整体验收.md)）。生产发布已由流水线执行并经健康检查（见[部署说明](部署说明.md)），备份恢复演练未开展。常规服务已实现 SMTP 投递，自动化使用隔离的私有临时 outbox，不连接真实 SMTP；这不代表服务商配置或人工投递已验证。

开发工作不补建 AI usage，不要求负责人、模型、harness、逐文件确认；资源与业务决定仍以实际确认范围为准。本目录不记录真实 AK、密码、完整连接串、签名 URL、真实对象 key 及私有部署可追踪信息。

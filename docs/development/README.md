当前测试只有一套 UC/US/SC 全量业务验收。自动化与人工浏览器按同一清单使用相同角色和业务预期，分别经真实 HTTP 与浏览器操作；结果独立记录。自动化 seed 只在 runner 内创建，测试建立的数据库、存储和 Redis 资源按本轮标识隔离，成功或失败均要求清理；清理复验完成前不记录为通过。持久化部署管理员和必要参考数据由 `app.manage seed` 独立初始化，供浏览器人工登录使用。数据库、存储与 KV 按所选 dotenv 文件配置，同一测试与 seed 命令适用，不设置 `--profile`。

仍未验证或未实现：本轮自动化资源清理的最终复验、生产迁移/生产资源配置（本轮禁止读取 `.env.prod` 和使用生产资源）、SMTP 服务商账户配置及真实收件箱人工投递验收、多实例 WebSocket 广播、备份恢复演练、OSS 生命周期/WORM 归档。常规服务已实现 SMTP 投递，自动化使用隔离的私有临时 outbox，不连接真实 SMTP；这不代表服务商配置或人工投递已验证。任何历史 test PG/OSS/HTTP 结果只代表其记录的目标和范围，不表示生产上线，也不能证明新的清理策略通过。

开发工作不补建 AI usage，不要求负责人、模型、harness、逐文件确认；资源与业务决定仍以实际确认范围为准。命令与当前能力见[环境配置](环境配置.md)和[整体验收](整体验收.md)；本目录不记录真实 AK、密码、完整连接串、签名 URL 或真实对象 key。

## 2. 共享接口约定

状态：总体契约已确认，具体错误码、字段与参数在细化中登记。

### HTTP 与模型

采用 RESTful，以复数名词组织资源，GET 查询、POST 创建或提交业务动作、PATCH 部分更新、DELETE 删除或解除关系。归属用子资源表达，关键状态转换明确业务契约。版本前缀采用统一约定，前端独立配置公开入口。

JSON 使用 snake_case。对象 ID 对外字符串，金额整数分并体现单位，时间 UTC ISO 8601。状态采用具名字符串枚举。省略、null 及更新清空语义逐字段注明。

成功响应按资源组织，列表包含 items 和分页信息；错误包含稳定业务错误码、展示说明、必要字段错误及 request_id，HTTP 状态表达协议结果。错误码清单待接口评审。

### 身份与权限

随机 Session 凭据通过持久 Secure／HttpOnly Cookie 传递，状态变更请求采用 CSRF 校验，具体同源部署及 Cookie 属性在配置清单中确定。Redis 保存有效 Session，PostgreSQL 保存账户及凭据版本，每次鉴权校验并复用请求上下文。

绝对期限与空闲期限取较早者，用户有效活动按配置间隔续期，心跳与自动轮询单独处理。账户多 Session、Session 多连接。退出撤销当前 Session；改密／重置使已有版本失效；封禁保留需求规定的读取及事项沟通。

Session 不存在或到期返回重新登录语义；Redis 查询未完成返回暂时服务错误，客户端保留凭据。恢复撤销语义见 Q-001。

### 分页与并发

普通列表页码分页，明确过滤、主次稳定排序及总数口径；聊天历史和事件恢复采用游标。默认页大小和上限由后端配置。

关键写接口按主体、操作、幂等键及输入摘要返回同次结果；同键不同输入返回冲突。旧页面敏感操作携带版本依据，过期提交按契约返回冲突。事务由用例统一提交，内部能力复用同一上下文。

### 配置与能力接口

后端配置按应用入口、实例、数据库、Redis、身份、IM、任务、业务策略、文件邮件及日志分组，登记类型、单位、依据、默认值、范围、关联关系、公开范围与生效方式。前端配置在各应用中维护，构建独立；输入限制和上传能力从接口取得。配置模型及 .env.example 在实现阶段同步建立。

新操作用当前配置，既有期限及授权保存当次参数／版本；受影响的既有业务通过明确变更处理。

### 日志审计与类型

统一 request_id、operation_id、event_id、task_id、correlation_id、causation_id、instance_id 和 connection_id 的含义。自动记录公共上下文，业务用例提供审计事实并在提交前持久化。

接口类型由 OpenAPI 契约生成；Python 和 TypeScript 严格类型检查配合白盒审查，运行时案例针对运行时性质或复杂关联。

### 协作接口

模块提供方、调用方和复核人按模板登记。共享契约由 TASK-001 维护；各任务提出所需变更，由指定审查人核对交界后汇入。

## 4. 并行对接与交界归属

状态：并行设计安排；下列对接骨架供各任务引用，细化结果随任务 PR 形成版本。

### 设计归属

模块表达数据及动作的维护边界，任务可以跨模块设计一个完整关联。每项交界由一个任务形成定义，使用任务引用同一源文件。审查人核对需求和一致性，设计内容以该交界的归属任务为唯一编辑位置。

| 交界 | 唯一设计任务 | 交付源文件 | 使用任务 |
|---|---|---|---|
| 账户资格、执行上下文、事务、幂等和审计公共字段 | TASK-001 | 公共事务与权限、会话与身份、配置与可观测性专题 | TASK-002／003／004 |
| 文件引用及通知创建基础契约、消息传输框架 | TASK-001 | 文件与邮件、实时与任务专题 | TASK-002／003／004 |
| 商品与分类关联审批、审核内容版本、商品读取／编辑资格 | TASK-002 | 商品与分类专题 | TASK-003／004 |
| 商品占用、请求／交易转换、交易分支创建归档触发及其通知 | TASK-003 | 商品与交易协同专题 | TASK-002／004 |
| 三类会话的消息、参与关系、已读和归档公共模型 | TASK-004 | 会话与处置事项专题 | TASK-003，TASK-001 实时传输适配 |
| 事项认领、沟通、决定与账户／商品／交易执行关联 | TASK-004 | 处置与主体协同专题 | TASK-001／002／003 |
| 实例、CI/CD、发布及恢复 | TASK-001 | 运行与部署说明 | 模块任务提供所需参数和兼容信息 |

### 可先引用的公共骨架

| 契约 | 当前对接依据 |
|---|---|
| 执行上下文 | 账户 ID、Session ID、请求／操作标识、当前资格及适用配置版本；ID 字符串，时间 UTC，金额整数分 |
| 事务 | 应用用例持有同一个 AsyncSession／事务，内部能力通过参数接受该上下文，由用例提交；并发任务各有自己的会话 |
| 权限结果 | 账户层提供当前资格，主体层检查归属、参与关系及状态，管理动作关联事项和认领资格 |
| 内部结果 | 每项动作列出成功业务结果与具名错误，接口层按共享 HTTP 语义映射；具体错误码由使用案例汇集 |
| 幂等 | 操作者＋操作类型＋请求键定位同次操作，输入摘要区分负载，结果及关联数据同事务保存 |
| 文件 | 业务保存并传递 file_id；使用文件时核对用途、归属、已核验状态并在本次业务事务建立引用 |
| 通知 | 业务提交接收账户、事件类型、来源主体及 ID、展示信息；通知记录和待分发事件随业务事务保存 |
| 实时事件 | 事件标识、接收账户、来源主体、类型、恢复进度及载荷；会话负责业务消息／已读，传输负责投递和连接 |

该骨架定义并行设计所需的语义及数据责任。字段名、类型细节、错误码和参数在各归属任务中补齐，采用同源更新并登记影响。

### 首批交界交付

TASK-003 首批交付商品占用与交易分支联动表；TASK-004 首批交付三类会话基础模型及处置执行请求表。TASK-002 同时完成商品／分类主体和资格表，TASK-001 补齐公共字段及技术 Q。各首批表先提供短小可审阅版本，再展开各自完整接口。

商品和分类设计读取占用结果及变更触发，交易设计读取会话基础输入，事项设计以动作类型及对象 ID 表达处置执行。通过上述对象和动作语义可以先完成本域草案，随后按归属任务的版本完成具体字段对齐。

### 交叉审查及集成

每个 PR 指定一位实际审查人，按需求、契约与差异复核，使用任务可提交具体意见。审查安排与任务执行分别推进；交界确认采用单一源文件及一个结论记录。需求或总体架构取舍在相应 Q／ADR 中确认。

细化顺序为公共骨架→各任务首批交界→模块完整接口→集成核对。各任务的主体分析、业务规则与案例预期持续并行。

## 商品与交易协同

设计归属：TASK-003。状态：首批对接骨架，状态及事务细化见任务交付。

| 能力／关联 | 输入 | 结果及维护责任 |
|---|---|---|
| 取得商品占用 | 执行上下文、事务、商品 ID、交易 ID | 商品模块维护唯一占用及商品状态，交易用例协调接受和其他请求关闭；成功、当前占用冲突、商品资格变化分别定义结果 |
| 释放商品占用 | 执行上下文、事务、商品 ID、当前交易 ID、结束依据 | 校验当前占用对应交易，商品模块执行释放及适用状态变化，交易模块保留历史 |
| 创建交易分支 | 同一事务、交易 ID、双方账户 ID | 会话模块创建本笔分支并返回标识；交易用例在有效请求创建时调用 |
| 归档交易分支 | 同一事务、交易 ID、结束原因 | 会话模块维护分支归档，历史和已读按会话规则保留 |
| 业务通知 | 同一事务、接收账户、事件类型及来源 ID | 通知模块保存通知，交易用例按动作确定触发及接收范围 |

TASK-003 待补齐完整状态条件、锁顺序、返回字段、错误、幂等和转换表，TASK-002／004 引用本专题中的对应能力。

## 处置与主体协同

设计归属：TASK-004。状态：首批对接骨架，具体动作契约随任务细化。

| 执行对象 | 处置请求依据 | 主体执行结果 |
|---|---|---|
| 账户 | 事项 ID、认领账户、目标账户、封禁／解除动作、理由与来源 | 账户模块维护限制记录和当前资格，关联处置决定 |

| 交易及评价 | 事项 ID、操作主体、交易／评价 ID、冻结／解除／状态调整／内容处置、理由 | 交易模块校验并维护占用、计时、确认及历史 |
| 事项会话 | 事项 ID、当前认领账户、相关参与账户及访问依据 | 会话模块维护消息及已读，按当前事项资格执行读取和发送 |

TASK-004 待逐动作补齐前后置、结果字段、错误、事务范围、幂等及正常／异常预期。决定依据和主体状态分别由对应模块保存，使用任务引用此表细化执行适配。

## 2. 共享接口约定

状态：总体契约已确认，具体错误码、字段与参数在细化中登记。

### HTTP 与模型

采用 RESTful，以复数名词组织资源，GET 查询、POST 创建或提交业务动作、PATCH 部分更新、DELETE 删除或解除关系。归属用子资源表达，关键状态转换明确业务契约。版本前缀采用统一约定，前端独立配置公开入口。

JSON 使用 snake_case。对象 ID 对外字符串，金额整数分并体现单位，时间 UTC ISO 8601。状态采用具名字符串枚举。省略、null 及更新清空语义逐字段注明。

成功响应按资源组织，列表包含 items 和分页信息；错误包含稳定业务错误码、展示说明、必要字段错误及 request_id，HTTP 状态表达协议结果。错误码清单待接口评审。

### 身份与权限

随机 Session 凭据通过持久 Secure／HttpOnly Cookie 传递，状态变更请求采用 CSRF 校验，具体同源部署及 Cookie 属性在配置清单中确定。Redis 保存有效 Session，PostgreSQL 保存账户及凭据版本，每次鉴权校验并复用请求上下文。

绝对期限与空闲期限取较早者，用户有效活动按配置间隔续期，心跳与自动轮询单独处理。账户多 Session、Session 多连接。退出撤销当前 Session；改密／重置使已有版本失效；封禁保留需求规定的读取及事项沟通。

Session 不存在或到期返回重新登录语义；Redis 查询未完成返回暂时服务错误，客户端保留凭据。恢复撤销语义见 Q-001。

### 分页与并发

普通列表页码分页，明确过滤、主次稳定排序及总数口径；聊天历史和事件恢复采用游标。默认页大小和上限由后端配置。

关键写接口按主体、操作、幂等键及输入摘要返回同次结果；同键不同输入返回冲突。旧页面敏感操作携带版本依据，过期提交按契约返回冲突。事务由用例统一提交，内部能力复用同一上下文。

### 配置与能力接口

后端配置按应用入口、实例、数据库、Redis、身份、IM、任务、业务策略、文件邮件及日志分组，登记类型、单位、依据、默认值、范围、关联关系、公开范围与生效方式。前端配置在各应用中维护，构建独立；输入限制和上传能力从接口取得。配置模型及 .env.example 在实现阶段同步建立。

新操作用当前配置，既有期限及授权保存当次参数／版本；受影响的既有业务通过明确变更处理。

### 日志审计与类型

统一 request_id、operation_id、event_id、task_id、correlation_id、causation_id、instance_id 和 connection_id 的含义。自动记录公共上下文，业务用例提供审计事实并在提交前持久化。

接口类型由 OpenAPI 契约生成；Python 和 TypeScript 严格类型检查配合白盒审查，运行时案例针对运行时性质或复杂关联。

### 协作接口

模块提供方、调用方和复核人按模板登记。共享契约由 TASK-001 维护；各任务提出所需变更，由指定审查人核对交界后汇入。

## 公共事务与权限交接契约

状态：C1 交接稿，待 PR 人工评审。设计归属：TASK-001；编写账号：iy88。输入：design 提交 `6250473`。

### 关联需求、决策与接口

依据 FR-01—FR-14 的主体资格、BR／TR／权限矩阵、第6章一致性与隐私要求，关联 ADR-002、003、005、009、010。调用方为 TASK-002／003／004 的业务用例，本契约定义公共输入、事务、资格、幂等及错误。数据模型和业务状态仍由各主体专题定义。

### 公共数据类型

| 类型 | 字段与约定 |
|---|---|
| EntityId | 正整数 ID 对外使用十进制字符串；数据库为整数；接口模型校验其范围 |
| ResourceRef | `resource_type`：具名主体类型；`resource_id`：EntityId |
| ExecutionContext | `request_id`：本次执行 UUID；`operation_id`：逻辑操作 UUID；`actor_kind`：account／system；`actor_id`：账户 ID 或已登记系统任务名；`session_id`：账户操作的内部 Session 标识；`credential_version`：鉴权读取的账户版本；`config_version`：本次配置版本 |
| TransactionContext | 同一用例持有的 SQLAlchemy AsyncSession、ExecutionContext 及本次审计／事件意图集合 |
| BusinessError | `code`：稳定错误码；`message`：可展示说明；`details`：按接口定义的公开字段；`resource`：允许公开时的 ResourceRef |
| OperationResult | `operation_id`、HTTP 状态、已确认响应数据及结果资源引用；用于成功操作的同次重试 |

账户上下文由身份依赖构建；system 上下文由登记的任务入口构建，附触发事件／任务标识。外部输入通过 Pydantic 转成用例参数，执行上下文由服务端补齐。当前请求中的关联查询复用已核验身份，用例写入时按下述协议重查资格。

### 用例和模块调用签名

以下为设计签名，T 为模块具名结果类型。

```text
run_write(context, operation_name, idempotency_key, normalized_input, use_case) -> OperationResult[T]
use_case(tx, context, request) -> T
lock_account_qualifications(tx, shared_account_ids, exclusive_account_ids) -> AccountQualifications
require_action(qualifications, action, resource_state, participation) -> Allowed | BusinessError
record_audit(tx, action, target, before_after, basis_ref) -> audit_id
add_event_intent(tx, recipient_ids, event_type, source, intent_key, payload_ref) -> event_id
```

内部能力接受 `tx`，返回具名结果或抛出具名 BusinessError。用例协调跨模块动作，公共包装完成最终提交及错误映射。内部能力的必要 flush 保持在调用方事务内。每个并发请求／后台任务持有自己的 AsyncSession。建议采用 PostgreSQL READ COMMITTED 隔离级别；等待锁后显式刷新或重新查询资格及业务状态，使后续语句读取最新已提交事实。

### 状态转换与数据约束

| 对象 | 规则 |
|---|---|
| 资格 | 账户当前身份、凭据版本和限制来自 PostgreSQL；主体进一步核对归属、参与、状态及认领 |
| 成功写入 | 主体变化、历史、必要审计、幂等结果、通知及待投递事件统一提交 |
| 业务校验结果 | 整体回滚，本次业务状态及成功审计保持原状，接口按错误码表达 |
| 唯一约束竞争 | 只将已登记的约束映射为对应业务冲突，其他异常记录关联标识后返回内部错误 |
| 查询 | 按当前读取资格构造响应字段；记录读取本身与需要审计的业务动作分别定义 |

时间判断使用同一逻辑数据库的当前时钟；等待行锁后重新读取状态，并以实际判定时刻检查期限。修改期限的规则按既有规则版本语义执行。

### 账户资格与并发写入

本交接稿建议采用 PostgreSQL 事务级共享／排他 advisory 资格锁，在统一登记的资格锁命名空间内以账户整数 ID 作为键。该机制是待本 PR 评审的具体实现约定。

- 普通写操作取得操作者和直接业务参与账户的共享资格锁，例如购买请求与交易取得买卖双方的锁，消息发送取得相关参与账户的锁。
- 封禁、解除、改密／重置及管理资格变更，对变化账户取得排他资格锁；管理操作者按需要取得共享锁。
- 用例在开始时合并账户集合，按账户 ID 升序取得所需最强模式，再重读账户资格和凭据版本。资格锁由事务结束释放。
- 资格变化事务通过账户模块保存当前状态，并协调适用的业务变化。封禁目标的锁取得后，读取其当前请求／交易集合，其他涉及该账户的新写入在取得资格锁后检查最新状态。
- 资格 advisory 锁与实际账户行的更新锁分别表达职责；账户模块在资格锁内执行普通字段更新。通知接收人存在性查询及外键关联沿数据库结构规则执行。

两种时序都有确定结果：业务事务先取得共享资格锁时，该业务先完成，后续限制按已提交状态处理；资格变化先取得排他锁时，后续业务读取新资格并返回对应结果。读接口依据当前账户和对象范围判定，Session 撤销恢复语义继续由 Q-001 细化。

### 锁顺序与事务边界

| 顺序 | 锁域及动作 |
|---|---|
| 1 | 本用例账户资格锁：账户 ID 升序，模式在首次取得时确定 |
| 2 | 幂等键的事务内唯一占位：操作者＋操作类型＋请求键 |
| 3 | 商品行：商品 ID 升序；锁后重读占用及状态 |
| 4 | 交易行：已知受影响集合按 ID 升序；单商品场景在商品锁内确定集合 |
| 5 | 处置事项行：事项 ID 升序，重查认领与当前状态 |
| 6 | 会话／分支及内容、文件登记行：用例列明所需集合，每类按稳定 ID 顺序 |
| 7 | 用户事件序号行：收集全部接收账户后按账户 ID 升序锁定、分配序号并保存事件 |

每个用例按涉及的锁域推进，并在具体专题登记其集合和顺序。需要补充更早锁域的对象时，回滚并重新规划整次用例；此分支计入统一的有限事务重试。事项认领可作为独立短事务；处置执行重新按全局顺序取得相关锁和资格。

接受请求的具体交易转换和商品占用由 TASK-003 定义；事项执行请求由 TASK-004 定义。调用方使用本表组织公共顺序，模块维护自身数据。

### 幂等作用域与结果

客户端关键写操作提交 `Idempotency-Key`。账户已鉴权，服务端校验键的格式和配置长度。作用域为 `(actor_id, operation_name, idempotency_key)`，数据库唯一约束保障跨实例同次识别。

输入摘要采用具名用例参数的规范 JSON：包含路径对象和有效业务字段，排序键并固定编码；各字段按 schema 处理省略、null、时间、金额及文本。摘要使用 SHA-256；凭据与敏感载荷通过其专用验证接口处理。规范化方案版本随记录保存。

| 情况 | 结果 |
|---|---|
| 已有成功记录、摘要相同 | 按当前身份及结果读取资格返回已保存业务结果，沿用 operation_id |
| 已有记录、摘要不同 | `IDEMPOTENCY_PAYLOAD_CONFLICT` |
| 首次请求 | 创建事务内占位，执行用例，保存响应状态、数据和资源引用，统一提交 |
| 同次请求并发 | 使用 INSERT ... ON CONFLICT DO NOTHING 协调唯一占位等待，再以新语句读取；先到事务提交后，后到者读取成功记录；先到者回滚后可接续执行 |
| 校验结束且事务回滚 | 本次占位随事务回滚，重试依据当前业务状态重新判断 |
| 响应丢失 | 使用同键重试，取得已提交结果 |

成功结果的重放复用原业务数据和状态码，当前执行产生新的 request_id。校验失败且有明确业务副作用的专用流程（如验证码尝试计数）在其契约中定义结果保存语义。保留期限内重复请求按本表执行；到达保留期限后的客户端重试策略在配置／接口中明确。

### 错误映射与输出

| 错误码 | HTTP 状态 | 语义 |
|---|---|---|
| SESSION_REQUIRED／SESSION_EXPIRED | 401 | 进入登录流程 |
| ACTION_NOT_ALLOWED／ACCOUNT_WRITE_RESTRICTED | 403 | 当前资格与动作不匹配 |
| RESOURCE_NOT_VISIBLE | 404 | 当前访问范围内没有对应资源 |
| STATE_CONFLICT／VERSION_CONFLICT | 409 | 状态或提交版本已变化 |
| IDEMPOTENCY_PAYLOAD_CONFLICT | 409 | 同键对应其他输入 |
| INPUT_INVALID | 422 | 输入格式、字段范围或组合校验结果 |
| RATE_LIMITED | 429 | 返回可用重试时间 |
| DEPENDENCY_UNAVAILABLE／TRANSACTION_RETRY_EXHAUSTED | 503 | 返回服务暂不可用及适用重试提示 |
| INTERNAL_ERROR | 500 | 返回请求标识，内部日志关联具体原因 |

错误 JSON 结构：`error: {code, message, details}`、`request_id`，以及已建立逻辑操作时的 `operation_id`。details 按接口声明字段输出，资源可见性由主体确认。模块通过稳定前缀补充具名业务错误并登记 HTTP 映射。

### 超时、重试与异常恢复

数据库锁等待、事务时间、重试次数及退避来自后端配置。只有已登记的死锁／序列化或锁集合重规划等整事务可重试条件进入有限重试；每次从新事务重读。外部网络、OSS、SMTP 和 Redis 投递通过提交后的状态流程处理。

数据库事务完成后返回成功；实时投递从持久事件推进。运行日志在公共包装输出 request_id、operation_id、实例及实际结果，审计记录业务主体和依据。原始密码、验证码、Cookie 及签名 URL 采用各自保护与脱敏约定。

### 规则版本

ExecutionContext 固定本次 config_version，幂等记录保存摘要规范版本及结果。存储结构承载不变量；阈值、超时及长度由配置校验。已有期限和授权保留创建时参数及版本。

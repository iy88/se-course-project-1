# C-09 交易记录

状态：候选类分析初稿，负责人张新悦；未开展人工模型评审，不表示类职责已确认。

## 职责与边界

承载一笔交易的完整过程：请求提出与结果、卖方接受后的进行中进度、双方完成确认、协商终止、争议及超时异常。交易记录与商品双向关联，并关联 C-10 交付确认记录、C-11 评价与 C-13 处置记录。

边界：请求与交易按同一对象的不同阶段建模，已定不拆类（见 [3.2.1](../draft-03-领域与数据.md)）；单方确认不作为独立状态，而是进行中的确认进度标记；冻结是进度暂停标记，不等于完成或终止。交易不记录付款金额、支付流水或资金凭证（BR-44）。

## 主要业务属性

关联商品及交易时内容、买方、卖方、请求提出与结果（接受／拒绝／撤回／锁单关闭）、双方确认人与时间、终止或有争议的结果及处理记录。以上为 BR-44 要求的至少保留项；属性为业务口径描述，不写字段类型或索引。

## 关联与数量约束

| 关联 | 重数（候选） | 说明 |
|---|---|---|
| 交易记录—商品 | 0..* : 1 | 同一商品同时至多一笔进行中交易 |
| 交易记录—买方／卖方 | 各 1 | 双方各自为 C-01，不与同一人交易本人商品 |
| 交易记录—交付确认记录（C-10） | 1 : 0..2 有效 | 每方一条有效记录，历史保留 |
| 交易记录—评价（C-11） | 1 : 0..2 | 每方每笔至多一条 |
| 交易记录—处置记录（C-13） | 0..* : 0..* | 争议、举报或冻结相关处置 |

同一买方对同一商品至多一条有效待接受请求；拒绝或撤回后可再次发起（BR-28、BR-41）。

## 关联规则、场景与用例

- 请求、接受、拒绝、撤回与自动关闭：BR-01、BR-05、BR-28、BR-29、BR-41、BR-42；TR-12—TR-14。
- 双方分别确认才算完成；单方确认暂定 7 天未回应转异常：BR-03、BR-04、BR-09；TR-15、TR-16。
- 争议保持锁单及原权限，解决恢复后清空当前确认、保留历史、重新单方确认才重启计时：BR-06、BR-30；TR-17、TR-21。
- 双方同意终止计为失败交易并解除锁单：BR-29、BR-30；TR-18、TR-20。
- 争议中禁止直接完成，必须先恢复进行中：TR-19 原转换已撤销、编号保留。
- 处置冻结整个进度、禁止该笔交易双方 IM、不自动完成或取消：BR-53；TR-10、TR-11。
- 场景：SC-05、SC-06；用例：UC-C05、UC-C06、UC-C14。

## 状态归属

状态：待接受、已拒绝、已撤回、已关闭、进行中、有争议、已终止、已完成、异常交易。转换与依据见 [5.2 交易记录](../draft-05-行为与状态.md)；确认进度与冻结标记单独表达，不设“冻结”状态。

## 待决与边界

- P-21：异常交易的后续处理与恢复路径，本节不预填转换。
- P-15／P-16 已决待模型：主动下架关闭请求并说明原因；超时按冻结规则限制双方。
- 不拆分为“请求”与“交易”两个对象：已定（负责人确认）；如后续要拆，须另给独立生命周期依据并重编 TR。

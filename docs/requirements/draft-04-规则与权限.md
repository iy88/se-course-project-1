## 4.2 交易、请求与争议

| 编号 | 现行规则 |
|---|---|
| BR-01 | 买方在商品页发起交易请求，由该商品卖方接受或拒绝。“交易请求”承接题目中的“下单”，不涉及线上付款。 |
| BR-02 | 卖方接受后，商品进入“交易中”，停止接受新交易；同一商品只能有一笔进行中的交易。 |
| BR-03 | 买卖双方分别确认完成；仅双方均确认后交易完成，商品标记为“已售出”。 |
| BR-04 | 单方确认采用进行中交易的确认进度，不单设状态；一方确认后另一方未回应，等待阈值初定 7 天。进入争议即有效响应，原未回应计时结束。争议解决恢复进行中后按 BR-30 清空当前确认，待一方重新确认才开始完整 7 天计时。超时转异常交易，按冻结规则限制交易双方（停止上架和交易操作、禁止该笔交易双方 IM），交管理员处理，保留处置通知与沟通单；不自动完成或取消。 |
| BR-05 | 卖方接受前，买方可撤回请求；接受后，一方提出终止，另一方同意后关闭交易。 |
| BR-06 | 交易买方或卖方均可主动发起争议并填写说明，统一进入“有争议”状态，不以哪方发起或是否已有单方确认为区别。争议期间商品保持锁单，争议本身不新增用户权限限制，保留原有各项权限；不解除已存在的封禁／冻结限制。 |
| BR-07 | 存在未结束且仍锁单的交易时，卖方不得主动下架，须双方先终止交易。普通终止解除锁单，无审核／违规限制时可恢复可交易，卖方也可选择下架；信息修改不导致二次审核；本项目仅考虑不改变商品主要内容和交易内容的微调。 |
| BR-08 | 管理员可查看争议相关记录、处理举报与违规，不承担付款核实、退款或赔付责任；证据不足时保留争议，不替双方认定交易完成。 |
| BR-09 | 首版不自动确认完成或超时取消交易；待接受请求仍无自动有效期。单方确认后另一方未回应的超时按 BR-04 处理：初定 7 天转异常交易并按冻结规则限制交易双方，不等于自动完成或取消。 |
| BR-28 | 同一商品允许多个买方存在待接受请求，同一买方对同一商品最多一条有效待接受请求；卖方接受一条时，其他待接受请求自动记为“已关闭”，原因统一为“商品已被其他用户锁单”，不产生多笔进行中交易。用户不得购买本人商品或向本人发起私聊。 |
| BR-29 | 卖方主动拒绝请求记为“已拒绝”，买方撤回记为“已撤回”；因卖方接受其他请求而自动结束的请求记为“已关闭”，原因为“商品已被其他用户锁单”；主动下架导致待接受请求结束也记为“已关闭”，说明原因为商品已下架；双方接受交易后同意终止记为“已终止”，完成记为“已完成”；统计中将已终止计为失败交易，拒绝、撤回及此类自动关闭不计入已接受交易的失败数。 |
| BR-30 | 任一交易方说明后发起争议，保持锁单及原权限，不自动冻结。认领管理员解决争议，或双方均确认争议已解决，可恢复进行中；恢复时清空双方当前完成确认，保留历史，双方重新确认，一方再次确认后才开始完整 7 天计时。必须先恢复进行中才允许确认完成，争议中仍可双方同意终止。解决争议不解除已有封禁／冻结，管理员不得替双方确认交付。 |
| BR-31 | 普通终止不自动导致下架或审核失效；无审核／违规限制时可恢复可交易，卖方也可下架后重新上架。信息修改不二次审核；其他审核／违规限制按其处置规则。未接受请求被拒、撤回或因其他用户锁单关闭不改变商品原状态；卖方主动下架时将该商品待接受请求记为“已关闭”并说明下架原因；信息修改假设仅微调、不改变商品主要内容及交易内容，不额外形成交易内容版本选择。 |
| BR-41 | 请求被拒绝或买方撤回后，买方可对该商品再次发起新请求；同一买方对同一商品的有效待接受请求至多一条，同一商品仍只能有一笔进行中交易。 |
| BR-42 | 待接受请求不设自动有效期，不自动过期；因接受、拒绝、撤回或其他用户锁单而结束时按对应结果记录。商品修改不关闭已有请求；商品主动下架时待接受请求记为已关闭，并说明原因为商品已下架。 |

## 4.3 商品发布、审核与浏览

| 编号 | 现行规则 |
|---|---|
| BR-10 | 商品发布后由平台管理员审核，通过审核后才对其他用户公开展示。 |
| BR-11 | 已审核通过的商品修改信息不触发二次审核，不因修改暂停公开展示或关闭已有待接受请求；本项目假设修改仅微调，不改变商品主要内容及交易内容；交易中／已售出的关键内容修改禁令仍按 BR-15。 |
| BR-12 | 商品关键内容包括标题、描述、图片、价格、分类。 |
| BR-13 | 已撤销：修改后暂停公开并二次审核。编号保留不复用；首次审核及审核拒绝后修改重提仍按 BR-10、BR-14。 |
| BR-14 | 审核不通过时，向卖方显示拒绝原因；卖方修改后可重新提交审核。 |
| BR-15 | 商品处于“交易中”或“已售出”时，禁止卖方修改上述关键内容。 |
| BR-23 | 用户可收藏／取消收藏公开商品，收藏清单仅本人可见。退出搜索不等于详情失效：交易中／已售出商品按 BR-46 保留登录详情访问；真正撤销公开访问的商品仅保留失效提示，不泄露不可见内容。封禁期允许查看本人收藏及有权查看的公共内容，禁止收藏／取消收藏；仅交易冻结不限制无关收藏操作。 |
| BR-24 | 商品搜索和筛选仅返回当前公开且可供浏览的商品，支持关键词、分类和价格范围；交易中、已售出、下架、待审或被拒商品不进入公开搜索结果。筛选参数范围见 BR-52。 |
| BR-33 | 商品审核检查描述与图片是否清晰、分类及价格是否合理完整、是否含明显违规或与二手物品交易无关内容；禁止物品细目由管理员维护并向用户展示，不宣称该教学规则已覆盖全部现实监管要求。审核结论记录审核者、时间及拒绝理由。 |
| BR-40 | 禁止发布物品细目由平台管理员维护并面向用户展示，至少覆盖：法律法规禁止流通的物品、危险品与管制物品、活体动物、药品与医疗器械、账号与虚拟财产、明显与二手闲置物品交易无关的服务或推广内容。细目条目由管理员补充维护；本条为教学项目工作设定，不宣称覆盖全部现实监管要求。 |
| BR-46 | 单件逻辑商品：卖方接受请求后进入交易中；待接受请求不使商品进入交易中。交易中及已售出不进入在售列表／搜索，但已登录用户仍可查看详情并显示状态。交易中禁止新交易请求，允许评论及卖方回复；已售出禁止请求、评论及回复。违规下架撤销公开访问优先于上述普通历史详情展示。多件／成交后保持在售仅扩展候选。 |
| BR-52 | 商品筛选支持关键词、分类与价格区间，三者可组合使用；价格区间含端点；无匹配结果时返回空列表并给出“无匹配商品”提示，不返回非公开商品。 |

## 4.4 商品页评论与买卖双方 IM

| 编号 | 现行规则 |
|---|---|
| BR-16 | 登录用户可评论已公开展示或处于交易中的商品；已售出禁止评论及回复。 |
| BR-17 | 买方可从商品页向该商品卖方发起私聊；会话双方可查看自己参与的会话。 |
| BR-18 | 管理员仅在举报或争议处理时查看与该事项相关的消息，不具有日常任意浏览私人会话的权限。 |
| BR-26 | 发布者可删除本人评论，不能编辑已发布评论；违规评论可由管理员移除并记录理由。首版 IM 支持双方文字消息，不提供撤回、编辑、附件及群聊；消息不向非会话成员公开，管理员访问遵守 BR-18。 |
| BR-27 | 公开可交易及交易中允许商品页评论与卖方回复，已售出禁止新增评论／回复。撤销公开访问后不允许新评论或新建商品咨询会话；交易中／已售出不新建商品咨询会话，已有会话及交易历史保留读取，发送受封禁／冻结限制。交易中／已售出只退出在售搜索，详情访问按 BR-46；二者不等同违规撤销公开访问。 |
| BR-47 | 商品页评论用于商品页咨询（包括允许评论的交易中阶段），与交易完成后的评价（BR-19）区分；应限制评论长度与发表频率，具体阈值在设计阶段细化。支持该商品卖方回复买方评论，首版不支持买方之间相互回复；商品已售出后禁止新增评论及回复；违规内容按 BR-26 处理。 |
| BR-48 | 咨询会话由买方向商品卖方发起；卖方可在已有会话中回复，但不主动发起新会话；同一买卖双方就同一商品不重复创建并行会话（如已有会话则继续沿用）。 |

## 4.5 账户与业务访问

| 编号 | 现行规则 |
|---|---|
| BR-35 | 校园用户以邮箱或手机号作为账户标识，配合密码普通注册；首版不进行校园身份、学籍或教职工身份核验，与“单校场景、普通注册”的范围摘要一致。注册字段最小集为账户标识、显示名称、密码；是否增加其他字段另行登记开放问题。 |
| BR-36 | 账户标识在同一平台内唯一；重复注册应被拒绝并提示标识已存在，不自动合并或接管既有账户。首版不设置登录失败次数阈值与自动锁定；如需引入另行登记开放问题。 |
| BR-37 | 忘记密码功能归 FR-01；重置须验证账户绑定邮箱或手机号，不以管理员人工重置为必经流程、不增加专门人工审计要求；验证码及交互方案留待设计。 |
| BR-38 | 禁止未登录访客访问业务内容，包括商品列表、搜索结果、商品详情与评论；未登录仅可使用注册、登录和忘记密码等账户入口。此项按 2026-10-17 袁尚峰重申的组内初步讨论结论修正，见 E-03 D-18。 |
| BR-39 | 首版不提供“仅本人可见”的私密发布或分组可见设置；商品审核通过后即对所有校园用户公开，未公开即不可浏览，与 BR-24 一致。 |

## 4.6 完成交易评价与举报

| 编号 | 现行规则 |
|---|---|
| BR-19 | 交易完成后未被封禁的双方可互评，每方每笔交易一条评价，包含 1—5 分评分及文字；不得评价未完成交易或代他人评价。首版不支持用户修改已提交评价，管理员可处理违规评价并记录理由。评分范围为项目设定。评价在商品详情页向所有已登录用户展示。 |
| BR-20 | 未被封禁的登录用户可举报商品、评论、消息、评价或用户，提交理由及可选证据；举报结果须由管理员确认后隐去用户和管理员信息，向所有已登录用户公开，确认前不可见；被举报对象不因举报自动判定违规。 |
| BR-21 | 管理员按举报核查，记录处理结论及理由，可不予处理、移除违规内容或封禁违规账户；证据不足记录无法认定，不推定平台外付款、交付事实。 |
| BR-50 | 首版不对举报处理设定承诺时限，不填写无依据的响应时间；举报结果按 BR-20 经管理员确认后匿名公开。 |

## 4.7 私人交易历史与交付记录

| 编号 | 现行规则 |
|---|---|
| BR-25 | 交易双方可查看本人交易的商品历史内容、交付记录和历史私聊；不向其他用户开放私人交易记录。普通商品详情及公开评价另按 BR-46、BR-19 向登录用户展示，不能将私人记录限制扩大为商品详情仅双方可见。交易历史内容不因后续商品编辑而改写，本项目假设修改只作微调、不改变商品主要内容及交易内容，不另设修改前后交易内容选择。 |
| BR-32 | 线下交付记录由交易双方各自确认完成时提交，记录确认人、确认时间及可选交付说明；不强制上传凭证、精确位置或支付信息。双方确认记录分别保存，不允许覆盖对方记录。 |
| BR-43 | 双方当前完成确认与历史记录分开：各自确认人、时间及可选说明独立保存，不覆盖对方记录，用户不得删除已提交历史。争议解决可按 BR-30 清空当前确认标记，但不删除历史，不等同用户自行更正。 |
| BR-44 | 交易记录至少保留：关联商品及其交易时内容、买卖双方、请求提出与结果（接受／拒绝／撤回／锁单关闭）、双方各自确认人与确认时间、终止或有争议的结果及处理记录；不记录付款金额、支付流水或资金凭证。 |
| BR-49 | 线下交付确认与说明提交后不支持用户自行更正；确有更正需求时登记为开放问题，由管理员按处置记录处理并留存理由。 |

## 4.8 统计口径

| 编号 | 现行规则 |
|---|---|
| BR-34 | 首版统计仅供管理员查看，包含用户数、当前各状态商品数、待处理审核／举报数、交易完成／终止／争议数量，以及所选时间范围内的完成交易数。交易时间统计按结果确认时间，当前状态数量按查询时点；不统计真实付款金额、流水或成交收入。 |
| BR-45 | 统计不设置默认时间范围，由管理员显式选择范围或“全部”；账户总数包含被封禁账户并在统计中单列封禁数；待处理审核数与待处理举报数按查询时点的未处理记录数计。该口径于 2026-10-16 经张新悦确认（E-02 D-15）。 |

## 4.9 管理事项、封禁与冻结

| 编号 | 现行规则 |
|---|---|
| BR-22 | 账户封禁后禁止发布／修改商品、交易操作、评论、IM、新增举报及评价既往已完成交易；本人相关记录保留只读。涉及交易的双方上架／交易限制按 BR-53。允许使用本人处置通知与沟通单与认领管理员沟通、反驳／申诉；这不属于买卖双方 IM。管理员解决问题并确认解除后自动恢复原权限及因处置停止的展示，不将原非在售商品变为在售。封禁账户可浏览原本有权查看的公共商品、评论、评价及已公开匿名举报结果，并查看本人收藏；禁止收藏／取消收藏等业务写操作，处置沟通单是例外。 |

## 4.10 统一权限解释

- 公开指对符合资格的已登录用户展示，不等于允许访客访问。“退出在售搜索”和“撤销详情访问”不同；交易中／已售出的普通详情仍可见，违规撤销访问则不可见。
- 买卖双方是相对于商品／交易的身份，不是互斥账号；某商品买方可在另一商品作为卖方。下表使用“执行主体＋对象范围”避免把身份误写成永久禁权。
- 封禁／冻结限制优先于一般操作资格；本人处置通知与沟通单是受限期的管理员沟通例外，不恢复买卖双方 IM。封禁允许有权访问的公共读取及本人收藏只读，禁止业务写操作；仅交易冻结保留既往交易评价、其他问题举报及收藏等无关权限（E-06 D-39）。
- 争议本身不增加权限限制，但商品继续锁单；禁止争议中直接完成，解决后按 BR-30 清空当前确认再恢复正常确认流程。

# 2. 用户需求

状态：需求分析草稿；负责人金婉怡继续细化。十项父 FR 保持题目覆盖分组，下列能力按已确认范围整理，不宣告用例或覆盖验证完成。

## 2.1 需求、规则与设计的分界

- 本章回答“系统为谁提供什么能力”，涵盖正常、异常与管理能力；出现功能入口不能只藏在 BR 中。
- 第 4 章 BR 回答资格、对象范围、限制、结果条件及业务口径；权限是约束，DT 组合处理情形，TR 表达事件与状态变化。
- 第 3 章描述领域对象职责关系，第 5 章展开具体场景、行为与状态模型；不能用规则表代替这些分析。
- 验证邮件／短信如何实现、阈值数值、页面布局、工单交互等留待设计；已明确的“须验证、限制频率、能与管理员沟通”仍是需求。运营具体禁发条目不要求本阶段穷举。

## 2.2 角色基础

| 编号 | 角色 | 边界 |
|---|---|---|
| R-01 | 校园用户 | 学生与教职工普通注册，不核验校园身份；访客仅有注册、登录、忘记密码入口 |
| R-02 | 买方 | 在某商品咨询／交易中的业务身份，不是互斥账户类型 |
| R-03 | 卖方 | 本人商品发布者，可在别的商品中作为买方 |
| R-04 | 平台管理员 | 认领事项并在归属／必要范围内管理；管理身份不自动授予私人记录任意访问权 |

买卖角色随商品／交易变化；封禁、冻结是限制，不是新的业务角色。项目组长和教师是涉众，不自动成为系统角色。

## 2.3 题目十项功能分组及讨论形成的能力范围

| 编号 | 功能分组 | 系统应提供的能力 | 规则依据 |
|---|---|---|---|
| FR-01 | 用户注册与认证 | 普通注册、登录、忘记密码；通过绑定邮箱或手机号验证后自助重置 | BR-35—BR-39 |
| FR-02 | 商品发布与审核 | 发布、首次审核、拒绝原因展示、修改重提、允许状态下信息微调及上下架；微调不改变商品主要内容和交易内容，下架关闭待接受请求并说明原因；管理员维护／展示禁发范围 | BR-07、BR-10—BR-15、BR-31、BR-33、BR-40 |
| FR-03 | 搜索与筛选 | 关键词／分类／价格组合检索、空结果提示；按资格显示商品详情和状态 | BR-24、BR-38、BR-46、BR-52 |
| FR-04 | 收藏与咨询 | 收藏及个人清单、失效提示；商品页评论、卖方回复买方；买方发起私人文字会话、历史查看及允许时发送 | BR-16—BR-18、BR-23、BR-26、BR-27、BR-47、BR-48 |
| FR-05 | 下单与交易确认 | 请求、接受／拒绝、撤回、完成确认、协商终止；任一方说明发起争议、解决恢复；单方确认超时识别与异常转交 | BR-01—BR-09、BR-28—BR-31、BR-41、BR-42、BR-53 |
| FR-06 | 线下交付记录 | 双方分别提交确认与可选说明、查看本人历史；管理员按处置记录处理更正 | BR-25、BR-32、BR-43、BR-44、BR-49 |
| FR-07 | 评价与举报 | 完成交易互评、在商品详情页展示；提交举报、管理员确认后匿名展示结果 | BR-19—BR-21、BR-22、BR-50 |
| FR-08 | 管理员审核与封禁 | 共享待办池、主动认领、核查处置、冻结／封禁／解除；处置通知与沟通单供用户说明、反驳／申诉和管理员解决 | BR-08、BR-18、BR-21、BR-22、BR-33、BR-40、BR-51、BR-53 |
| FR-09 | 商品状态流转 | 展示商品状态、按请求及交易结果联动，普通终止解除锁单、按资格恢复；违规停止访问及解除后的恢复 | BR-02、BR-03、BR-07、BR-11、BR-15、BR-30、BR-31、BR-46、BR-53；TR-01—TR-21 |
| FR-10 | 数据统计 | 管理员选时间范围或全部查看账户、商品状态、审核／举报待办及交易结果统计 | BR-29、BR-34、BR-45 |

十项父 FR 仅用于追踪题目分组，不是实际功能需求数量的上限。讨论已形成自助找回密码、卖方回复、争议发起及解决、超时异常处理、共享池认领、处置通知与沟通单、举报结果确认后匿名公开等新增或扩展能力，不能因归入父 FR 而忽略其独立需求及验收。后续按用户目标建立可追踪子需求；跨分组能力关联相应父 FR，不强行压缩为恰好十条需求。FR-08 的处置沟通不同于 FR-04 买卖双方 IM，封禁／冻结仍允许前者。

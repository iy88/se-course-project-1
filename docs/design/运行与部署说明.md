# 运行与部署说明

## 环境与配置

开发、测试和正式环境分别登记 PostgreSQL、Redis、OSS、SMTP 和访问地址。后端统一 .env，前端各自维护开发／构建配置；配置模型检查类型、范围、必要依赖和关联关系。各实例连接池和内存统一预算。

## 启动与迁移

独立步骤执行 Alembic 迁移，再由 systemd 启动原生 API、IM、worker、scheduler 多实例。Nginx 维护静态资源与 HTTP／WS 上游。实际启动命令及监听清单待部署任务细化。

## CI/CD

GitHub Actions 验证提交，Jenkins 构建并部署明确版本，执行配置资源检查、迁移、逐实例滚动、就绪检查和业务验证。前端独立构建，发布登记接口兼容及配置版本。

## 停止与恢复

实例停止新接入／领取工作，按配置排空，IM 重连及任务认领协议衔接。保留可用版本及配置，按数据库兼容范围回退。数据库、Redis 和文件备份恢复步骤及会话恢复语义在实际部署计划中明确并验证。

## 责任

部署、服务器、Nginx、实例、配置发布、迁移执行、回退和部署验收由 TASK-001专门负责。模块成员提供交付及兼容性说明。

## TASK-001 第3批 Session 持久撤销部署输入

[Q-001](decisions/questions/Q-001-Session撤销与Redis故障恢复.md)采用袁尚峰2026-11-14选择的B方案；字段、锁序、Cookie、依赖失败及保留规则见[会话与身份](detailed-design/key-designs/会话与身份.md)。

- 迁移建立 SessionGuard、摘要唯一约束及撤销清理意图，发布时 API／IM 同时采用持久依据核对。协议切换期间阻断旧鉴权实例；既有Redis Session缺少登记时要求重新登录。
- 账户、凭据版本、SessionGuard和退出审计使用同一权威PostgreSQL；鉴权及锁后重查读取主库。连接预算包含逐请求及IM投递检查，按真实负载验证；应用权限禁止修改已签发凭据的归属与摘要。
- Redis读取／续期失败采用有限超时；持久撤销提交后，Redis清理或IM提示失败由持久意图重试。核对Cookie安全属性、同源Origin配置及CSRF，日志按字段白名单脱敏。
- Redis恢复可继续接受当前有效Session，逐次核对持久撤销、凭据版本及期限；缺失值不从登记自动重建。数据库历史恢复期间阻断入口并停止签发／续期，撤销所有恢复出的SessionGuard、清空Redis Session命名空间并断开现有连接后再开放入口。
- 回退版本必须识别SessionGuard及撤销依据；版本回退先核对所有API／IM的鉴权协议，采用旧鉴权逻辑的版本通过重新评估及迁移流程处理。TC-COM-015—017登记恢复与跨实例证据。

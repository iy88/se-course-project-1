# 1. 阶段划分与依赖

## 设计固化与编码边界

D0 完成模型、契约、关键规则及验证预期，评审成果由 `design` 合入 `main`。S1 交付工程底座、通用基础设施、依赖验证、GitHub CI、分进程开发启动和维护工具，为 S2—S4 提供共同工程前置。阶段开发可以重叠，依赖前一阶段真实实现的功能使用[阶段开发基线](03-阶段准入与验收安排.md#阶段开发基线)推进。阶段批准版本、责任人和证据在[准入记录](../acceptance/阶段准入记录模板.md)登记。

## 实现目标与用户故事

| 阶段 | 实现范围 | 可独立体验的主链 |
|---|---|---|
| S1 工程底座 | Java/Maven API、双前端、GitHub CI、分进程开发启动，PostgreSQL、Redis、OSS、SMTP、共享运行机制及维护工具 | 构建并分进程启动示例，验证文件、事务、投递、调度及维护工具的初始化、清理和重试 |
| S2 账户、商品与基础管理 | US-01 账户与头像；US-02／03／09／13 商品、目录、基础审核和展示；US-04 商品评论、回复和收藏。实现审核结果的站内持久化与查看 | 用户登录后上传图片、选择分类并发布商品；管理员维护分类、认领并审核；用户查看结果，审核通过的商品可浏览、筛选、互动及下架。各路径以账户、商品与审核数据运行 |
| S3 交易与沟通 | US-05／06 请求、占用、约定、确认及取消；US-07 交易评价；US-04 私聊与交易会话；US-11 实时通知；US-12 交易入口；US-14 超时与争议触发异常事项 | 买家从商品发起请求，卖家接受并锁单，双方从交易进入会话、约定并确认，完成后评价；核对通知、已读和断线恢复。超时或争议时验证异常事项真实创建并关联交易 |
| S4 治理与管理完善 | US-07 举报与匿名结果；US-08 事项问询、审核处置沟通与申辩；US-10 管理统计；US-12 本人事项；US-14 异常事项处置 | 用户提交举报与证据，管理员认领、问询、执行处置，用户查看结果并按规则申辩，管理员结案；核对主体状态、审计及统计 |

业务场景和规则见[用户故事及验收条件](../../appendices/user-stories/index.md)及[需求与接口映射](../detailed-design/01-需求与接口映射.md)。

袁尚峰交付 Hello World 工程、双前端、API、通用基础设施、GitHub Actions、分进程开发启动和维护工具。Jenkins v2 部署由袁尚峰提前推进，用当前 `main` 验证构建与部署，支持后续小步交付。详见 [S1 任务卡](../tasks/S1-工程骨架与基础设施.md)和[部署验收安排](04-最终部署验收安排.md)。

## 工作量安排

每阶段四人各维护一个工作包和一条工作分支。一个工作包可以保留多个可独立审查的 PR，其阶段工作分支纳入本包全部联调输入。各阶段的责任人和完成条件见 [S2](../tasks/S2-商品与交易.md)、[S3](../tasks/S3-账户与沟通.md)和 [S4](../tasks/S4-治理与管理.md)任务卡。四人可以按契约和可用工时交错推进。

## 并行开发约定

- 账户、商品、交易、会话、通知和事项各由所属模块写入本域事实。跨主体操作沿用具名命令、只读投影及公共事务、锁序和幂等约定。
- 开工时核对签名、权限、错误、事务及代表性测试数据。受控替身复用同一套预期，正式联调接入真实模块。测试专用装配和数据留在测试范围内。
- 共享 OpenAPI 入口、装配和迁移按阶段合成版本核对。涉及 Flyway 时检查版本冲突，并验证干净数据库及上一阶段数据库升级。

## 跨目标契约与验证数据

| 契约 | 提供方与接入阶段 | 重点验证 |
|---|---|---|
| 账户和文件 | S2 账户及资格、S1 文件服务供各阶段复用 | 真实 Session、管理员权限、头像与商品图片核验及引用；S4 验证账户限制和事项证据 |
| 商品审核及交易占用 | S2 接入审核认领、分类及通知；S3 接入商品占用和释放 | 审核结论、认可分类及商品展示同事务；并发接受时商品占用唯一 |
| 会话及通知 | S2 提供基础审核通知；S3 接入私聊、交易会话和实时投递；S4 接入事项会话 | 当前读权限、业务写入与会话和通知的一致性，真实投递、已读及补取 |
| 异常事项与处置 | S3 提交超时或争议触发的异常事项；S4 接入认领、处置和恢复 | 对应交易与异常事项可追溯；处置结果、证据、审计及主体状态一致 |

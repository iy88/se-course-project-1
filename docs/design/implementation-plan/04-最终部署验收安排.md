# 4. 最终部署验收安排

部署归 TASK-001，各模块提交配置、迁移、依赖及兼容性信息。

## 增量构建与部署

开发者在本地执行构建、冒烟与受影响的回归验证，结果随 PR 登记。最终课程验收使用执行时最新 [`main`](https://github.com/iy88/se-course-project-1/tree/main) 的本地隔离环境。生产验收登记实际责任人和日期。

## 执行依据

批准阶段及需求覆盖完成后，按运行说明从干净环境启动，登记来源分支、产物、环境配置、迁移及资源版本。依据实际拓扑核对分流、健康与退出。

## 验收范围

全链路、权限与隐私、真实数据库及媒体访问、外部故障与备份恢复、发布切换及回退兼容、获准负载。当前发布脚本按整组切换验证，滚动流程按对应演练登记。性能采用需求第6、7章条件，执行前核验参数、样本和口径。

## 性能测量

按[质量要求](../../requirements/06-质量要求.md)及[验收依据](../../requirements/07-验收与验证.md)执行。记录环境、发布版本、网络条件、活跃用户数、商品规模、操作配比、实际速率、有效样本和失败样本。

2026-11-27 的本机代表性执行、默认 capacity、性能上限和 legacy 对照见 [TC-PERF-001 性能与容量测试报告](../test-cases/reports/performance-capacity/测试报告.md)。该证据适用于所列 Mac loopback 环境，不代替目标部署的 WAN 复测。

- 常用交互采用 100 名同时活跃用户及 10,000 条商品记录，从用户发起到可用结果计时，至少 95% 在 3 秒内返回。
- 文本消息在双方在线、网络正常时，从发送方发出到接收端实际显示计时，至少 95% 在 2 秒内显示。用本次发送结果的消息标识与接收端显示记录关联样本，纳入未显示或超时样本，并保存端点计时的时钟校验依据。覆盖双方连接分布在不同 IM 实例的情形。S3 开发期间可通过集成测试验证事件分发、顺序及恢复。接收端显示时延在开发完成后的系统测试测量，最终部署按实际环境复测。

# 2. 测试策略与依据

## 预期来源

需求正文、BR／TR／权限矩阵、详细 US／UC／SC 与人工确认构成预期依据。AI 辅助扩展案例，对应任务登记的审查姓名核验预期及适用范围。

## 静态与白盒验证

后端按所选技术栈执行严格类型与静态检查（Python候选为Pyright strict、Ruff），前端使用 TypeScript 严格类型检查及构建检查。全部业务逻辑白盒核对输入、主体资格、状态、不变量、事务、锁序、失败分支与审计。审查记录对应版本和差异。

## 运行时验证选取

每个案例说明不可静态确认的性质，或所覆盖的复杂关联／跨模块黑盒行为。使用真实 PostgreSQL 多连接验证并发；使用多 API／IM／worker 实例验证共享机制。合成数据和环境版本随案例登记。

## 必要技术验证计划

| 专题 | 场景 | 预期及证据 |
|---|---|---|
| 事务及锁单 | 两实例竞争接受；提交失败；同次重试 | 唯一占用、整体回滚、稳定结果；数据库状态与命令 |
| IM | 用户连接分布两实例；重连；流裁剪或分发中断 | 目标覆盖、去重、补取与已读独立；客户端可见及持久记录 |
| 任务调度 | worker 退出、租约接管、重复投递 | 幂等业务结果、可恢复执行权；领取与执行证据 |
| Session | 跨实例续期退出、改密、Redis 恢复 | 按已确认语义生效；Q-001 结论作为预期 |
| 文件 | 上传中断、重复完成、核验后覆盖、回收竞争 | 文件内容稳定、引用与权限正确；Q-002 作为预期 |
| 邮件 | 异步重试、重发替代、并发错误提交 | 生命周期、幂等计数、敏感载荷保护；Q-003 作为预期 |

测试代码、批准执行范围、环境与真实结果在各任务及证据记录中登记。

## 分阶段回归

任务合入前运行适用检查与受影响回归；阶段验收核对主流程、关键异常和前阶段回归；最终按需求负载、权限和恢复要求验证。

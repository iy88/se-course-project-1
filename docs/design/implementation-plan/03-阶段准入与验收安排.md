# 3. 阶段准入与验收安排

## 准入

四任务设计评审集成并固化design后，准备拟进入阶段的编码任务卡及准入材料；通过阶段准入批准后开始业务编码。按阶段核对前置 Q 关闭、ADR 接受、接口双方及复核确认、状态／错误／事务／权限明确、人工前后端联合测试及适用的单元／集成预期已核验、环境与配置齐备、责任及完成条件。批准记录采用[准入模板](../acceptance/阶段准入记录模板.md)。

## Issue 与任务分支

四位成员各自的任务 Issue 在派发时登记，输入包含 design 的具体提交、需求与 ADR／Q、文件范围及依赖。分支、Draft PR、单一职责的小步 commit 及批次集成按[任务索引](../tasks/索引.md)组织。TASK-001 统筹正式决定、共享文档与生成物；成员维护自己的模块源文件并交叉审查。

## 审查与阶段验收

开发阶段按[审查模板](../reviews/模板.md)记录版本、业务与约束检查、人工前后端联合测试、优先单元测试、按需集成测试及问题处理。开发完成后执行系统测试与人工验收，按[验收模板](../acceptance/阶段验收单模板.md)记录完整业务链、关键异常、回归、残余风险与验收人。

## 变更

原因→影响需求／ADR／接口／数据／测试→人工决定→修改→回归。重大取舍新建替代 ADR，原版本通过 Git 及记录追踪。

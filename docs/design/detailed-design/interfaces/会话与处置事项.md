## 会话接口

### 会话定位与已读

REST 与实时事件共用 `conversation_kind`（`chat`／`trade`／`case`）及 `conversation_id`（主体 ID 的十进制字符串）。服务端按类型查对应会话表和参与资格。同一数值可存在于不同会话表。双人列表按登录账户与 `peer.account_id` 聚合；每条会话返回自己的类型及 ID。事项接口的 `thread` 返回 `{conversation_kind: "case", conversation_id}`，详情和列表只返回调用者有资格读取的线程。

同一账户可同时持有多个 Session 与多条连接，接口按账户身份鉴权，不把连接当作参与者。发送成功的消息投递到本人其他连接；各连接维护自身投递游标，断线或换设备后按类型会话与 `seq` 重新补拉数据库历史，不依赖连接内缓存。已读推进为账户级单调值，`message_read` 只同步本人其他连接，不告知对端；会话列表、事项列表、通知列表与通知标读均不推进会话已读。

## 事项接口

### 视角与可用操作

事项详情按调用者身份投影视角；同一事项对不同调用者返回不同内容。`available_actions` 由服务端按身份、事项状态与当前时刻计算，是当前可写动作的权威集合；调用方不自行推导入口。

| 视角 | 判定 | 可见范围 |
|---|---|---|
| `reporter` | 本人提交该举报 | 本人提交内容、进度与公开结论；不含申辩内容与他人线程 |
| `related_account` | 存在本人参与的事项线程或本人申辩资格 | 本人线程、本人申辩期限与处置结果 |
| `manager` | 当前认领人且具备平台管理资格 | 全部线程、证据与管理操作 |

同时满足多个条件时按 `reporter`、`related_account`、`manager` 的顺序取第一个，响应只投影一个 `viewpoint`。

`available_actions` 的元素取下列具名动作，按适用范围返回；表内条件除注明外均要求事项未结案。

| 动作 | 视角 | 返回条件 |
|---|---|---|
| `supplement_evidence` | `reporter` | 举报人本人 |
| `respond_inquiry` | `related_account` | 存在指向本人的未回复问询 |
| `submit_appeal` | `related_account` | 本人已受实际处置、本人申辩期限未过且尚未提交申辩 |
| `inquire` | `manager` | 当前认领人 |
| `decide` | `manager` | 当前认领人，事项为 `claimed` |
| `resolve_appeal` | `manager` | 当前认领人且有未处理申辩 |
| `close` | `manager` | 当前认领人、已决定、全部申辩期届满且无未处理申辩 |
| `publish_result` | `manager` | 当前认领人、举报事项已结案且尚未公开 |

空数组表示当前明确无可写操作；字段缺失表示响应尚未提供该投影，调用方按原有依据回退，不把缺失当作“无操作”。`pending_inquiries[]` 只出现在 `related_account` 与 `manager` 视角：`{inquiry_action_id, asked_at, scope_text}`，管理员另返回 `related_account_id`；`related_account` 只返回指向本人的条目，已回复或已归档的条目不再出现。说明消息（`statement`）必须引用该数组中的 `inquiry_action_id`，不按列表顺序推断。

### API-CASE-007 处置决定与执行

| 项目 | 内容 |
|---|---|
| 需求与决策依据 | FR-08、BR-08、BR-26、BR-32、BR-33、TR-09、TR-10；[处置与主体协同](../key-designs/处置与主体协同.md) |
| 方法与路径 | `POST /api/v1/admin/cases/{case_id}/decisions` |
| 调用者及权限 | 处置类事项的当前认领管理员；须存在决定依据；商品审核结论使用 API-PRD-006 |
| 请求 | `decision_kind`（`no_action`／`not_actionable`／`violation`）、`reason`（必填）、`basis_refs[]`（证据引用标识）、`enforcements[] {action, target_ref, expected_result}`（可为空） |

| 失败响应 | `BASIS_REQUIRED`（422）、`TARGET_STATE_CONFLICT`（409）、`TRADE_TERMINAL`（409，已完成或已终止，含同商品另有锁单的恢复请求）、`TRANSITION_NOT_ALLOWED`（409，未结束交易的转换条件不满足）、`OWNERSHIP_MISMATCH`（403）、`TRADE_FREEZE_NOT_ACTIVE`／`RESTRICTION_NOT_ACTIVE`（409）；任一执行失败整次回滚 |

| 事务 | 按公共锁序取得商品、交易、事项、会话锁后一次提交；目标集合变化时整事务重规划 |
| 隐私 | 响应只返回执行结果与受影响账户标识，不返回证据内容与他方申辩 |

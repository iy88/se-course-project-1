# 文件上传接口契约

设计归属：TASK-001 第2批；输入：design `2a7cb17`；决定：[Q-002](../../decisions/questions/Q-002-直传授权后的对象覆盖控制.md)。路径相对于统一 API 版本前缀；ID 为字符串，时间为 UTC ISO 8601。文件状态及引用采用[文件协议](../key-designs/文件与邮件.md)，主体用例调用 C3 维护关联。Cookie、CSRF、错误外壳及 Idempotency-Key 采用[共享约定](../02-共享接口约定.md)与 C1。

创建主体前，冻结账户禁止以 product_image 的 null target 申请发布上传；合规编辑已有商品时传入该商品并按其编辑资格判定。封禁账户的商品上传拒绝；事项沟通例外必须传入允许沟通的具体事项，由 TASK-004 核对当前参与资格。null target 的 case_evidence 按新建举报资格检查。上传授权仅允许暂存，绑定任意主体时仍由该主体锁后核对权限、文件归属、用途和数量。

### OSS 表单与签名条件

后端使用官方 SDK 的 PostObject V4 签名，返回固定 Bucket HTTPS 入口及完整字段。policy 固定 expiration、Bucket、精确 key（不使用客户端前缀匹配）、x-oss-forbid-overwrite=true、x-oss-object-acl=private、声明 MIME 对应的 x-oss-content-type、success_action_status=204、V4 签名字段及适用的 STS token 条件；content-length-range 限制为本次 declared_size。用途格式由后端能力规则校验。对象键由后端随机生成，包含环境／用途隔离前缀；数据库唯一约束，永不复用，客户端无法自选或补签另一个键。

客户端向 OSS 提交同一表单及一个 file 字段。首次成功返回204；同键再次上传由 OSS 返回 FileAlreadyExists，客户端随后调用完成接口查询核验结果。网络中断时可在有效期内重用同一表单；若原对象已经存在，直接进入完成核验。修改 MIME、大小、key、ACL、禁止覆盖字段或签名策略均须被拒绝。声明 MIME 只提供预筛选，后端核验实际字节后才允许业务引用。

| 隐私 | 仅返回原上传账户获准读取的元数据，日志采用 file_id、OSS request_id、检查结果；签名读取 URL 由主体查询时调用 prepare_file_read 签发 |

### 实际内容核验

从登记中的 Bucket／key 获取对象，读取实际字节，核对长度与声明值及授权用途上限、检测实际类型并核对其与声明 MIME 一致。JPEG 和 PNG 通过抽样解码验证，PDF 通过结构解析验证。后端用 `If-Match` 条件读取，检查实际字节数和读取前后的 ETag。内容不合法返回 FILE_CONTENT_INVALID 并保持 uploading，原对象保持禁止覆盖；重新选择文件需要新上传授权，原登记按期限清理。

核验所得内部 content_identity 为 {bucket, object_key, etag}，ETag 用于检测 OSS 对象变化。并发请求在文件锁内比较 ETag、大小和 MIME，匹配时返回已提交的核验结果。读取失败或校验前后变化保持原状态并返回对应错误。上传阶段无删除权限，应用仅由回收能力删除无引用对象；对象维护工具遵循相同协议。非法对象留存受暂存清理和上传配额约束。

### 正常、失败和重复调用

正常：创建授权 → OSS 首次上传 → 完成核验 → 主体写入时 attach_files → 主体查询时签发读取地址。完成响应丢失：原键重试返回同一文件核验事实；不同键也不创建第二份核验及引用。上传响应丢失且重复上传返回409：调用完成接口核对已有对象。OSS 暂时故障：返回503并保留 uploading；到期后重新创建授权。

上传授权 expires_at 是允许进入 verified 的完成期限。接近到期才完成传输的对象可能无法及时核验，客户端使用新授权重传；verified 文件之后按业务引用及保存的回收期限管理，上传授权到期不撤销已有有效引用。

## 用途与策略接入

purpose的公开值由已启用用途生成；当前为product_image／case_evidence。资格表描述各主体应提供的规则，FileUpload通过文件专题定义的策略端口调用，主体依赖参与C1准备及锁规划。[文件端口与业务策略组装](../key-designs/文件与邮件.md#文件端口与业务策略组装)定义核验器、版本及错误处理。

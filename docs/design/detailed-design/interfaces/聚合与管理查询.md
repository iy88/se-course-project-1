# 本人聚合、待办与管理查询

TASK-001第5批。输入design `2a7cb17`的R0／R1／R2a、需求FR-10／11／12、BR-16／24／27／31—34、需求4.17／4.18。账户与通知评审输入[PR #47提交2fc423b](https://github.com/iy88/se-course-project-1/tree/2fc423b)，事件及配置交界输入[PR #48提交46033be](https://github.com/iy88/se-course-project-1/tree/46033be)。主体任务提供各自字段及等义查询实现；本专题定义统一输出与查询规则，不给主体新增重复计数或待办实体。

所有路径相对于统一API前缀。ID字符串、时间UTC ISO 8601；计数为非负安全整数。分页page默认1，page_size默认20、最大100，均从后端配置取得；列表按明确次序分页，total使用相同过滤谓词。本组查询返回Cache-Control:no-store，在同一短只读数据库快照构造列表、总数及as_of（UTC查询时点）；多语句组合使用短只读REPEATABLE READ或等价单语句查询，不改变C1写事务隔离级别。

## 统一规则及适配接口

```text
AccountQueries.require_self(context) -> AccountScope
ManagementQueries.require_manager(context) -> ManagerScope
OwnerReadModel.list_owned(scope, filters, page) -> OwnedPage
OwnerReadModel.count_owned(scope, filters) -> int
OwnerReadModel.todo_candidates(scope, now) -> QueryPredicate
OwnerReadModel.require_todo_action(source, actor, qualifications, now) -> Allowed
ManagementQueries.statistics(scope, time_selection, as_of) -> ManagementStatistics
```

各主体由同一规则方法提供对象判定及等义SQL谓词。聚合层组织同一数据库快照、分页与输出白名单，不复制账户／商品／交易／事项资格条件。所有参与、归属、当前限制和事项认领在分页前处理，total、overview及待办counts复用同一谓词。

R0商品与收藏、R1交易与评价、R2a会话及后续事项模型的字段由对应任务绑定。TASK-002／003／004在本域接口批次交付OwnerReadModel实现及字段映射，当前源文件已有的归属与权限直接作为本批设计依据；源字段未交付项以具名适配要求登记，集成逐项核对，编码采用design实际集成版本。

## 查询适配的组合与能力检查

采用[公共能力扩展边界](../key-designs/公共能力扩展边界.md)。OwnerReadModel为聚合侧声明的端口，各主体提供实现，应用组装层按资源kind绑定。QueryScope显式携带当前身份、as_of及同一只读快照参与句柄；list_owned、count_owned及todo_candidates在该scope内执行，不开启独立快照。QueryPredicate表示查询语义及参数，可由持久化适配器实现，不能要求跨模块传递某一ORM的表达式或会话对象。

聚合层组合主体投影、稳定排序、计数与分页；主体维护当前资格及等义筛选条件。更新业务类型时同步公开schema及输出白名单，统一快照和分页算法复用。启动时检查各查询所需的主体实现完整且唯一；运行时依赖故障沿既有503语义处理。文件用途的策略、内容核验器及规则schema也由配置完整性检查验证，配置值不承载业务实现。

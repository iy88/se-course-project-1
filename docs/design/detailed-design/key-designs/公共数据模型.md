# C9 公共数据模型、约束与保留

TASK-001第7批。输入design `2a7cb17`及本任务专题评审输入：文件[PR #46提交3d9adb6](https://github.com/iy88/se-course-project-1/tree/3d9adb6)、身份／邮箱[PR #47提交2fc423b](https://github.com/iy88/se-course-project-1/tree/2fc423b)、事件／任务[PR #48提交46033be](https://github.com/iy88/se-course-project-1/tree/46033be)、配置／查询[PR #49提交2401508](https://github.com/iy88/se-course-project-1/tree/2401508)。关联FR-01／02／07／08／11／12、ADR-002—009及DATA-01—04。

本文件定义账户、账户封禁、通知、幂等及审计的公共数据结构，并汇总专题已定义的数据及关联。已有专题字段、状态协议和参数默认值以其唯一源文件为准，汇总表用于迁移及交界核对，变更先更新维护方源文件再同步引用。代码与迁移采用design中实际集成版本；表名为设计名，实际迁移逐项登记对应关系。

## 通用类型与主外键

| 类型 | 数据库及对外表示 | 结构约束 |
|---|---|---|
| EntityId | 正数bigint主键／外键；接口十进制字符串 | 同一主体ID稳定，创建后不以邮箱／名称替换；常规分配不复用 |
| OperationId／EventId／TaskId／GroupId | UUID | 各自标识逻辑操作、投递、任务及邮箱验证组，不相互替代 |
| 时间 | timestamptz，服务端UTC；接口ISO 8601 | 期限晚于创建／签发；锁后期限使用数据库当前时钟 |
| 技术序号／版本 | bigint，非负或按源规则正数 | HTTP／WS使用安全整数范围，账户事件seq_head及floor符合C2；版本只在所属操作递增 |
| ResourceRef | 已登记resource_type及EntityId | 传输／审计引用有明确维护方，解析时核对归属和保留；实际主体关系采用明确外键 |
| 受限JSON | jsonb，具名schema及版本 | 不以任意字典替代核心关系；禁止凭据／验证码／正文进入通用日志及幂等载荷 |

账户外键引用Account。跨模块商品、交易、三类会话、事项及执行记录的具体表名由TASK-002／003／004维护；公共引用不复制其当前资格、认领人、交易双方或快照事实。历史／审计保留采用RESTRICT或明确逻辑删除协议，禁止因删除临时Session或幂等结果级联抹除业务历史。

## Account：账户及凭据版本

唯一维护方：账户模块。当前身份、凭据及账户资料由Account统一提供；归属以account_id保持。

| 字段 | 类型／空值及独立用途 |
|---|---|
| account_id | EntityId主键 |
| email | 非空text，去首尾空白的实际投递邮箱，登录比较经统一normalize_email函数 |
| display_name | 非空text，当前显示名称；长度／内容由当前配置检查 |
| password_hash | 非空text，密码库自描述专用散列，不保存原始密码 |
| credential_version | 正整数，初始1；改密／重置及Q-004换绑成功同事务递增，用于旧Session和旧邮箱请求失效 |
| role | 具名user／manager事实；manager按规则具有普通用户能力，角色当前变更及依据进审计 |
| created_at | 非空UTC创建时间 |

email的数据库唯一索引使用与Account.normalize_email等义的确定性函数表达式；应用查找、邮箱资格锁和数据库唯一性共用同一规范，禁止另存normalized_email列。迁移及编码测试使用大小写、空白与格式边界向量核对数据库函数和应用方法；实际支持邮箱字符集在接口schema与投递库适配中一致声明。

Account.roles()从当前role给出接口所需角色集合，Account.require_manager()检查当前角色；不保存第二套is_admin。Account.is_banned(restrictions, now)读取当前有效AccountBan，冻结从TASK-003所属交易冻结及参与关系取得，不保存账户级派生冻结布尔值。显示名称的历史事实由业务快照／审计保存，不从当前display_name回算。

唯一性竞争由具名约束映射EMAIL_IN_USE，版本／邮箱／密码修改按C1与专题锁序执行。账户当前记录及业务归属保留，不以本表新增账户注销流程；维护方在实际需求变化时定义删除及保留协议。

## AccountBan：独立封禁来源与解除事实

唯一维护方：账户模块，TASK-004事项执行调用。冻结由交易主体维护，本表只承载账户封禁的实际执行结果。

| 字段 | 类型／空值及用途 |
|---|---|
| restriction_id | EntityId主键 |
| account_id | 非空账户外键 |
| source_execution | 非空具名事项执行引用，实际执行表由TASK-004绑定；同一执行对同一账户唯一 |
| reason | 非空受限理由，来源于实际处置依据，内容规则由事项输入核验 |
| applied_at／released_at | 执行时间非空，解除时间可空；解除不得早于执行 |
| release_execution | 实际解除执行引用或null；与released_at配对，重复解除沿用原记录 |

索引覆盖account_id及未解除来源查询。多个封禁来源分别保留，账户是否封禁由有效来源存在性计算；解除一项不清除其他来源。封禁／解除与适用交易、请求及通知按C1／R1／R2b同事务组织。历史依据继续保留，不将来源行清理成单个当前布尔值。

## SessionGuard及撤销清理：采用Q-001唯一源

源定义：PR #47的会话与身份0.1.1。账户模块维护，公共数据关系汇总如下：

| 数据 | 字段类型摘要及关系 | 主键／约束／索引 | 保留依据 |
|---|---|---|---|
| SessionGuard | session_id EntityId、token_digest bytea32、account_id外键、credential_version签发快照、issued_at／absolute_expires_at、idle_timeout_seconds／renew_interval_seconds、csrf_digest bytea32、revoked_at可空 | PK session_id，UNIQUE token_digest；期限晚于签发，0＜续期间隔＜空闲≤绝对跨度；account_id／绝对期限扫描索引 | 至少绝对期限；未完成清理意图继续保留，缺失登记按身份无效 |
| 撤销清理意图 | session_id唯一关联、created_at、next_attempt_at、attempts、completed_at可空；认领token／租约依公共ClaimableWork | 一Session一清理意图，次数非负、租约字段配对，未完成重试扫描索引；使用外键时先归档／删除已完成意图再清理Guard，禁止丢失未完成工作 | 与持久撤销同次提交，Redis清理和IM提示结束后按保留规则归档 |
| Redis Session | token_digest定位键；session_id及last_activity_at，TTL受空闲／绝对期限约束 | Redis运行时数据，需同时通过当前SessionGuard／Account检查 | 缺失不从数据库自动重建，旧值不能覆盖持久撤销 |

原始Session／CSRF凭据不进数据库及日志。审计中的内部Session标识仅为关联值，不对临时SessionGuard设置会导致历史级联删除的强依赖。PostgreSQL历史恢复按Q-001清除有效授权状态并轮换C2事件epoch，Redis操作限制v2命名空间。

## EmailVerification：采用Q-003一张表

源定义：PR #47邮箱验证与投递0.1.1。email_verification由账户模块维护，验证状态及本轮投递进度共用一行；不另建邮件载荷／投递表或镜像TaskSchedule。

| 字段组 | 类型及关系 | 结构及查询约束 |
|---|---|---|
| 标识及用途 | id EntityId PK；purpose具名枚举；email text；account_id FK或null；entry_digest bytea32或null；group_id UUID | 注册account为空且entry绑定；重置由账户与入口绑定，换邮箱按账户及同group两行；UNIQUE(group_id,purpose) |
| 本轮验证 | code text或null、code_length／max_failed_attempts／failed_attempts整数、created_at／expires_at、credential_version可空、rule_version | 保留前导0；未失效格式符合保存的长度；失败次数非负；已消费或明确失效时code=null；期限先于清理判断 |
| 结束事实 | consumed_at／invalidated_at可空 | 至多一种已结束事实，错误／消费与账户操作采用专题事务；不另存verified／active |
| 投递事实 | delivery_rules JSON具名快照、send_attempts、next_attempt_at、lease_token／lease_until、sent_at可空、last_delivery_error脱敏类别 | 次数非负，租约配对；scope及未发送／租约／到期扫描索引；旧token不覆盖接管结果 |

scope通过purpose、account或entry、规范邮箱构成；换邮箱替代作用域按账户整组处理。发送成功后code仍供校验，消费／替代／到期／耗尽清空；数据库历史恢复先失效恢复出的验证行并清空code／租约。记录保留至少覆盖本轮验证及公共幂等期限，秘密原码不复制到审计、队列或通用幂等表。

## 文件登记及引用：采用Q-002与C3唯一源

源定义：PR #46文件协议0.2.0及上传接口0.1.0。文件能力唯一维护；TASK-002／004通过C3调用建立／保留／释放引用。

| 数据 | 字段类型摘要及关系 | 结构约束／索引 | 保留与来源 |
|---|---|---|---|
| FileRecord | file_id EntityId PK、owner_account_id FK、purpose、state、object_key、上传声明与授权期限／规则快照、upload_target或null、content_identity、verified_metadata、created_at／verified_at／cleanup_after、signing_context | object_key唯一且不复用；状态及核验事实配对；owner／用途及回收状态／期限索引 | uploading至核验／回收，verified保持内容标识；cleaning／deleted拒绝新引用 |
| FileReference | reference_id EntityId PK、file_id FK、target ResourceRef、slot、created_by、created_at | 同file＋target＋slot有效引用唯一；file_id及target查询索引；实际主体关联由C3授权及所有权维护 | 历史／证据引用分别保存，释放只影响指定关系；重新建立关系取得新reference_id |
| 清理墓碑 | FileRecord的deleted状态及原key、授权截止时间、最近尝试事实 | 周期迟到上传扫描，键索引保留 | 迟到对象重复删除，保留键不复用依据；不得清理有效历史引用 |

content_identity及核验字节依据不由客户端替换；幂等重放的上传表单采用原期限及签名上下文。临时文件清理与主体历史保留分别维护，当前图片解除引用不等于删除历史图片。FileReference作为当前有效关系保存，释放删除指定当前关系，原ID由主体审计留作事实关联，业务历史使用独立有效引用；不为已释放关系保存第二份可用状态。

## Notification：通知事实及已读

唯一维护方：通知模块。接收范围、业务来源及模板由触发用例提供，读取资格由当前主体方法检查。

| 字段 | 类型／空值及用途 |
|---|---|
| notification_id | EntityId主键 |
| recipient_account_id | 非空Account外键 |
| intent_key | 非空稳定字符串，同recipient唯一 |
| event_type | 业务通知类型，如trade.request_accepted；由触发方登记 |
| source | 非空ResourceRef，关联业务来源，受当前读取资格控制 |
| business_event_id | UUID或null；与系统消息共同来源时必填，同次业务子事件稳定 |
| template_key／template_version | 非空具名模板及版本，保证可解析保存的display_params |
| display_params | 非空具名JSON schema，可为空对象；仅允许最少展示事实 |
| occurred_at／created_at／read_at | 业务时间及创建时间非空，首次已读可空；read_at≥created_at |

索引覆盖(recipient_account_id,created_at,notification_id)及本人未读扫描。同一意图返回已有通知，异载荷冲突；打开具体通知后首次设置read_at，列表不标读。通知不保存unread_count、业务待办完成或聊天阅读进度。

传输UserEvent使用C2的notification_created／notification_read，引用notification_id；Notification.event_type保留业务类型，二者不混用。Notification不重复保存反向event_id，创建结果通过EventIntentBatch对应接收人取得。模板参数／来源在当前权限下投影，签名URL及验证码走专用流程；历史通知沿主体要求保留，不采用短期传输事件TTL删除。

## 幂等结果与审计

| 数据／维护方 | 字段及类型 | 约束／索引／保留 |
|---|---|---|
| OperationResult／C1公共能力 | operation_id UUID PK；actor_kind、actor_ref（账户／entry／system服务端依据）、operation_name、idempotency_key；request_digest bytea、digest_version／key_version；HTTP状态、受限result_data JSON、result_refs、created_at／expires_at | UNIQUE(actor_kind,actor_ref,operation_name,idempotency_key)；expiry扫描索引；同键异输入409；成功结果与业务同事务，验证码错误结果按专用语义提交；到期后客户端先同步事实，不能假定键永久保留 |
| AuditRecord／公共审计能力 | audit_id EntityId PK、occurred_at、actor_kind、actor_account_id FK或系统／entry关联、actor_name_snapshot可空、action、target、basis_ref可空、before_after具名JSON、operation_id及必要规则／配置版本 | 字段白名单与操作者配对；按target／时间、actor／时间及operation_id索引；成功记录与业务同事务，重放不重复，回滚无成功审计；业务历史保留规则独立于临时幂等／Session清理 |

含密码／验证码的输入摘要采用PR #47专用HMAC及版本引用；原文不进OperationResult。result_data不保存Cookie或签名地址，登录签发不使用通用成功结果重放保存原始凭据。审计operation_id／Session标识为历史关联值，幂等结果或Session清理不级联删除审计。entry只能标识公开账户入口，验证后的业务操作者按实际账户记录。

## 账户事件与通用任务：采用C2唯一源

源定义：PR #48实时与任务0.1.0。下面汇总结构约束与保留，具体传输、权限投影、认领及ACK仍由C2维护。

| 数据 | 字段类型及键 | 不变量、索引及保留 |
|---|---|---|
| EventNamespace | 单例主键＋epoch UUID | 各实例共用，历史恢复轮换，旧客户端cursor重新快照 |
| AccountEventHead | account_id PK／FK、seq_head／replay_floor bigint | 0≤floor≤head；事件最终锁域分配，回滚不推进；清理同事务推进连续前缀floor |
| UserEvent | event_id UUID PK、recipient_account_id FK、account_seq、event_type／schema_version、intent_key、source、origin_connection_id可空、occurred_at／created_at／expires_at | UNIQUE(recipient,seq)及(recipient,intent_key)；账户seq及expiry索引；源引用不替代消息明确外键，传输保留期限不删除业务历史 |
| UserEvent派发字段 | lease_token／lease_until、attempts、next_attempt_at、published_at可空 | 可与事件同表保存；租约配对，attempts非负，待派发索引；published_at仅表示Redis发布确认，客户端ACK不删除其他设备可重放事件 |
| TaskSchedule | task_id UUID PK、task_kind、source_ref、trigger_key、source_version、due_at／rule_version；attempts／next_attempt_at、lease_token／lease_until、completed_at／cancelled_at、脱敏last_error | UNIQUE(task_kind,trigger_key)；到期／重试／租约索引，完成与取消互斥；主体锁后token校验与业务原子完成，旧token拒绝；保留触发及完成依据，清理按来源规则 |

邮箱、文件及事件派发由自己的持久记录实现ClaimableWork，不把同一事实复制进TaskSchedule。Redis只保存运行时Session、流／队列、连接租约与协调状态；命名空间按v2前缀隔离，逻辑DB可在后续部署选择。客户端ACK、消息阅读与通知阅读分别维护。

## 规则与迁移检查清单

1. 字段来源逐项应用DATA-01—04：身份及归属只存必要事实，历史快照和版本有明确用途；本人概览、待办、管理统计、can_*及unread_count都通过查询／类方法取得，不新增持久镜像表。
2. 数据库唯一、外键、空值配对、期限与计数约束由迁移承载；用途大小、次数上限与期限参数由类型化配置及保存的快照校验。跨模块外键／引用采用主体实际模型后核对，不能以未交付字段假装已有迁移。
3. 按C1资格与业务锁序核对各关系创建、释放及清理；迁移测试验证失效与清理不会级联抹除历史、恢复不能重新授权，索引支持当前查询谓词。
4. PostgreSQL使用同一v2业务数据库，legacy与v2库名／用户独立；真实DDL、Alembic修订号及数据迁移命令随实现提供，当前交付为设计及检查输入。

实际验证采用TC-COM-033／034，并复用文件011—014、身份邮箱015—022、事件任务023—028及查询029—032的专题预期；对应运行环境与结果随编码任务登记。

## 扩展标识与技术栈映射

采用[公共能力扩展边界](公共能力扩展边界.md)。本模型的主外键、唯一性、保留及事务约束以PostgreSQL语义表达，持久化类、DDL迁移工具及框架由技术映射确定。FileRecord.purpose是服务端登记的稳定标识，首批公开product_image／case_evidence；其目标类型、策略和核验器由文件专题与应用组装定义。新增正式用途同步API schema与数据库适用约束，保持文件生命周期算法稳定。

历史授权保存的规则及版本继续可解析；用途停用不删除有效引用或改变已核验内容。Notification来源、UserEvent来源及TaskSchedule.task_kind通过对应主体端口解析，清理或部署升级前检查存量版本可处理。数据库保存事实与必要版本，策略实现和框架类名不进入业务表；无需新增插件表。文件专题、C2与查询端口为唯一行为来源，本汇总同步其实际集成版本。

# 邮箱验证与异步投递：单表协议

归属：TASK-001第3批，PR #47。输入design `2a7cb17`及本批会话契约 `4759b1d`。依据FR-01、BR-20—22、需求4.19、ADR-008、[Q-003](../../decisions/questions/Q-003-异步邮件敏感投递内容保护.md)。袁尚峰（iy88）2026-11-14通过标注决定：一张表承载邮箱验证及其投递进度，PostgreSQL短期明文保存验证码，不增加应用层加密。

## 单表字段、约束与用途

账户模块维护 `email_verification`。一条记录对应一封邮件及一轮验证码；一次换邮箱创建同组的旧邮箱／新邮箱两行。该表同时是持久待投递来源，Taskiq消息只携带记录ID；定时扫描可重新发现未完成任务。邮件不另设载荷表、校验摘要表或专属投递表。

| 字段 | 类型／空值及事实来源 |
|---|---|
| id | 数据库整数主键，对外字符串；本轮稳定标识 |
| purpose | registration、password_reset、email_change_old、email_change_new具名枚举 |
| email | 去首尾空白的实际投递地址；比较与唯一性使用Account.normalize_email；不设重复的normalized_email列 |
| account_id | 账户外键或null；注册为null，其他为对应账户；服务端由当前身份或邮箱查找确定 |
| entry_digest | 32字节公开账户入口上下文摘要，或null；注册／重置必填，登录后的换邮箱为null |
| group_id | UUID；换邮箱两行共用且purpose不同，其他每轮独立生成；用于两份验证不可混搭 |
| credential_version | 已有账户签发时的凭据版本快照，注册为null；版本变化使旧验证失效 |
| created_at／expires_at | UTC时间；保存本轮期限，重试不延长 |
| code | 按本轮配置长度生成的十进制字符串，保留前导0；短期明文，可为null；消费或失效后清空 |
| code_length／max_failed_attempts／rule_version | 本轮格式、错误次数上限及规则版本快照；校验与旧授权一致 |
| failed_attempts | 非负整数，初始0，按不同逻辑提交的错误校验次数原子递增 |
| consumed_at／invalidated_at | UTC时间或null；分别保存成功消费与重发替代／耗尽等失效事实，结束原因随审计记录 |
| delivery_rules | 本轮投递次数上限及重试间隔快照，供接管与重试沿用 |
| send_attempts／next_attempt_at | 实际发送尝试次数、下次可认领时间，未结束轮由任务规则维护 |
| lease_token／lease_until | 本次认领UUID及UTC租约截止时间，未认领为null；更新投递结果必须匹配token |
| sent_at | SMTP服务接受本轮邮件的首次已确认时间或null；不宣称收件人已收取 |
| last_delivery_error | 脱敏错误类别或null，保存网络／SMTP分类；不保存邮件正文、验证码或原始服务响应 |

主键、账户外键、(group_id,purpose)唯一；按purpose＋account_id＋邮箱规范化表达式、purpose＋entry_digest＋邮箱规范化表达式建立查询索引。scope是这些事实构成的查询条件，不新增scope_key列。约束：expires_at＞created_at、failed_attempts≥0、send_attempts≥0、有效code长度符合保存的code_length、已消费或已失效时code为null、租约token与截止时间成对存在。索引覆盖到期清理及 next_attempt_at／lease_until 的未发送任务扫描。当前有效状态、可认领状态及是否过期由方法计算；不存active、verified或delivery_status等派生列。

## 类方法与事务

| 方法 | 输入／结果及唯一规则 | 调用入口 |
|---|---|---|
| EmailVerification.require_usable(context, account, now) | 核对purpose、邮箱、入口或账户、版本、同组关系、期限、消费／失效和尝试上限；成功Allowed，否则具名错误 | 注册、重置、换邮箱在行锁后调用 |
| EmailVerification.check_code(submitted) | 使用恒定时间比较；匹配返回Allowed，不匹配返回具名校验结果，由专用验证用例累计本轮失败 | 账户动作原子校验 |
| EmailVerification.consume(now) | 与账户变更同事务设置consumed_at、code=null；失败回滚保留原码及未消费事实 | 注册／重置／换邮箱成功路径 |
| EmailVerification.invalidate(now, reason) | 设置invalidated_at、code=null，撤销未开始的认领；已被替代／消费保持原事实 | 重发、错误耗尽、到期清理 |
| EmailVerification.require_delivery_lease(token, account, now) | 核对当前租约token、未过期／未结束、当前账户版本和仍有原码；成功Allowed，失败结束本次发送；已认领尝试不再按未认领次数条件过滤 | worker实际SMTP发送前 |
| EmailVerification.is_sendable(now) | code非空、未结束且未过期、sent_at为空、到达重试时点、send_attempts未达保存上限、租约可取得；包含当前账户版本有效性 | worker候选查询及行锁后复核，采用等义查询条件 |

Account.normalize_email对去首尾空白后的登录标识作大小写无关比较，账户唯一索引、邮箱锁及全部账户入口共用；实际投递仍使用保存的输入地址。规范化属于统一方法及索引表达式，不新增重复列；已有邮箱在迁移时核对重复归并风险。

锁域遵守C1：先所有账户资格锁，再SessionGuard行锁，再取得邮箱命名空间的事务级advisory锁（规范邮箱稳定散列为锁键，按实际锁键排序并去重），随后幂等占位；在业务锁之前按账户ID锁账户资料行、按id锁本用例全部邮箱验证行。匿名注册通过邮箱锁串行与邮箱占用变化协调；换邮箱先准备旧／新邮箱和两行记录。发现需要更早对象时整次回滚重规划。worker／到期清理只锁本表行，不在持有该锁时反向取得账户或Session锁。

## 申请、重发及公开账户入口

注册／忘记密码入口由服务端创建短期、签名保护的 `__Host-se_entry` HttpOnly／Secure／Lax Cookie，包含随机入口nonce、截止时间和CSRF凭据摘要；GET /account/entry-context提供对应CSRF值，状态变更校验Origin及请求头。与已有Session CSRF分开，访问账户入口不覆盖当前Session。入口nonce摘要绑定验证行和公开幂等作用域，不接受客户端自选entry_id；签名密钥通过后端配置提供。此签名用于入口完整性，与本轮验证码明文决定分别表达。

同次申请按入口或账户＋操作＋Idempotency-Key重放原请求ID及期限；敏感原码与SMTP内容不保存到幂等响应。不同键明确重发时，在同一scope的邮箱锁内使旧轮失效并清空code，再建立新轮。换邮箱重发作用域按account_id确定，与拟换入邮箱变化无关，成组重发旧／新两行并使该账户旧组失效，避免跨组拼接。注册创建账户前，账户与全部业务对象均不建立。

忘记密码申请对邮箱存在与否统一返回202及相同结构。邮箱不存在时返回无法命中真实行的请求标识及统一期限，不创建投递记录；后续提交统一验证失败。标识生成、响应结构及请求处理时间不暴露账户存在性，具体时延策略通过接口集成验证。注册使用已占用邮箱按BR-21返回明确EMAIL_IN_USE。

## 错误次数与同次重试

格式不合法在schema边界422，不累计；格式合法但不匹配时，专用验证用例在行锁内累计一次failed_attempts，并保存该逻辑提交的失败结果后提交；达到上限同事务失效并清空code。该分支返回422 VERIFICATION_CODE_INVALID，不能由普通BusinessError处理再次回滚计数。共用幂等结果存储按原键重放失败结果，同键重试不重复计数。

涉及密码及验证码的请求由专用输入摘要协议使用服务端密钥HMAC计算、保存算法及密钥版本；使用已有入口签名密钥派生独立用途子键，密钥可用期覆盖幂等保留期。日志、追踪、原始request dump及通用幂等表不保存密码／验证码原文。校验摘要仅用于区分同次请求负载，不作为验证码校验的第二份权威数据，也不引入验证码加密存储。

换邮箱先核对两行purpose、group、账户及当前旧邮箱；两个格式合法验证码在同一事务全部检查，对不匹配的行各累计一次，匹配行不提前消费。全部匹配时才原子消费两行、更新账户邮箱及必要审计；任何账户唯一性或后续写入失败均整体回滚。注册和重置遵循同一账户变更／消费提交边界。

成功消费后原码已清空，同次成功请求仍由幂等记录识别并按当前结果读取资格重放；旧入口提交不同键只能得到已使用／失效错误。重置成功后的同次请求可在原entry及请求键范围内取得原无敏感信息的成功确认，不以已变化的凭据版本重新执行重置。新密码与原码都不返回客户端。

## worker认领、发送与清理

1. 调度读取未投递且有效的行；短事务使用行锁及公共租约协议分配lease_token、lease_until，递增send_attempts；在事务内重查当前账户版本及is_sendable，随后提交。
2. 事务外发送SMTP。发送前重新读取行及当前版本并调用require_delivery_lease核对token、剩余期限、消费／失效事实；短时将收件地址与code加载到worker内存，SMTP网络超时及取消均显式处理。
3. 成功后短事务按lease_token条件记录sent_at并清理租约；失败记录脱敏类别、下次有限重试时点并释放租约；token已被接管时旧worker不覆盖新认领结果。进程在发送后、落库前退出时，后续认领可能重发同一个code，属于同轮重复邮件，不生成新轮或延长期限。
4. 重发、成功消费或到期可以与已开始的SMTP交错；本轮在数据库先失效后，外部已在途邮件可能到达，但其code不能再消费。若worker已读取原码，数据库清空不撤回其内存及在途邮件；worker在发送结束后释放内容引用，错误及日志采用字段白名单。
5. 发送成功只结束投递进度，code仍供用户校验。消费、替代、到期或失败次数耗尽时清空code；周期扫描兜底，业务校验始终先检查expires_at，清理滞后不会延长有效性。到达本轮投递尝试上限时停止自动发送并允许用户按新键重发；本轮已成功到达的code仍按原期限可用。

数据库备份可包含当时有效原码，随备份策略保留；历史恢复先隔离账户入口，批量失效恢复出的全部验证行、清空code及租约，再恢复worker和入口。应用数据库账户及worker只读取本流程所需字段，日志与审计不留code。记录归档时清除入口摘要、邮箱等非必要数据，保留期限采用阶段实际配置；交易、聊天与处置历史不使用本表清理规则。

## 文件邮件配置输入

| 配置 | 类型／默认值及依据 | 范围、公开性及生效 |
|---|---|---|
| EMAIL_CODE_LENGTH | 整数，默认6位，十进制随机码 | 6—10；公开格式，新轮快照 |
| EMAIL_CODE_TTL_SECONDS | 正整数秒，默认600，覆盖邮件交互 | 60—1800；公开，新轮保存截止时间 |
| EMAIL_CODE_MAX_FAILED_ATTEMPTS | 正整数，默认5，限制在线尝试 | 1—20；新轮快照，接口仅按策略输出必要提示 |
| EMAIL_RESEND_INTERVAL_SECONDS | 正整数秒，默认60，防止反复投递 | 1—600；公开retry_after，申请时取当前值 |
| EMAIL_SEND_MAX_ATTEMPTS／EMAIL_SEND_RETRY_SECONDS | 正整数，默认3次／30秒 | 次数1—10，间隔1—300；新轮保存适用投递规则；内部 |
| SMTP_TIMEOUT_SECONDS／EMAIL_LEASE_SECONDS | 正整数秒，默认10／60 | 超时1—30，租约大于超时并覆盖调度余量；worker只在有效租约内开始发送；内部 |
| EMAIL_CLEANUP_SCAN_SECONDS／EMAIL_RECORD_RETENTION_SECONDS | 正整数秒，默认60／86400 | 扫描1—300；保留至少覆盖验证码TTL及公共幂等保留期限；内部 |
| SMTP_ENDPOINT／SMTP_CREDENTIALS／SMTP_SENDER | 必填类型化连接、凭据来源及发件地址 | TLS方式及端口关联校验，凭据不公开；实例安全配置，按受控发布生效 |
| ACCOUNT_ENTRY_SIGNING_KEYS／ACCOUNT_ENTRY_TTL_SECONDS | 必填带版本签名密钥集合；入口期限默认1800秒 | 入口期限大于验证码TTL；原密钥保留到适用入口及幂等到期；内部 |

IP／邮箱／入口的申请频率及发送预算由当前配置统一限制，429返回Retry-After；登录失败次数仍按BR-21不新增锁定阈值。具体采用值、公共Taskiq租约参数和SMTP依赖在C5／阶段准入登记，.env.example随实现建立。投递次数上限及重试间隔的当次快照归入rule_version对应参数，与过期／重试判断一致。

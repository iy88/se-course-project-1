# 交易与评价

设计归属：TASK-003。本文件第 2 批定义 T1 主体与关系、T2 转换与计时；第 4 批补充 T4 跨主体调用顺序与原子范围；接口在第 3 批登记，验证预期在第 5 批登记。

## 关联需求、决策与接口

- 需求：FR-05（请求、约定、终止与争议）、FR-06（完成确认）、FR-07 评价部分、FR-09 占用部分、FR-14 交易部分；US-05、US-06、US-07；SC-05、SC-06、SC-09；BR-01—BR-09、BR-14、BR-18、BR-24、BR-27—BR-30、BR-32、BR-33；TR-11—TR-19；4.15。
- 决策：ADR-002（主体模块及统一业务数据库）、ADR-003（统一用例事务与幂等）、ADR-006（分作用域配置与规则版本）、ADR-010（RESTful 契约）；CHG-001 的终态规则。
- 公共契约：[公共事务与权限](公共事务与权限.md)（C1 0.1.2）、[账户与通知](../interfaces/账户与通知.md)（C3 0.1.1）、[商品与交易协同](商品与交易协同.md)（R1 0.2.2）、[商品与分类](商品与分类.md)（R0 0.1.2）、[会话与处置事项](会话与处置事项.md)（R2a）。
- 本文件只定义交易与评价主体的数据、状态、计时和事务约束；商品状态、会话消息、事项处置分别由 R0、R2a、R2b 维护。

## 主体与关系（T1）

### 实体总览

| 实体 | 职责 | 关键关系 | 生命周期 |
|---|---|---|---|
| Trade（请求／交易） | 一笔请求从提交到结束的聚合；承载双方、状态、当前约定、终止原因和版本 | 商品 1:N（同时至多一笔有效）；买方／卖方各 1；约定、取消、争议、确认、计时、冻结、历史、评价均属于本笔 | 待接受→进行中／已拒绝／已撤回／已关闭；进行中→已完成／已终止／有争议／异常交易；有争议／异常→进行中（恢复）；终态不再改变 |
| TradeItemSnapshot | 接受请求时的商品内容快照，保证历史交易内容不被后续编辑改写 | Trade 1:1 | 接受请求时创建，不可变 |
| AgreementVersion | 首次约定与变更的提案／生效版本；保留全部提案历史 | Trade 1:N，当前至多一条有效 | 提案→生效／拒绝／被替代 |
| AgreementDecision | 对某一约定提案的不可变决定 | AgreementVersion 1:1 | 同意或拒绝后不可变 |
| CancellationProposal | 取消申请及直接取消记录；按阶段和角色决定是否需要对方同意 | Trade 1:N，当前至多一条待决 | 待决→同意／拒绝／撤回；直接取消直接同意 |
| CancellationDecision | 对某一取消申请的不可变决定 | CancellationProposal 1:1 | 同意／拒绝／撤回后不可变 |
| TradeDispute | 争议记录、说明、解决方式与管理依据 | Trade 1:N，当前至多一条未解决 | 未解决→自行解决／管理解决／随交易终止 |
| DisputeResolutionConfirmation | 双方各自确认争议已解决 | TradeDispute 1:N，每方至多一条 | 提交即历史，不可改 |
| TradeConfirmation | 双方各自的完成声明；区分当前标记与历史 | Trade 1:N，每方当前至多一条 | 提交即历史；完成／终止保留当前，变更生效、争议解决、未结束恢复清空当前标记 |
| ConfirmationWait | 单方确认后的 7 天等待计时；支持暂停与续算 | Trade 1:1 | 未启动→计时中→暂停→结束 |
| TradeFreeze | 处置、封禁、超时产生的冻结事实及来源 | Trade 1:N，可多条并存 | 生效→解除；结束交易自动解除本笔冻结 |
| TradeStateHistory | 请求结果、状态、阶段、约定、确认、取消、争议、冻结、管理调整的追加历史 | Trade 1:N | 只增不改 |
| Review | 交易完成后的互评及违规处理 | Trade 1:N，每方至多一条 | 提交→可见／被管理员移除 |

### 字段定义

类型约定：`EntityId` 数据库为 bigint、接口为十进制字符串；金额为整数分；时间为 UTC `timestamptz`；枚举为具名字符串；`business_event_id` 为 UUID（生成后不再变化）；JSON 仅用于快照和展示参数，不用于状态字段。

#### Trade

| 字段 | 类型 | 必填 | 约束与说明 |
|---|---|---|---|
| id | bigint | 是 | 主键 |
| product_id | bigint | 是 | 关联商品；不级联删除 |
| buyer_id | bigint | 是 | 请求发起人；与 seller_id 不同 |
| seller_id | bigint | 是 | 商品卖方；与 buyer_id 不同 |
| status | enum | 是 | `pending_acceptance`／`rejected`／`withdrawn`／`closed`／`in_progress`／`disputed`／`abnormal`／`terminated`／`completed` |
| request_note | varchar(500) | 否 | 请求说明，可为空 |
| active_agreement_id | bigint | 否 | 当前有效约定；必须属于本交易且状态为生效 |
| version | integer | 是 | 乐观版本，每次状态／约定／确认变化加一；接口返回 |
| close_reason | enum | 否 | `other_user_locked`／`product_delisted`／`public_access_revoked`／`account_banned`；仅 `closed` 使用 |
| terminal_reason | enum | 否 | `completed`／`cancelled`／`admin_terminated`；仅 `completed`／`terminated` 使用 |
| requested_at | timestamptz | 是 | 请求提交时间 |
| responded_at | timestamptz | 否 | 接受／拒绝／撤回／关闭时间；接受后即受理时间 |
| ended_at | timestamptz | 否 | 完成／终止时间 |
| created_at | timestamptz | 是 | 记录创建 |
| updated_at | timestamptz | 是 | 最后更新 |

约束：

- `buyer_id <> seller_id`。
- 同一商品同买方至多一条待接受请求：`unique (product_id, buyer_id) where status = 'pending_acceptance'`。
- 同一商品至多一笔有效交易：`unique (product_id) where status in ('in_progress','disputed','abnormal')`。
- 已完成／已终止为终态；已拒绝／已撤回／已关闭同样不再推进，可另发新请求。状态、约定、确认、冻结、会话归档均不再由普通写入改变。
- `close_reason` 仅 `status = 'closed'`；`terminal_reason` 仅终态。
- 交易会话不在此保存第二份 `trade_conversation_id`：R2a 的 `TradeConversation.trade_id` 非空唯一，通过关联读取。
- 索引：`(buyer_id, status, requested_at desc)`、`(seller_id, status, requested_at desc)`、`(status, updated_at)`、`(product_id, status)`。

阶段由方法派生，不设 `phase` 列：

- `Trade.phase()`：`status in ('in_progress','disputed','abnormal')` 且 `active_agreement_id` 为空 → `first_agreement_pending`；非空 → `awaiting_completion`；终态返回空。
- 方法读取当前状态与有效约定，供界面和转换使用。

### 关系与唯一约束汇总

| 关系 | 重数 | 约束 |
|---|---|---|
| 商品—交易 | 1:N | 同时至多一笔有效交易；历史多笔保留 |
| 买方／卖方—交易 | 1:N | 双方不同账户；参与方可读本人记录 |
| 交易—快照 | 1:1 | 接受请求时创建，不可变 |
| 交易—约定 | 1:N | 同时至多一条生效；版本号唯一 |
| 约定—决定 | 1:1 | 决定不可变 |
| 交易—取消申请 | 1:N | 同时至多一条待决 |
| 取消申请—决定 | 1:1 | 决定不可变 |
| 交易—争议 | 1:N | 同时至多一条未解决 |
| 争议—解决确认 | 1:N | 每方至多一条；self 解决须两条 |
| 交易—完成确认 | 1:N | 每方当前至多一条；历史保留 |
| 交易—计时 | 1:1 | 一笔一条 |
| 交易—冻结 | 1:N | 可多条并存；任一有效即冻结 |
| 交易—状态历史 | 1:N | 追加写 |
| 交易—评价 | 1:N | 每方每笔至多一条 |
| 交易—会话 | 1:1 | R2a 以 `trade_id` 非空唯一，不在本表复制参与方 |

### 状态、阶段与标记

| 状态 | 含义 | 是否占用商品 | 可执行的主要动作 |
|---|---|---|---|
| pending_acceptance | 待卖方接受 | 否 | 接受、拒绝、撤回、因下架／封禁关闭 |
| in_progress | 进行中 | 是 | 约定、确认、取消、争议 |
| disputed | 有争议 | 是 | 解决恢复、双方同意终止；普通确认禁止 |
| abnormal | 异常交易 | 是 | 管理处置、恢复进行中；解除冻结不恢复状态、不自动完成 |
| completed | 已完成 | 否 | 查看、评价；终态 |
| terminated | 已终止 | 否 | 查看；终态 |
| rejected／withdrawn／closed | 请求结束 | 否 | 查看；可另发新请求 |

- **阶段**由 `Trade.phase()` 从 `status` 与 `active_agreement_id` 派生，不存字段：进行中且无生效约定为首约待确认；有生效约定为约定已确认待完成；有争议／异常保留进入前阶段；终态无阶段。
- **标记**独立于状态：当前完成确认（`TradeConfirmation.invalidated_at is null`）、等待计时（`ConfirmationWait.ended_at is null`）、有效冻结（`TradeFreeze.ended_at is null`）、未解决争议（`TradeDispute.status = 'open'`）。
- 终态不可恢复、不可改写；终态变更请求由 `Trade.require_transition` 返回 `TRADE_TERMINAL`（409），本次事务不改变交易、商品、会话或限制。
- 未结束交易（有争议／异常）的管理恢复只回到进行中；恢复不重新取得占用、不重开会话、不启动计时。

### 业务记录 ID、business_event_id 与系统消息引用

`business_event_id` 由交易用例在业务事务内生成 UUID，随业务记录保存；同一业务事件的系统消息、通知 intent_key 与持久事件共同引用该值。系统消息按 `business_event_id` 唯一；同一动作产生多个子事件时分别生成，按业务因果分配消息序号。

| 事件类型 | source_ref 类型 | 记录及 ID | 事件标识来源 | 访问范围 |
|---|---|---|---|---|
| request_created／request_accepted／request_rejected／request_withdrawn／request_closed | 空 | 所属交易；由会话外键定位 | `TradeStateHistory.business_event_id` | 交易双方 |
| agreement_proposed／agreement_change_proposed | agreement_proposal | `AgreementVersion.id` | `AgreementVersion.business_event_id` | 交易双方 |
| agreement_confirmed／agreement_rejected | agreement_decision | `AgreementDecision.id` | `AgreementDecision.business_event_id` | 交易双方 |
| completion_confirmed | completion_confirmation | `TradeConfirmation.id` | `TradeConfirmation.business_event_id` | 交易双方 |
| cancellation_requested | cancellation_request | `CancellationProposal.id` | `CancellationProposal.business_event_id` | 交易双方 |
| cancellation_accepted／cancellation_rejected／cancellation_withdrawn | cancellation_decision | `CancellationDecision.id` | `CancellationDecision.business_event_id` | 交易双方 |
| dispute_opened／dispute_resolved／trade_frozen／trade_unfrozen／trade_abnormal／trade_completed／trade_terminated／trade_restored | trade_transition | `TradeStateHistory.id` | `TradeStateHistory.business_event_id` | 交易双方；管理路径附事项依据 |

- 历史消息引用当时的不可变记录；提案／确认／决定记录不因后续当前状态变化改写。`TradeConfirmation` 当前标记清空只改失效字段，原记录与 `business_event_id` 保留。
- 服务端校验 `source_ref` 记录属于当前 `trade_id`；其他交易的记录整体拒绝。历史引用不改为当前提案或当前确认。
- 交易历史、系统消息、通知、审计、幂等结果及持久事件同事务提交；同一 `business_event_id` 的系统消息与同一事件的通知 intent_key 去重。
- 管理员通过认领事项读取必要范围；不因系统消息发给双方而获得整段交易历史权限。

## 规则调用边界

- `Trade.require_transition(target_status, context)` 统一校验来源与目标状态、终态及操作资格；已完成／已终止的变更返回 `TRADE_TERMINAL`。
- `Trade.phase()` 从状态与 `active_agreement_id` 派生阶段，不写列。
- 商品占用按 R0 的取得／释放能力执行，交易不直接写商品表。
- 交易会话按 R2a 的 `ensure_trade_conversation`、`append_trade_system_event`、`archive_trade_conversation` 调用；交易只保存关联事实。

补充规则：

- T2-13 仅用于另一方尚无当前确认；若另一方已有当前确认，该提交按 T2-14 处理，不启动计时。
- T2-11 变更生效后不自动计时；任一方重新提交完成确认才开始完整 7 天。
- T2-22 进入争议结束原未回应计时，但不清空当前确认；T2-23／T2-24 恢复时才清空。
- T2-25 的 7 天按 `ConfirmationWait.accumulated_seconds` 与 `active_since` 计算，冻结期间不累计。
- T2-26 冻结不改变状态、不释放占用、不归档会话；仅阻断交易操作与双方两类 IM。
- T2-27 对异常交易只解除冻结，不改变状态、不续算；恢复进行中按 T2-29。
- T2-28 只把非终态调整为已完成／已终止，不作为恢复进行中的入口；终态不可作为来源再次调整，终态变更返回 `TRADE_TERMINAL`；结束态统一释放占用、解除本笔冻结、归档会话。未结束交易恢复按 T2-29 处理，保持原占用。
- T2-29 只适用于异常交易，不重新取得占用、不重开会话、不解除冻结、不启动计时；恢复后任一方重新提交完成确认，才重新开始完整等待。有争议恢复按 T2-23／T2-24。
- T2-23／T2-24 恢复进行中不解除已有冻结；解除冻结仅按 T2-27。
- 交易终止时，未解决争议记录置 `terminated`；管理员完成／终止同样处理。

### 计时规则

| 项目 | 规则 |
|---|---|
| 阈值 | 7 天，配置项 `trade.confirmation_wait_seconds`，启动时复制到 `ConfirmationWait.wait_seconds` 与 `policy_version` |
| 启动 | 首方在“约定已确认待完成”提交当前确认且另一方无当前确认时启动 |
| 暂停 | 任一有效 `TradeFreeze` 生效时暂停；把当前 `active_since` 区间计入 `accumulated_seconds` 并置空，不另存暂停时间字段 |
| 续算 | 仅解除最后一个有效冻结、原当前确认仍有效、且无变更／争议／终止事件时续算剩余时间 |
| 结束 | 第二方确认完成、变更生效、进入争议、终止、超时、争议解决或异常恢复时结束；结束后不再计时 |
| 恢复 | 争议解决、异常恢复不启动计时；任一方重新提交完成确认后启动完整 7 天 |
| 超时 | 后台扫描使用数据库时钟；达到阈值后转异常并冻结；不自动完成、不自动取消 |
| 幂等 | 同一确认重复提交按当前确认唯一约束与接口幂等处理；不重复启动计时 |

## 跨主体调用顺序与原子范围（T4）

采用 R0 0.1.2、R2a（PR #43）、R2b 0.1.3、C1 0.1.2、C3 0.1.1。交易用例持同一 `tx` 与执行上下文；R0／R2a／R2b 不自行提交。

### 接受请求

1. 锁定买方、卖方账户资格并重读；幂等占位。
2. 锁商品行，读取 `ProductStateView`，重读生命周期、`Product.has_valid_review(audits)`、展示限制、`occupancy_trade_id`。
3. 调用 `Product.require_acquire_occupancy(context, audits, restrictions) -> Allowed`；失败返回 `PRODUCT_NOT_AVAILABLE`／`OCCUPANCY_CONFLICT`。
4. 锁本交易及同商品其他待接受请求；按交易 ID 升序收集、排序。
5. 调用 R0 取得占用（product_id、trade_id）；交易置进行中；写受理快照。
6. 读取本交易既有 `TradeConversation`（trade_id 唯一）；接受不新建，缺失按数据不一致失败。
7. 关闭其他待接受请求；逐条写请求结果、`request_closed` 系统消息及通知意图。
8. 生成接受事件 `business_event_id`；`append_trade_system_event` 写 `request_accepted`。
9. 写状态历史、幂等结果、通知意图；提交；提交后投递。

### 完成／终止

1. 锁定账户资格与幂等占位。
2. 锁商品行，重读占用。
3. 锁交易行；`Trade.require_transition` 校验目标状态与终态。
4. 锁交易会话；调用 R0 释放占用（product_id、trade_id、结束依据），商品默认下架；结束计时；保留双方当前确认；解除本笔交易全部冻结；未解决争议置 `terminated`。
5. 生成终态 `business_event_id`；先写最后业务消息，再 `archive_trade_conversation`。
6. 写状态历史、通知意图、幂等结果；提交；提交后投递。
7. 终态后的再次调整返回 `TRADE_TERMINAL`，不改变交易、商品、会话或限制。

### 争议／异常恢复

1. 有争议由 T2-23／T2-24 解决；异常由 T2-29 恢复；终态直接返回 `TRADE_TERMINAL`。
2. 锁交易、事项；校验认领管理员、事项依据；不重新取得占用。
3. 锁交易会话；不重开、不新建；争议解决由双方各写一条解决确认历史并写 `dispute_resolved`，异常恢复写 `trade_restored`，均追加系统消息。
4. 争议解决清空双方当前确认、结束原计时；异常恢复清空当前确认；两条路径都不启动计时。
5. 不解除已有冻结；解除冻结单独走 R2b 与 T2-27。

### 管理调整

- 管理员只把非终态调整为已完成／已终止；完成／终止按上述结束顺序释放、归档。
- 不伪造双方确认；保留现有当前确认；写 `trade_completed`／`trade_terminated` 历史与系统消息。
- 不支持终态恢复到进行中，也不支持旧交易重新取得占用。

### 调用契约与事务位置

| 动作 | 调用 | 事务位置 |
|---|---|---|
| 校验接受资格 | `Product.require_acquire_occupancy` | 商品行锁后、交易锁前 |
| 取得占用 | R0 取得占用（product_id、trade_id） | 接受事务内 |
| 写快照 | 交易域插入 `TradeItemSnapshot` | 接受事务内 |
| 创建会话 | `ensure_trade_conversation` | 请求创建事务内；接受只读既有 |
| 追加系统消息 | `append_trade_system_event` | 业务记录写入后、归档前 |
| 归档会话 | `archive_trade_conversation` | 终态消息后、提交前 |
| 释放占用 | R0 释放占用（product_id、trade_id、结束依据） | 结束事务内 |
| 冻结／解冻 | R2b 处置请求 + `TradeFreeze` | 交易锁、事项锁后；会话锁前 |

### 原子与失败

- 业务状态、约定与决定、确认、计时、冻结、历史与系统事件、幂等结果、会话创建／归档与通知意图同事务提交；任一步持久化失败整体回滚。
- R0 失败映射为 `PRODUCT_NOT_AVAILABLE`、`OCCUPANCY_CONFLICT`、`OCCUPANCY_NOT_HELD`、`STATE_CONFLICT`。
- R2a 创建／归档失败映射为 `TRADE_CONVERSATION_CREATE_FAILED`、`TRADE_CONVERSATION_NOT_FOUND`，整体回滚。
- 通知投递失败发生在提交后，由 C2 恢复，不回滚业务；系统消息按 `business_event_id` 唯一，通知按同一事件与接收账户去重。

## 锁顺序与事务边界

按 C1 公共顺序：账户资格锁（账户 ID 升序、最强模式）→ 幂等占位 → 商品行锁（商品 ID 升序，锁后重读状态与占用）→ 交易行锁（受影响交易 ID 升序）→ 事项行锁（ID 升序）→ 会话子域（ChatConversation → TradeConversation → CaseConversation → 消息 → 阅读进度 → 文件登记 → 文件引用）→ 通知事件序号。

| 用例 | 锁集合 | 事务内变化 | 事务外 |
|---|---|---|---|
| 接受请求 | 买卖双方资格；商品；本交易及其他同商品待接受请求 | 取得占用、交易进行中、关闭其他请求、快照、会话、历史与系统事件、通知意图 | 通知投递、实时事件 |
| 拒绝／撤回 | 双方资格；本交易；会话 | 请求结束、归档会话、历史与事件、通知意图 | 投递 |
| 首次约定／变更 | 双方资格；本交易；约定与决定；会话／消息 | 新增／生效／拒绝、当前确认、计时、历史与事件、通知 | 投递 |
| 完成确认 | 双方资格；本交易；确认与计时；会话 | 当前确认、完成、释放占用、商品状态、解除冻结、归档、历史与事件、通知 | 投递 |
| 取消 | 双方资格；本交易；取消申请与决定；商品（生效时）；会话 | 申请／决定、终止、释放、归档、历史与事件、通知 | 投递 |
| 争议 | 双方资格；本交易；争议；会话／消息；事项（管理路径） | 争议状态、计时结束、当前确认清空（解决时）、历史与事件、通知 | 事项与通知 |
| 超时 | 系统资格；交易；计时；商品；会话 | 异常、冻结、计时结束、管理事项、历史与事件、通知 | 事项创建与投递 |
| 冻结／解冻 | 管理员资格或系统；交易；冻结；计时；会话／消息 | 冻结记录、暂停／续算、历史与事件、通知 | 投递 |
| 管理调整／恢复 | 管理员资格；事项；交易；商品（结束）；会话 | 目标状态、占用、归档、确认、计时、历史与事件、通知 | 投递 |
| 评价 | 评价者资格；交易；评价 | 唯一评价、历史 | 无 |

原子范围：业务状态、约定与决定、确认、计时、冻结、历史与系统事件、幂等结果、会话创建／归档与通知意图在同一事务提交；任一步失败整体回滚。其他待接受请求已结束时按幂等跳过；通知投递失败发生在提交后，由 C2 恢复，不回滚业务。

## 超时、重试与异常恢复

- 超时扫描按配置周期执行，逐笔锁定交易、重读状态与计时；仅“进行中、仅一方当前确认、无争议、无有效冻结、累计达阈值”时转异常。
- 冻结暂停／续算以 `TradeFreeze.ended_at is null` 的有效集合为准；多笔冻结须全部解除才续算。
- 死锁、序列化失败、LockPlanChanged 按 C1 有限重试；业务状态冲突不重试，返回稳定错误。
- 会话创建／归档失败整体回滚；通知意图持久化后投递失败由 C2 恢复，不回滚业务。
- 已完成／已终止保持终态；终态变更返回 `TRADE_TERMINAL`，不改变任何对象。
- 争议解决与异常恢复只回进行中，保持原占用、不重开会话、不启动计时。

## 规则版本

- 等待阈值、分页、文本长度上限由配置提供；等待启动时复制 `wait_seconds` 与 `policy_version`，后续配置变化不改变已启动计时。
- 状态、阶段、原因枚举作为稳定业务词汇；新增枚举走变更记录。
- 约定金额、评分范围、快照字段长度为数据库约束与接口校验共同表达。

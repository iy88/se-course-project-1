# 处置与主体协同

设计归属：TASK-004；编写：张新悦（`sourmoon-peekaboo`）。输入：design 提交 `453f4f4`；需求提交 `ff491a6`。第 4 批按 R0、R1、R2a、C1、C3 的评审版本绑定执行入口与主体能力。本稿定义 R2b 的处置执行请求，事项主体、动作流水与证据引用见[事项主体与处置执行](事项主体与处置执行.md)，事项线程与消息字段见[会话与处置事项](会话与处置事项.md)。

## 关联需求、决策与接口

- 需求：FR-08 处置与解除、FR-14 异常交易处理；BR-08、BR-13、BR-26、BR-32、BR-33；DT-02、DT-03、TR-09、TR-10；第 4 章 4.9、4.10、4.13、4.15、4.17。
- 决策：[ADR-002 主体模块及统一业务数据库](../../decisions/adr/ADR-002-主体模块及统一业务数据库.md)、[ADR-003 统一用例事务与幂等](../../decisions/adr/ADR-003-统一用例事务与幂等.md)、[ADR-009 统一上下文与 AOP 日志审计](../../decisions/adr/ADR-009-统一上下文与AOP日志审计.md)。
- 交界：账户限制由账户模块执行、商品展示与内容由商品模块执行、交易冻结与状态由交易模块执行；本专题定义请求语义与预期结果，各主体在自身文件中维护状态字段、锁集合与转换（[并行对接与交界归属](../04-并行对接与交界归属.md)）。执行请求的调用协议取[公共事务与权限](公共事务与权限.md)，通知按[账户与通知](../interfaces/账户与通知.md)。

## 通用请求与结果

| 项目 | 内容 |
|---|---|
| 请求方 | 事项用例；动作发起人必须是该事项当前认领管理人（`claimed_manager_id`），由事项在调用前校验 |
| 请求字段 | `case_id`、`enforcement_id`（本次执行标识）、`action`、`target_ref`（`resource_type` + `resource_id`）、`basis_ref`（决定与证据引用集合）、`requested_by`、`requested_at`、`expected_result` |
| 前置 | 事项处于 `claimed` 且已有决定；`basis_ref` 非空；目标对象存在且当前状态允许该动作 |
| 成功结果 | 具名结果：`action`、`target_ref`、`result_ref`（目标主体记录标识）、`previous_state`、`current_state`、`affected_scope`（实际受影响对象集合）、`occurred_at` |
| 失败结果 | 具名错误；目标主体不变，整次事务回滚 |
| 重复请求 | 同一 `enforcement_id` 重放返回原结果；同事项同动作同目标已生效时返回既有 `result_ref`，不重复记录限制或重复通知 |
| 事务 | 与事项决定同一用例事务；目标主体写入、事项执行关联、通知意图与审计同次提交；实时与外部副作用在提交后推进 |

`expected_result` 只表达业务预期，不作为目标主体可用性的判断依据：实际可执行性由目标主体在取得锁后按当前状态重新判定，不符即返回具名错误，事项改为记录未执行及原因。

## 账户限制

| 动作 | 目标 | 预期结果 | 具名错误 |
|---|---|---|---|
| `restrict_account` | 账户 ID | 账户模块按来源分别记录限制（类型、原因、依据、执行者、生效时间）；不同来源可同时生效，同一来源重试沿用原限制；用例协调该账户参与的待接受请求按 D-52 关闭并归档对应分支、未结束交易按冻结规则处理、双方通知；实际受影响范围写入 `affected_scope` | `BASIS_REQUIRED`、`OWNERSHIP_MISMATCH` |
| `lift_account_restriction` | 账户 ID、限制记录 ID | 记录解除时间、解除人与依据；按当前资格恢复权限及因该处置停止的展示；其他有效限制保留；不将原非在售商品变为在售 | `RESTRICTION_NOT_ACTIVE`、`BASIS_REQUIRED` |

封禁与解除均须记录执行者、理由及时间（BR-32）。同一账户多次封禁分别成条记录，解除只解除指定记录；剩余有效限制由账户模块按当前资格汇总。

## 商品与评论内容

| 动作 | 目标 | 预期结果 | 具名错误 |
|---|---|---|---|
| `withdraw_public_access` | 商品 ID | 商品停止公开展示但不改变生命周期；该商品待接受请求按 BR-02 关闭并记录原因；相关收藏按失效提示处理；通知卖方 | `TARGET_STATE_CONFLICT`（已撤销公开访问） |
| `remove_content` | 评论 ID 或评价 ID | 逻辑删除违规内容并保留原文、作者、时间与处理依据；不连带撤销无关商品公开访问；通知作者 | `TARGET_STATE_CONFLICT`（已移除）、`CONTENT_NOT_FOUND` |
| `restore_display` | 商品 ID | 仅恢复原展示资格，不重审、不将处置前非在售商品恢复为在售；与商品当前生命周期及交易占用分别判断 | `TARGET_STATE_CONFLICT`（无需恢复） |

撤销公开访问不解除交易锁单，重新上架只适用于已下架状态（4.10）。内容移除涉及交易时，交易冻结与商品撤销公开按同一决定的范围分别执行，二者可同时生效（SC-07-13）。

## 交易与评价

| 动作 | 目标 | 预期结果 | 具名错误 |
|---|---|---|---|
| `freeze_trade` | 交易 ID | 交易模块记录进度暂停标记，暂停双方交易操作与计时、保留当前完成确认与已用等待时间；禁止该对用户之间普通私聊与全部交易分支发送（历史可读），不影响双方与第三方会话；通知双方原因、范围与处置沟通入口 | `TARGET_STATE_CONFLICT`（已结束或已冻结） |
| `lift_trade_freeze` | 交易 ID、冻结依据 | 解除指定冻结；仅当原确认仍有效时续算剩余等待时间；其他有效冻结或账户封禁继续生效 | `TRADE_FREEZE_NOT_ACTIVE` |
| `adjust_trade_status` | 交易 ID、目标状态 | 按 BR-08 有依据调整未结束交易的状态，记录前后状态、执行人、时间与原因；已完成、已终止交易保持终态，不接受恢复；不伪造用户确认；仅恢复未结束交易，保留原占用，解除冻结另行处理 | `TRADE_TERMINAL`（已完成或已终止）、`TRANSITION_NOT_ALLOWED`（未结束交易的转换条件不满足）、`BASIS_REQUIRED` |
| `remove_evaluation_content` | 评价 ID | 逻辑删除违规评价并保留依据；不改变交易结束状态与统计口径 | `TARGET_STATE_CONFLICT` |

冻结不等于交易结束，也不产生分支归档；交易进入已完成或已终止时自动解除本笔冻结并通知（4.15、BR-33）。解除非结束状态冻结须认领管理员有依据处理。

## 事项线程

事项线程的读取与发送由[会话与处置事项](会话与处置事项.md)维护，本专题只确认执行结果对线程的影响：实际处置与冻结、状态调整须通知受影响者并给出处置沟通入口；线程不随交易结束归档，随事项结案归档。买卖双方 IM 的限制由 `freeze_trade` 与 `restrict_account` 的结果表达，不在线程侧另存状态。

## 事务与锁序

| 顺序 | 内容 |
|---|---|
| 1 | 账户资格锁：操作者、目标账户及受影响双方，按账户 ID 升序取所需最强模式 |
| 2 | 幂等占位：操作者＋操作类型＋请求键 |
| 3 | 商品行：目标商品及同商品其他受影响对象，按商品 ID 升序，锁后重读展示与占用 |
| 4 | 交易行：目标交易及同商品其他交易，按 ID 升序；单商品场景在商品锁内确定集合 |
| 5 | 处置事项行：按事项 ID 升序，重查认领与当前状态 |
| 6 | 会话子序：会话 → 分支 → 参与关系 → 消息 → 已读进度 |
| 7 | 用户事件序号：接收账户按 ID 升序分配并保存通知事件 |

执行目标在决定后才扩展时（例如封禁导致该账户其余待接受请求进入范围），按公共重新规划流程整事务重做，不在第 5 级锁内回取第 3、4 级（[公共事务与权限](公共事务与权限.md)）。每个动作列出自身涉及的锁域集合，调用方按本表组织，主体维护自身数据。

## 通知与审计

| 触发 | 接收与内容 |
|---|---|
| 冻结、解冻、状态调整 | 交易双方；原因、实际限制或恢复范围、剩余其他限制及处置沟通入口 |
| 封禁、解除 | 受限账户；原因、范围、恢复结果及沟通入口；D-52 关闭的请求另通知双方 |
| 内容移除、撤销公开访问 | 受影响作者或卖方；原因与可查看入口 |
| 举报处理确认 | 举报人；可公开结论与原因，不披露他人私人消息、申辩内容或管理员信息 |

审计记录动作、目标、前后状态、依据引用、执行者与时间，不记录消息正文与证据内容（ADR-009）。通知意图与业务同事务保存，投递在提交后推进；重复执行不重复发送同一意图（[账户与通知](../interfaces/账户与通知.md)）。

## 幂等与错误

- 幂等作用域为 `(actor_id, operation_name, idempotency_key)`；`enforcement_id` 与事项动作绑定，重试返回原结果（ADR-003）。
- 跨主体具名错误统一为 `TARGET_STATE_CONFLICT`、`TRADE_TERMINAL`、`TRANSITION_NOT_ALLOWED`、`LOCK_CONFLICT`、`RESTRICTION_NOT_ACTIVE`、`TRADE_FREEZE_NOT_ACTIVE`、`CONTENT_NOT_FOUND`、`BASIS_REQUIRED`、`OWNERSHIP_MISMATCH`；HTTP 映射按公共表，主体可补充前缀化业务错误。
- 部分成功不允许：一个决定涉及多个目标时，任一目标校验失败即整次回滚，事项记录未执行及原因，不留下半处置状态。

## 第4批：主体能力绑定

以下按 R0 商品能力、R1 交易触发、R2a 会话模型、C1 公共事务与 C3 文件／通知的评审版本，绑定执行入口、主体能力、锁集合与结果映射。事项用例持同一事务，主体能力只写自身数据、不提交事务（ADR-003）。

### 执行入口

```text
execute_enforcement(context, operation_name, idempotency_key, request) -> OperationResult[EnforcementResult]
```

| 项目 | 内容 |
|---|---|
| request 字段 | `case_id`、`enforcement_id`、`action`、`target`（ResourceRef）、`basis_ref`、`reason_text`、`expected_result`、`occurred_at` |
| operation_name | `case.enforcement.<action>`，逐动作登记；与幂等作用域 `(actor_id, operation_name, idempotency_key)` 一致 |
| idempotency_key | 取 `enforcement_id`；同一事项内由其与 `case_id` 组成数据库唯一约束 |
| 入口组织 | C1 `run_write`；prepare 只读收集目标对象与账户标识，资格与状态在写事务取得锁后重查 |
| 成功结果 | `EnforcementResult`：`action`、`target`、`result_ref`、`previous_state`、`current_state`、`affected_scope`、`occurred_at` |
| 复用 | 同一 `enforcement_id` 重放 C1 已保存的 `OperationResult`；摘要不一致返回 `IDEMPOTENCY_PAYLOAD_CONFLICT` |

### 动作与主体能力

| action | 目标读取 | 主体能力 | 成功与幂等结果 | 具名错误 |
|---|---|---|---|---|
| `restrict_account` | `AccountQualifications`（目标账户）；该卖方 `ProductStateView` 集合；该账户参与的未结束交易与待接受请求 | 账户侧按来源保存限制记录（账户契约 C4 登记）；不同来源可叠加；`Product` 对该卖方全部未删除商品应用展示限制（`source_type=账户封禁`、`source_ref=限制标识`）；R1 关闭待接受请求并按冻结规则处理未结束交易；R2a `archive_trade_conversation` 归档被关闭请求的分支 | 限制标识；`RESTRICTION_APPLIED`，同一执行重试重放原结果；同来源已生效时沿用原限制 | `BASIS_REQUIRED`、`OWNERSHIP_MISMATCH` |
| `lift_account_restriction` | 限制记录及其来源商品集合 | 账户侧记录解除；`Product` 按同一来源标识解除展示限制 | `RESTRICTION_RELEASED`，重复解除取 `RESTRICTION_NOT_ACTIVE` 的既有结果 | `RESTRICTION_NOT_ACTIVE`、`BASIS_REQUIRED` |
| `withdraw_public_access` | `ProductStateView` | `Product` 应用展示限制（`source_type=管理撤销公开`、`source_ref=决定引用`）；R1 关闭该商品待接受请求；C3 `create_notifications` | `RESTRICTION_APPLIED`；`affected_scope` 含受影响待接受请求 | `TARGET_STATE_CONFLICT`、`RESOURCE_NOT_VISIBLE` |
| `restore_display` | `ProductStateView.display_restrictions` | `Product` 解除管理撤销公开来源的展示限制，重新计算可见性 | `RESTRICTION_RELEASED` | `RESTRICTION_NOT_ACTIVE`、`RESOURCE_NOT_VISIBLE` |
| `remove_content` | 评论记录（商品）／评价记录（交易） | 商品侧按管理员移除写入 `removed_at`、`removed_by_admin_id`、`removed_reason`、`basis_ref`；评价由 TASK-003 评价能力逻辑删除 | 留存记录标识；原文、作者与时间保留 | `CONTENT_NOT_FOUND`、`TARGET_STATE_CONFLICT` |
| `freeze_trade` | 交易记录及 `trade_transition` 历史 | 交易侧写冻结事实；R2a `append_trade_system_event` 追加 `trade_frozen`；C3 `create_notifications` | `trade_transition` 标识；会话不归档 | `TARGET_STATE_CONFLICT`（已结束或已冻结） |
| `lift_trade_freeze` | 生效冻结记录 | 交易侧写解除事实；追加 `trade_unfrozen`；通知双方 | `trade_transition` 标识；其他有效冻结与账户封禁保留 | `TRADE_FREEZE_NOT_ACTIVE` |
| `adjust_trade_status` | 交易记录与 `Trade.require_transition(target, context)` | 交易侧按目标状态校验转换；结束目标时 `Product` 按结束依据释放占用并转已下架，R2a 在写入终态后归档会话；追加 `trade_adjusted`／`trade_terminated` | 前后状态与 `trade_transition` 标识；终态交易返回 `TRADE_TERMINAL` | `TRADE_TERMINAL`、`TRANSITION_NOT_ALLOWED`、`BASIS_REQUIRED` |
| `remove_evaluation_content` | 评价记录 | 交易侧评价逻辑删除并保留依据；不改写交易结束状态与统计口径 | 留存记录标识 | `TARGET_STATE_CONFLICT` |

各动作在取得锁后重读目标事实：商品按 `ProductStateView` 的 `lifecycle_state`、`occupancy_trade_id`、`display_restrictions`；交易按 R1 的当前状态、冻结记录与占用归属；账户按资格锁后读取的 `AccountQualifications`。`expected_result` 只登记业务预期，不作为跳过重读的依据。

### 系统消息与分支归档

处置执行不建立新会话，也不写入消息正文；交易侧事实变化按 R2a 的事件类型追加系统消息。

| 执行动作 | 系统消息 `event_type` | `source_ref` | 归档 |
|---|---|---|---|
| `freeze_trade` | `trade_frozen` | `trade_transition` + 本次变更 ID | 不归档 |
| `lift_trade_freeze` | `trade_unfrozen` | `trade_transition` + 本次变更 ID | 不归档 |
| `adjust_trade_status`（非终态） | `trade_adjusted` | `trade_transition` + 本次变更 ID | 不归档 |
| `adjust_trade_status`（终止） | `trade_terminated` | `trade_transition` + 本次变更 ID | 写入终态后归档 |
| 事项结案 | 不产生交易消息 | — | `archive_case_conversation` |

冻结、解冻与状态调整都不重开已归档会话、不迁移消息、不新建第二条交易会话。买卖双方的普通私聊与交易消息限制由 R2a 的 `require_send` 按双方账户资格与二人冻结计算，执行请求不另存会话状态。事实变化向事项相关方告知时调用 `append_case_message`（`message_kind=system_notice`），事件标识沿用事项事件。

### 通知意图

通知按 C3 `create_notifications` 与业务同事务提交；`intent_key` 由动作、执行标识与通知种类构成，同次执行重试保持一致。

| 执行动作 | `event_type` | 接收账户 | `intent_key` 组成 |
|---|---|---|---|
| `restrict_account` | `case.account_restricted` | 目标账户 | `{enforcement_id}:restricted` |
| `lift_account_restriction` | `case.account_restriction_lifted` | 目标账户 | `{enforcement_id}:lifted` |
| `withdraw_public_access` | `case.display_withdrawn` | 卖方 | `{enforcement_id}:withdrawn` |
| `restore_display` | `case.display_restored` | 卖方 | `{enforcement_id}:restored` |
| `remove_content` | `case.content_removed` | 内容作者 | `{enforcement_id}:removed` |
| `remove_evaluation_content` | `case.evaluation_removed` | 评价作者 | `{enforcement_id}:evaluated` |
| `freeze_trade` | `case.trade_frozen` | 交易双方 | `{enforcement_id}:frozen` |
| `lift_trade_freeze` | `case.trade_unfrozen` | 交易双方 | `{enforcement_id}:unfrozen` |
| `adjust_trade_status` | `case.trade_adjusted` | 交易双方 | `{enforcement_id}:adjusted` |
| 决定与执行结果告知举报人 | `case.result_published` | 举报人 | `{decision_id}:published` |

模板标识与版本从 C3 事件登记表取得；`display_params` 只含原因、范围、恢复结果与处置沟通入口，不含消息正文与证据内容。被关闭待接受请求的买方通知由 R1 的关闭动作登记，本动作不重复提交同一 `intent_key`。

### 锁集合与原子范围

| 动作 | 第1级 账户资格 | 第3级 商品 | 第4级 交易 | 第5级 事项 | 第6级 会话子序 | 第7级 事件序号 |
|---|---|---|---|---|---|---|
| `restrict_account` | 目标账户排他、操作者共享 | 该卖方全部未删除商品，按 `product_id` 升序 | 该账户参与的未结束交易，按 ID 升序 | 本事项 | 被关闭请求的交易会话（归档）、事项会话 | 接收账户按 ID 升序 |
| `lift_account_restriction` | 目标账户排他、操作者共享 | 限制来源涉及的商品 | 无 | 本事项 | 事项会话 | 同上 |
| `withdraw_public_access` | 操作者共享 | 目标商品及同商品展示限制行 | 同商品待接受请求涉及交易 | 本事项 | 被关闭请求的交易会话 | 同上 |
| `restore_display` | 操作者共享 | 目标商品及展示限制行 | 无 | 本事项 | 无 | 同上 |
| `remove_content` | 操作者共享 | 商品及评论记录行 | 评价所属交易行 | 本事项 | 无 | 同上 |
| `freeze_trade`／`lift_trade_freeze` | 操作者与交易双方共享 | 无 | 目标交易及同商品其他交易 | 本事项 | 本笔交易会话 | 同上 |
| `adjust_trade_status` | 操作者与交易双方共享 | 结束目标时的目标商品 | 目标交易及同商品其他交易 | 本事项 | 本笔交易会话（终止时归档） | 同上 |
| `remove_evaluation_content` | 操作者共享 | 无 | 评价所属交易行 | 本事项 | 无 | 同上 |

执行目标在决定后才确定时，例如封禁后新增的待关闭请求，按 C1 回滚本次事务并以补充集合整次重规划，不在第 5 级锁内回取第 3、4 级对象。同一决定涉及多个目标时按上表合并集合后一次排序，不逐目标依次跨域回取。

### 证据与审计绑定

- 决定与执行依据取事项的证据引用记录；`basis_ref` 指向该组引用，非空是执行前置条件。
- 证据文件按 C3 `attach_files`（`purpose=case_evidence`、`target` 为事项）建立引用，写入与主体变化同事务，第 6 级文件子序按 `file_id` 升序。
- 审计按 C1 `record_audit` 记录动作、目标、前后状态、依据引用、执行者与时间；不记录消息正文与证据内容。

## 验证场景与测试关联

设计阶段按下列预期核对请求语义与事务边界，TC 编号与运行条件随第 5 批登记：

1. 同一决定含交易冻结与商品撤销公开访问：两项在同一事务生效；任一项校验失败时交易、商品、通知均回滚（BR-26、BR-33）。
2. 封禁执行时该账户存在待接受请求与未结束交易：请求按 D-52 关闭并归档分支，交易按冻结规则处理，双方均收到通知（BR-32、DT-03）。
3. 冻结期间双方尝试推进交易或互发消息被拒绝，历史只读，与第三方会话不受影响；解冻且原确认有效时续算剩余等待（BR-33、D-51）。
4. 管理员尝试恢复已完成或已终止的交易时返回 `TRADE_TERMINAL`；同商品存在另一笔锁单交易时，两笔交易、商品占用、会话及限制均保持原状（BR-08）。
5. 解除封禁后恢复原资格，其他有效限制保留，非在售商品不自动上架（BR-32、TR-10）。
6. 同一 `enforcement_id` 重复请求返回原结果，不重复记录限制、不重复通知（ADR-003）。

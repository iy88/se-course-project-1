# 商品与交易协同

设计归属：TASK-003。本文件第一批定义 R1 商品与交易联动的业务契约；商品字段、会话字段、调用签名与锁集合在第 4 批按 R0／R2a／R2b／C1／C3 的评审版本细化。

## 关联需求、决策与接口

- 需求：FR-05（请求、约定、终止与争议）、FR-06（完成确认）、FR-09（商品占用与限制恢复）、FR-14（超时异常与处置）；BR-01—BR-08、BR-14、BR-27—BR-30、BR-32、BR-33；TR-05—TR-19；4.15、4.17。
- 决策：ADR-002（主体模块与统一业务数据库）、ADR-003（统一用例事务与幂等）、ADR-006（分作用域配置与规则版本）、ADR-010（RESTful 契约）。
- 公共输入：[公共事务与权限](公共事务与权限.md)（C1）、[账户与通知](../interfaces/账户与通知.md)（C3）。
- 交界：R0 商品能力由 TASK-002 维护；R2a 会话模型、R2b 处置执行请求由 TASK-004 维护。本文件只定义交易侧触发事实、业务标识、结果语义、通知接收范围与调用责任。

## R1 业务契约

R1 涉及商品占用、请求关闭和交易分支三类联动；请求与交易在同一记录中表达。商品字段、会话字段、调用签名与锁集合由 R0／R2a 及第 4 批适配定义，本文件不重复。

### 术语与边界

- **商品占用**：一笔已接受且未结束的交易对商品的排他锁单关系；同一商品同时至多一笔占用。占用由商品模块保存，交易模块保存持有占用的交易标识。
- **有效交易**：状态为进行中、有争议或异常交易的交易；只有有效交易持有商品占用。已完成／已终止／已拒绝／已撤回／已关闭不持有占用。
- **请求结束**：待接受请求因接受其他请求（转已关闭）、拒绝（转已拒绝）、撤回（转已撤回）、商品生命周期下架、撤销公开访问或相关账户封禁（转已关闭）而结束；按结果与原因记录。
- **交易分支**：每笔有效请求／交易唯一对应的会话分支；请求被判拒绝、撤回、关闭或交易结束时归档。
- 具体字段、调用签名、锁集合和会话消息结构在第 4 批细化；管理事项状态机由 TASK-004 定义；本文件只定义 R1 的业务事实、结果和通知范围。

### 能力契约

R1 包含以下五项能力，触发、结果、事务位置和通知范围一并列明。

| 能力 | 触发事实 | 调用方 → 维护方 | 业务标识 | 前置与状态重读 | 成功结果 | 具名失败／冲突 | 事务与锁位置 | 通知与幂等 |
|---|---|---|---|---|---|---|---|---|
| 取得商品占用 | 卖方接受一条待接受请求 | 交易用例 → 商品模块（R0） | product_id、trade_id、actor_account_id | 商品公开可交易且无其他有效占用；请求为待接受；锁商品后重读状态与占用 | 商品交易中，占用持有者为 trade_id | OCCUPANCY_CONFLICT；PRODUCT_NOT_AVAILABLE；REQUEST_ALREADY_ENDED（请求已拒绝／撤回／关闭） | 同一事务；账户资格锁 → 幂等占位 → 商品行锁 → 重读 → 交易行锁；商品先锁、状态重读 | 通知请求买方接受结果；被关闭请求的买方关闭原因；以接受动作幂等键定位 |
| 释放商品占用 | 交易完成、有效取消／协商终止、管理调整结束 | 交易用例 → 商品模块（R0） | product_id、trade_id、结束依据 | 占用持有者必须等于 trade_id；锁商品后重读占用；商品按结束规则置默认下架；卖方是否继续上架另行处理 | 占用解除；商品按结束规则置默认下架；继续上架由卖方另行选择，不在本能力内 | OCCUPANCY_NOT_HELD；STATE_CONFLICT（版本变化） | 同一事务；账户资格锁 → 幂等占位 → 商品行锁 → 交易行锁；释放与交易终态同一提交 | 通知双方结束结果与商品上架结果；完成时的评价入口由 T1 提供；以结束动作幂等键定位 |
| 关闭待接受请求（非拒绝／撤回） | 接受一条请求（关闭同商品其他待接受请求）；商品生命周期下架；撤销公开访问；相关账户封禁；管理处置撤销公开 | 交易用例 → 交易模块（本域） | product_id、trade_id（被关闭请求）、原因码、触发来源 | 请求必须为待接受；接受场景下同商品其他待接受请求一并关闭；原因与实际触发一致 | 请求转已关闭，原因记为其他用户锁单／商品已下架／公开访问已撤销／相关账户被封禁；不计失败交易 | REQUEST_ALREADY_ENDED；STATE_CONFLICT | 同一事务；随接受或关闭动作在同一交易锁集合内完成；逐请求按 ID 升序 | 通知每个被关闭请求的买方；封禁场景同时通知双方；由业务动作触发，不单独接受客户端幂等键 |
| 创建交易分支 | 有效购买请求创建成功（BR-01） | 交易用例 → 会话模块（R2a） | trade_id、product_id、buyer_id、seller_id、branch_id | 同一事务已写入待接受记录；同一 trade_id 无分支时创建，已有分支返回原分支并由入口打开，不重复创建；分支创建失败不得留下无分支请求 | 返回唯一 branch_id；已有分支返回原分支；分支与系统消息同事务写入；交易保存标识 | BRANCH_CREATE_FAILED | 同一事务；交易记录写入后调用；分支创建在会话子域锁内；失败整体回滚 | 通知卖方新请求；系统消息定位请求与分支；按 trade_id 唯一，重试返回已有 branch_id |
| 归档交易分支 | 请求拒绝／撤回／关闭；交易完成／终止；管理调整结束 | 交易用例 → 会话模块（R2a） | trade_id、branch_id、结束原因 | 分支存在；归档幂等，重复调用返回既有结果；归档不删除消息、已读和历史 | 分支只读；历史保留；不自动重开；普通私聊不受影响；冻结不归档 | BRANCH_NOT_FOUND | 同一事务；在请求或交易结束写入后调用；会话子域锁内；失败整体回滚 | 归档本身不通知；结束动作按通知表通知对方、受影响买方或双方；按 branch_id 唯一，重复归档返回既有结果 |

拒绝、撤回是独立请求动作，分别转已拒绝、已撤回，不经过“关闭待接受请求”能力；已拒绝、已撤回、已关闭均不计失败交易。

### 动作触发矩阵

| 业务动作 | 商品占用 | 请求结果 | 交易分支 | 通知 |
|---|---|---|---|---|
| 提交购买请求 | 不变 | 不关闭 | 创建该笔分支 | 卖方：新请求；关联商品、请求、发起人及时间 |
| 接受请求 | 取得 | 同商品其他待接受请求全部关闭 | 保持 | 请求买方：已接受；被关闭请求的买方：关闭及原因 |
| 拒绝请求 | 不变 | 本请求结束（已拒绝） | 归档 | 请求买方：已拒绝及原因 |
| 买方撤回 | 不变 | 本请求结束（已撤回） | 归档 | 卖方：已撤回；买方获即时反馈 |
| 下架／撤销公开／账户封禁导致关闭 | 待接受请求不占用，不释放；已有有效交易占用保持，按冻结／处置处理 | 仅关闭相关待接受请求；进行中交易不转已关闭、不终止 | 仅归档被关闭请求的分支；有效交易分支不归档 | 下架／撤销公开：受影响买方；账户封禁：双方；注明实际原因 |
| 双方完成确认 | 释放 | 不变 | 归档 | 双方：完成、商品上架结果、评价入口 |
| 首约前买方直接取消 | 释放 | 不变 | 归档 | 双方：已终止及原因 |
| 卖方申请取消／约定后协商取消 | 生效后释放 | 不变 | 生效后归档 | 待同意方：申请；生效后双方：已终止 |
| 取消申请拒绝／撤回 | 不变 | 不变 | 不归档 | 拒绝时通知提案方；撤回时通知对方；交易继续 |
| 发起争议 | 保持 | 不变 | 不归档 | 详情显示有争议；不新增用户通知；管理事项由 R2b 处理 |
| 争议解决恢复进行中 | 保持（继续锁单） | 不变 | 保持原状；不归档、不重开 | 自行解决：详情可见、不另发；管理解决按 4.17 管理调整通知双方 |
| 争议中双方同意终止 | 释放 | 不变 | 归档 | 双方：已终止及原因；争议记录保留 |
| 单方确认超时转异常 | 保持（不释放，异常仍锁单） | 不关闭 | 不归档（冻结不归档） | 双方：异常、冻结、暂停上架及交易操作、禁止双方 IM、管理沟通入口、剩余其他限制 |
| 处置／封禁冻结 | 保持 | 不关闭（待接受请求按封禁另关） | 不归档 | 双方：冻结原因、限制范围、沟通入口 |
| 解冻 | 保持 | 不变 | 不归档 | 双方：解除及剩余限制 |
| 管理调整结束 | 释放 | 不变 | 归档 | 双方：前后状态、原因、剩余限制 |
| 管理恢复进行中（异常／争议） | 保持（继续锁单） | 保持已接受（不回退待接受） | 不重开原分支 | 双方：恢复及依据 |
| 旧交易恢复为进行中 | 重新取得（须无其他锁单且商品可取得占用；否则拒绝） | 保持已接受（不回退待接受） | 不重开原分支 | 双方：恢复及依据 |

管理恢复与旧交易恢复不启动等待计时；恢复后任一方重新提交完成确认，才重新开始完整等待。

### 结果语义

| 结果 | 语义 | 使用场景 |
|---|---|---|
| OCCUPANCY_ACQUIRED | 占用取得成功 | 接受请求 |
| OCCUPANCY_RELEASED | 占用释放成功 | 完成、终止、管理调整结束 |
| OCCUPANCY_CONFLICT | 同商品已有其他有效占用；本次事务不写入占用、交易或分支（并发失败方的请求状态可能已由成功方接受动作关闭，不属于本次写入） | 并发接受、旧交易恢复 |
| PRODUCT_NOT_AVAILABLE | 商品生命周期或展示资格不允许取得占用 | 接受、旧交易恢复 |
| OCCUPANCY_NOT_HELD | 释放时占用持有者不是本交易 | 释放竞态 |
| REQUEST_CLOSED | 请求按实际原因关闭 | 接受关闭其他请求、下架／撤销公开／封禁关闭 |
| REQUEST_ALREADY_ENDED | 请求已结束（拒绝／撤回／关闭），当前动作不可执行；同键重试由 C1 幂等重放 | 对已结束请求再次操作 |
| BRANCH_CREATED | 分支创建成功，返回唯一 branch_id | 请求创建 |
| BRANCH_REUSED | 已有分支，返回原分支，不重复创建 | 分支已存在时的重复进入（同键重试由 C1 重放） |
| BRANCH_ARCHIVED | 分支归档成功，返回归档结果 | 请求或交易结束 |
| BRANCH_ALREADY_ARCHIVED | 已归档，返回既有结果 | 重复归档／补偿重放（同键重试由 C1 入口重放，不进入本结果） |
| BRANCH_CREATE_FAILED | 会话侧创建失败，业务事务回滚 | 分支创建失败 |
| BRANCH_NOT_FOUND | 分支不存在，无法归档 | 数据不一致或错误调用 |
| RESTORE_BLOCKED_BY_LOCK | 旧交易恢复前发现同商品另有锁单交易 | BR-08／D-48 |

接口层把具名结果映射为稳定错误码与 HTTP 状态；错误码在第 3 批接口文件中登记，不在此重复。

# C5 配置、审计与可观测性

归属TASK-001第5批，输入design `2a7cb17`、ADR-006／009、需求质量与规则版本约定。文件参数采用[PR #46](https://github.com/iy88/se-course-project-1/pull/46)，身份／邮箱采用[PR #47提交2fc423b](https://github.com/iy88/se-course-project-1/tree/2fc423b)，实时／任务采用[PR #48提交46033be](https://github.com/iy88/se-course-project-1/tree/46033be)作为专题评审输入；具体采用值及字段在集成及阶段准入核对。

## 配置加载与发布

后端从显式指定的单份.env加载运行参数，通过类型化Settings建立不可变配置快照；受控加载器仅组合该文件与代码声明默认值，不以业务代码读取os.environ、临时文件或另一配置源补缺。启动检查未知字段、类型、范围、关联、必需凭据引用与所需依赖；失败输出脱敏字段名和原因并停止启动。密码、DSN、密钥和签名内容不输出到配置报告。

每个入口取得同一配置版本及作用域，HTTP／IM／worker／scheduler共享业务规则，实例ID、监听地址等实例参数单独具名；新进程读取发布的快照，不热改已运行对象。配置版本由非秘密有效值及秘密来源版本引用确定，日志只输出版本标识；原始秘密不参与公开报告。滚动期间的新旧期限使用记录保存的快照，各入口在阶段测试检查兼容性。

两个前端分别维护开发服务器、代理、公开API／WS地址、基础路径及构建配置；仅构建公开值进入前端包。输入限制与能力由后端API取得，前端显示与校验不替代后端规则。部署目录／域名及数据库／Redis实际值按用户确定的同机隔离边界，在后续部署阶段配置。

## 分组与当前实现输入

| 配置组／键 | 类型、单位及默认／必填依据 | 范围、关联校验与公开性 | 生效 |
|---|---|---|---|
| APP_ENV／INSTANCE_ID／PROCESS_KIND | 必填具名字符串，kind=api／im／worker／scheduler | 环境与实例唯一标识；进程类型决定所需依赖；仅必要环境标识公开 | 进程启动 |
| HTTP_BIND_HOST／HTTP_BIND_PORT／IM_BIND_HOST／IM_BIND_PORT | 具名地址及1—65535端口，部署提供 | 进程监听无冲突，实例上游从同一输入派生；不公开内部地址 | 重启 |
| DATABASE_URL | 必填PostgreSQL连接，凭据来自后端安全配置 | 业务库名／用户为v2独立资源，共用服务实例；不记录DSN | 重启及连接验证 |
| DB_POOL_SIZE／DB_MAX_OVERFLOW／DB_POOL_TIMEOUT_SECONDS | 正整数或非负溢出，默认5／5／5秒 | pool≥1、overflow≥0、timeout1—60；各进程连接预算总和在部署准备核算 | 重启 |
| DB_LOCK_TIMEOUT_SECONDS／DB_TRANSACTION_TIMEOUT_SECONDS | 正整数秒，默认3／10 | 锁等待小于事务上限，实际I/O不在持锁事务；内部 | 新事务快照 |
| TX_RETRY_LIMIT／TX_RETRY_BASE_MILLISECONDS | 非负次数／正整数毫秒，默认3／50 | 次数0—10，退避10—1000且总预算受请求超时约束；仅C1登记的整事务可重试错误 | 新请求 |
| REDIS_URL／REDIS_NAMESPACE | 必填连接及独立前缀 | 共用实例，前缀覆盖Session／Stream／broker内部键／结果／配额，逻辑DB可选；均内部 | 重启及隔离检查 |
| ALLOWED_ORIGINS／PUBLIC_API_BASE／PUBLIC_WS_BASE | 非空精确Origin集合及HTTPS／WSS公开入口 | Cookie及CSRF作用域匹配，不使用任意通配带凭据跨域；公开地址可进入前端 | 重启／前端构建 |
| LIST_PAGE_SIZE／LIST_PAGE_SIZE_MAX | 正整数，默认20／100 | 1≤默认≤最大≤1000；001能力响应公开 | 新查询 |
| PASSWORD_MIN_LENGTH／PASSWORD_MAX_LENGTH | 正整数字符数，默认12／256，作为初始配置输入 | 8≤最小≤最大≤1024；密码散列库按输入长度及参数显式限制资源；格式限制公开 | 新密码校验，已有散列仍可核对 |
| DISPLAY_NAME_MAX_LENGTH | 正整数字符数，默认64，用户名称输入上限 | 1—256；配合统一内容规则，公开 | 新资料提交 |
| IDEMPOTENCY_KEY_MAX_LENGTH／IDEMPOTENCY_RETENTION_SECONDS | 正整数字符数／秒，默认128／86400 | 键16—512；保留至少覆盖支持的网络重试窗口，关联验证码记录保留及旧摘要密钥版本；内部 | 新记录保存期限 |
| REQUEST_BODY_MAX_BYTES | 正整数字节，默认1048576，JSON入口边界 | 1024—10485760；不套用浏览器OSS直传文件大小；后端与入口代理一致 | 发布及新请求 |
| LOG_LEVEL／LOG_FORMAT | 登记级别及json，默认INFO／json | 调试日志也采用白名单与脱敏；无正文／凭据开关；内部 | 进程启动 |
| LOG_ROTATION／LOG_RETENTION | 部署具名日志策略输入 | 针对运行日志，业务审计与历史保留按需求独立管理；内部 | 后续部署阶段 |

下列专题键以其源文件的类型、单位、范围及默认依据为准，本表登记配置归属和完整性校验，集成后进入统一Settings，不在另一文件维护第二套默认数值：

| 专题配置 | 唯一输入及必校验关系 | 公开／保存依据 |
|---|---|---|
| OSS_ENDPOINT／REGION／BUCKET／CREDENTIALS、FILE_*及OSS_IO_* | PR #46文件协议；私有Bucket且从未开启版本控制，临时保留晚于上传期限，用途允许格式必须有核验器 | 上传用途／大小／格式由文件能力接口公开；旧授权保存规则 |
| SESSION_ABSOLUTE／IDLE／RENEW／CLEANUP／DEPENDENCY_* | PR #47会话专题；续期间隔＜空闲≤绝对期限 | 保存签发快照；Cookie期限受绝对期限约束 |
| EMAIL_CODE_*／RESEND／SEND_*／LEASE／CLEANUP／RECORD_*、SMTP_*、ACCOUNT_ENTRY_* | PR #47邮箱专题；单表明文code、发送租约大于I/O超时、记录及密钥保留覆盖幂等／入口期限 | 仅代码格式／有效期／重发间隔公开；原码及SMTP凭据专用保存 |
| EVENT_*／IM_*／WORK_* | PR #48实时与任务；批次≤窗口、心跳＜空闲、任务租约覆盖I/O预算 | 协议必要限制公开；事件／任务保存期限及版本 |
| 交易有效等待及主体输入限制 | TASK-002／003／004提供唯一配置与规则版本，当前单方完成等待依据既定7天 | 新业务取当前配置，既有等待保存适用参数；暂停／续算由TASK-003规则维护 |

功能所需参数缺失时拒绝把该能力声明为已启用；阶段尚未采用的主体能力通过显式能力集说明。避免默认值掩盖缺少SMTP、文件用途核验器或主体查询适配。具体.env.example与Settings代码随实现建立，值及来源版本在准入材料登记。

## 审计与运行日志的字段及提交点

运行日志覆盖请求／任务开始、完成、拒绝及异常；业务审计保存已发生的主体变化和依据。统一上下文包括request_id、operation_id、correlation_id、causation_id、event_id、task_id、instance_id、connection_id，按实际入口填值或null，禁止把互不相同的标识混用。

业务审计字段：audit_id、occurred_at、actor_kind、actor_account_id或系统任务名、action、target具名引用、basis_ref或null、受限before_after、operation_id及必要配置／规则版本。公共包装生成技术上下文，主体用例提供业务事实；审计与业务／历史／幂等／事件同事务。回滚不保留成功审计，业务拒绝在事务外写脱敏运行日志，不伪造主体变化。

| 动作组 | 具名审计动作及最少事实 | 原码及私有内容处理 |
|---|---|---|
| 账户 | account.registered／password_changed／password_reset／email_changed／name_changed；稳定账户、变更字段名及必要前后值、实际操作者 | 不保存密码、散列、验证码、Cookie、CSRF、输入摘要或密钥；邮箱前后值仅限获准审计范围 |
| Session | session.issued／revoked；内部SessionID、签发／撤销时间及来源操作 | 不记录原始凭据或token_digest；失败鉴权只记类别和关联标识 |
| 邮件验证 | verification.requested／replaced／consumed／invalidated，记录验证ID、用途、结果类别及规则依据 | code只在单表专用字段，SMTP正文及原始服务响应不进入日志／审计 |
| 文件 | file.authorized／verified／references_changed／cleanup_claimed／deleted；file_id、用途、引用ID及保留依据 | 不记录签名表单／URL、存储凭据及用户原始文件名；必要元数据受限 |
| 主体业务 | 商品提交／编辑／审核、交易请求／约定／确认／终态、事项认领／处置／解除，动作名由主体唯一登记 | 保留前后业务事实及basis_ref，不把整段聊天／证据正文写入通用审计 |
| 事件及任务 | 派发／认领／重试／接管／完成及取消的运行记录，token对应内部任务与结果类别 | broker载荷只含稳定ID，日志不记消息正文、SMTP内容或完整私有事件 |

账户公开入口在验证前以entry标识运行上下文，成功建立／验证账户后审计实际账户主体及相应验证依据；不由客户端自报操作者。系统任务记录task_id与原业务basis，管理动作记录当前实际管理员及事项依据。

成功幂等重放沿用原operation_id及业务审计，本次request_id生成新运行记录，标明重放但不重复写业务审计。失败的验证码次数是专用已提交事实，按Q-003保存失败结果与计数，运行日志只记录失败类别；不将整个事务标成普通回滚后又重放计数。

## 白盒及动态验证输入

逐入口检查配置对象读取、类型范围、密钥引用版本、审计提交位置和脱敏白名单。日志字段序列化与错误响应采用显式schema，异常库原文仅在经过清洗的内部边界处理，不直接回显请求体。TC-COM-032覆盖配置缺失／非法关联、公开白名单、实例版本变化、回滚／重试审计及敏感字段扫描；真实运行结果随编码任务登记。

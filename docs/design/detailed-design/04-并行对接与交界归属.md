# 4. 并行对接与交界归属

## 设计归属

模块表达数据及动作的维护边界，任务可以跨模块设计一个完整关联。每项交界由一个任务形成定义，使用任务引用同一源文件。审查人核对需求和一致性，设计内容以该交界的归属任务为唯一编辑位置。

| 交界 | 唯一设计任务 | 交付源文件 | 使用任务 |
|---|---|---|---|
| 账户资格、执行上下文、事务、幂等和审计公共字段 | TASK-001 | 公共事务与权限、会话与身份、配置与可观测性专题 | TASK-002／003／004 |
| 文件引用及通知创建基础契约、消息传输框架 | TASK-001 | 文件与邮件、实时与任务专题 | TASK-002／003／004 |
| 商品与分类关联审批、审核内容版本、商品读取／编辑资格 | TASK-002 | 商品与分类专题（R0） | TASK-003／004 |
| 商品占用、请求／交易转换、交易分支创建归档触发及其通知 | TASK-003 | 商品与交易协同专题 | TASK-002／004 |
| 三类会话的消息、参与关系、已读和归档公共模型 | TASK-004 | 会话与处置事项专题（R2a） | TASK-003，TASK-001 实时传输适配 |
| 事项认领、沟通、决定与账户／商品／交易执行关联 | TASK-004 | 事项主体与处置执行、处置与主体协同专题（R2b） | TASK-001／002／003 |
| 实例、CI/CD、发布及恢复 | TASK-001 | 运行与部署说明 | 模块任务提供所需参数和兼容信息 |

## 可先引用的公共骨架

| 契约 | 当前对接依据 |
|---|---|
| 执行上下文 | 账户 ID、Session ID、请求／操作标识、当前资格及适用配置版本；ID 字符串，时间 UTC，金额整数分 |
| 事务 | 应用用例持有同一个 AsyncSession／事务，内部能力通过参数接受该上下文，由用例提交；并发任务各有自己的会话 |
| 权限结果 | 账户层提供当前资格，主体层检查归属、参与关系及状态，管理动作关联事项和认领资格 |
| 内部结果 | 每项动作列出成功业务结果与具名错误，接口层按共享 HTTP 语义映射；具体错误码由使用案例汇集 |
| 幂等 | 操作者＋操作类型＋请求键定位同次操作，输入摘要区分负载，结果及关联数据同事务保存 |
| 文件 | 业务保存并传递 file_id；使用文件时核对用途、归属、已核验状态并在本次业务事务建立引用 |
| 通知 | 业务提交接收账户、事件类型、来源主体及 ID、展示信息；通知记录和待分发事件随业务事务保存 |
| 实时事件 | 事件标识、接收账户、来源主体、类型、恢复进度及载荷；会话负责业务消息／已读，传输负责投递和连接 |

该骨架定义并行设计所需的语义及数据责任。字段名、类型细节、错误码和参数在各归属任务中补齐，采用同源更新并登记影响。

## 首批交界交付

基础契约按需求、总体设计及公共骨架独立发布，各自维护具名输入输出、前后置条件、错误和依据。下表按具体交付项组织依赖。

| 交付 | 维护任务 | 首批范围 | 使用位置 |
|---|---|---|---|
| R0 商品能力 | TASK-002 | 商品状态、展示／编辑资格及商品侧状态维护能力 | TASK-003 的商品适配；TASK-004 的商品执行适配 |
| R1 交易触发 | TASK-003 | 占用取得／释放、请求关闭、分支创建／归档的触发事实、业务标识及通知范围 | TASK-002 的占用适配；TASK-004 的分支适配 |
| R2a 会话模型 | TASK-004 | 参与关系、消息、已读、归档的基础字段和能力 | TASK-003 的分支调用；TASK-001 的实时传输 |
| R2b 处置请求 | TASK-004 | 目标、动作、依据、认领资格、预期变化及错误 | TASK-001／002／003 的主体执行适配 |

R0、R1、R2a、R2b 均可从需求及公共骨架开展，按各自语义独立审查和集成。R1 定义何时触发及期望结果，R2a 定义会话能力；具体签名绑定由后续适配 PR 完成。R2b 定义处置请求，主体任务在后续适配中核对并维护实际状态变化。

TASK-004 的 R2a、R2b 同时作为优先批次建立两份 PR：R2a 维护会话专题；R2b 维护独立的事项专题及处置协同专题。两项采用各自源文件，集成后补齐相互引用。

## 跨主体适配就绪条件

| 适配 PR | 采用的交界版本 | 完成交付 |
|---|---|---|
| TASK-002 第4批 | R0、R1、R2b；C1／C3 | 商品占用、处置执行、文件与通知的商品侧适配 |
| TASK-003 第4批 | R0、R1、R2a、R2b；C1／C3 | 商品／会话／处置签名、锁集合、调用顺序及原子范围 |
| TASK-004 第4批 | R0、R1、R2a、R2b；C1／C3 | 交易分支、商品与交易执行、证据及通知适配 |

各适配 PR 登记输入契约的源文件、提交及关联评审 PR。基础契约评审与本域设计同步推进；本域接口按其对应规则独立成批，关联验证在适配完成后核对。接口定稿和阶段准入采用已确认版本。

## 交叉审查及集成

每个 PR 指定一位实际审查人，按需求、契约与差异复核，使用任务可提交具体意见。审查安排与任务执行分别推进；交界确认采用单一源文件及一个结论记录。需求或总体架构取舍在相应 Q／ADR 中确认。

细化顺序为公共骨架→各任务首批交界→模块完整接口→集成核对。各任务的主体分析、业务规则与案例预期持续并行。

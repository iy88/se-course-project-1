# ADR-002 主体模块及统一业务数据库

| 字段 | 内容 |
|---|---|
| 编号/标题 | ADR-002 主体模块及统一业务数据库 |
| 协作入口 | [任务 Issue](https://github.com/iy88/se-course-project-1/issues/38) |
| 背景 | FR-01—FR-14；C-01—C-16。 关联 Q：按实际问题登记。 |
| 比较 | 见下表可行方案及影响 |
| 决定 | 账户、商品、分类、交易、会话、处置事项、通知七模块；PostgreSQL 为统一业务数据库。评论归商品，事项沟通归会话，分类单列，禁发范围归商品。 |
| 理由 | 使强关联数据、规则和动作具有稳定维护方。 |
| 代价 | 跨主体写入需要明确用例协调；聚合查询需统一权限口径。 |
| 验证 | 按需求反向核对主体、动作及跨模块调用，审查事项决定和状态执行的关联。 预期由对应任务的实际审查人核验，执行版本、环境、命令和结果在任务证据中登记。 结果位置随任务证据登记。 |
| 确认 | 本会话已明确采纳；确认姓名：袁尚峰；实际确认日期按会话记录登记，整理日期2026-11-13；交叉复核姓名及日期待登记。 |
| 重新评估条件 | 主体关系或批准需求变化。 |

## 可行方案比较

| 方案 | 收益与代价 |
|---|---|
| 方案 A | 按页面／功能划分，入口直观，主体数据维护可能跨组 |

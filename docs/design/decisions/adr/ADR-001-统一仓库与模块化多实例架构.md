# ADR-001 统一仓库与模块化多实例架构

| 字段 | 内容 |
|---|---|
| 编号/标题 | ADR-001 统一仓库与模块化多实例架构 |
| 协作入口 | [任务 Issue](https://github.com/iy88/se-course-project-1/issues/38) |
| 背景 | FR-01—FR-14；用户端移动网页及管理端电脑网页。 关联 Q：按实际问题登记。 |
| 比较 | 见下表可行方案及影响 |
| 决定 | 统一 monorepo；小屏响应式网页＋PWA 与 PC 管理网页独立构建发布；模块化单体按运行需要部署多个服务实例。 |
| 理由 | 保持设计、契约和代码版本可追踪，以主体模块支持并行细化。 |
| 代价 | 统一发布需核对跨模块兼容性；单机多实例资源需统一预算。 |
| 验证 | 多实例请求分流、共享状态、重连及后台接管。 预期由对应任务的实际审查人核验，执行版本、环境、命令和结果在任务证据中登记。 结果位置随任务证据登记。 |
| 确认 | 确认人袁尚峰（`iy88`）；首版登记日期 2026-11-13，依据架构首版提交。版本集成与后续复核证据见[确认与决策索引](../01-确认与决策索引.md#责任与普通细化项)。 |
| 重新评估条件 | 业务边界或实测容量变化。 |
| 替代关系 | 首次登记；后续替代关联新旧 ADR |

## 可行方案比较

| 方案 | 收益与代价 |
|---|---|
| 方案 A | 一个前端应用，统一入口与构建，需协调两类交互 |
| 方案 B | 两个独立前端，分别优化与发布，维护共享契约 |

独立业务服务可独立发布；当前统一数据库和跨主体事务更直接由模块化应用承载。

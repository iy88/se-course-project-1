# ADR-006 分作用域配置与规则版本

| 字段 | 内容 |
|---|---|
| 编号/标题 | ADR-006 分作用域配置与规则版本 |
| 协作入口 | [任务 Issue](https://github.com/iy88/se-course-project-1/issues/38) |
| 背景 | 第8章设计留项及已确认配置要求。 关联 Q：按实际问题登记。 |
| 比较 | 见下表可行方案及影响 |
| 决定 | 后端指定 .env 为运行参数来源；两端分别维护开发和构建配置。类型、范围、关联及必要依赖启动校验；业务能力随代码交付并按进程职责装配，已接入能力的必要依赖在启动时校验；配置禁止控制业务功能的启用或停用；可运行、已验证的增量可先合入和部署；可调整阈值读取配置，结构不变量按数据库模型保障。既有期限保存当次参数或版本。 |
| 理由 | 保持前端独立构建，配置可追踪，阈值调整通过配置落实。 |
| 代价 | 需要维护配置清单、公开能力契约、默认值依据与生效方式。 |
| 验证 | 检查配置完整性及派生一致性，运行时验证跨实例参数变化的行为。 预期由对应任务的实际审查人核验，执行版本、环境、命令和结果在任务证据中登记。 结果位置随任务证据登记。 |
| 确认 | 本会话已明确采纳；确认姓名：袁尚峰；实际确认日期按会话记录登记，整理日期2026-11-13；交叉复核姓名及日期待登记。 |
| 重新评估条件 | 配置作用域、发布方式或规则变更。 |
| 替代关系 | 首次登记；后续替代关联新旧 ADR |

## 可行方案比较

| 方案 | 收益与代价 |
|---|---|
| 方案 A | 合并前后端配置便于一处查看，构建输入相互耦合 |
| 方案 B | 按作用域统一配置，前端独立构建，交界通过能力接口和部署契约表达 |

选择后端单一 .env＋两端独立配置，类型化校验和规则版本支撑发布。

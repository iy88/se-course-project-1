## 可行方案比较

| 方案 | 收益与代价 |
|---|---|
| 方案 A | 各入口手工记录，业务就近，但公共字段和脱敏分散 |
| 方案 B | 中间件／用例包装复用公共流程，业务显式提供事实 |

选择公共机制与显式事实组合，必要审计在提交前写入。

## C5字段及动作登记

[配置与可观测性](../../detailed-design/key-designs/配置与可观测性.md)定义账户、Session、邮箱验证、文件、主体业务和任务的审计最少事实及日志白名单。成功审计与业务同事务，回滚无成功记录，同键重放只新增请求运行记录；验证码失败次数采用其专用提交语义。TC-COM-032核对配置、事务及秘密标记，实际结果在编码任务登记。

## Spring 入口及 AOP 映射

HTTP 过滤器、实时连接入口及 worker 包装建立并清理执行上下文。Spring AOP 在公开的应用用例入口统一记录请求／操作 ID、动作、耗时及结果，使用脱敏字段白名单。对于跨实例任务，从已登记的来源和队列引用恢复关联标识。日志只记录业务动作一次，内部服务复用同一上下文。

业务用例显式提供操作者、具名动作、目标、前后事实和依据；有审计要求时，经公共审计接口在业务事务内持久化。成功日志在事务结果明确后记录，回滚和幂等重放按实际结果区分。通过代理调用的用例采用 Spring AOP；同类内部调用由同一外层用例覆盖。事务作用域由用例显式声明。

Spring Boot 4.1.2 的 AOP 依赖采用 `spring-boot-starter-aspectj`。S1 验证覆盖代理入口、跨线程日志上下文清理、事务回滚时无成功审计、同键重放与脱敏，对应 TC-COM-032 及公共事务案例。

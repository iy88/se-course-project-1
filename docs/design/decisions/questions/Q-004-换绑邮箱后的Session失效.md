# Q-004 换绑邮箱后的 Session 失效

| 字段 | 内容 |
|---|---|
| Q编号／标题 | Q-004／换绑邮箱后的Session失效 |
| 协作入口 | [Issue #38](https://github.com/iy88/se-course-project-1/issues/38)、[PR #47](https://github.com/iy88/se-course-project-1/pull/47) |
| 问题与依据 | 需求4.19规定同时验证旧／新邮箱、稳定用户ID及新邮箱登录；已有Session在换绑后如何处理需明确 |
| 选项与影响 | A：全部退出，换绑时更新账户凭据版本，旧Session均失效，用户重新登录；B：保留Session，现有登录继续使用，新登录采用新邮箱 |
| 推荐 | A，与改密／重置采用同一凭据失效机制 |
| 最终决定 | 换绑成功后使全部旧Session失效，使用新邮箱重新登录 |
| 确认身份 | 袁尚峰（iy88），项目负责人；真实确认；2026-11-14，逐轮问题选择“全部退出（推荐）：换绑成功后使全部旧 Session 失效，使用新邮箱重新登录。” |
| 实现规则 | 账户邮箱、credential_version递增、两份验证码消费及清空、审计与幂等结果同事务；提交后清理当前Cookie，旧Session通过版本核对拒绝，Redis／IM清理提示可重试 |
| 交界影响 | Q-001／ADR-005采用同一版本失效规则；API-COM-AUTH-008、会话专题、TC-COM-020及部署输入同步；用户ID及历史归属保持 |
| 验证与复核 | TC-COM-020覆盖换绑与旧Session并发、新邮箱登录及多实例IM；运行结果随编码任务登记，实际交叉复核通过PR登记 |

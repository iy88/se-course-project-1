## 本轮细化与验证边界

退出以 PostgreSQL 撤销事务提交为成功依据，Redis 删除失败由持久清理意图重试；账户操作锁与 SessionGuard 行锁确定退出和业务写入的先后。只读请求在本次读取鉴权时判定，业务写入在资格锁后重查。IM 收发和后台向连接投递前核对相同依据，跨实例撤销通知用于及时断开连接。

Redis 不存在或到期按重新登录处理；Redis／数据库查询失败返回503并保留客户端凭据。Redis 恢复不从持久登记自动重建 Session；PostgreSQL 历史备份恢复执行会话清空流程。具体字段、锁序及清理协议见会话专题；真实多实例／故障恢复验证采用 TC-COM-015—017。

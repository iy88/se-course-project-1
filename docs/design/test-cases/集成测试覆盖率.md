# 后端集成测试覆盖率

## TC-COV-001 集成覆盖率采集与归档

| 项目 | 内容 |
| --- | --- |
| 范围 | Project1 后端 Maven reactor 中由 Failsafe 执行的集成测试。通过 `coverage-report` 汇总应用和业务模块的生产代码行、分支覆盖率，排除 `maintenance`。 |
| 依据 | [后端构建入口](../../../README.md)、[集成测试与 JaCoCo agent](../../../backend/backend-app/pom.xml)、[跨模块覆盖率汇总](../../../backend/coverage-report/pom.xml)、[GitHub Actions](../../../.github/workflows/ci.yml)。 |
| 前置 | JDK 27、Maven、隔离的 PostgreSQL 和 Redis。创建数据库所有者及应用账号，准备测试环境文件，并用维护工具执行最新迁移。CI 的临时环境配置见工作流。 |
| 通过条件 | 本次 Failsafe 执行至少一个用例且全部通过，无失败、错误或跳过。独立报告的行和分支均有非零命中，可按模块读取行和分支计数，模块计数之和与全局计数一致。 |
| 覆盖率解释 | 记录行和分支的已覆盖数、总数及比例。覆盖率验收目标为行 ≥ 85%、分支 ≥ 65%。证据采集与目标达成情况分别记录。 |

### 执行步骤

1. 从仓库根目录执行下列命令。`clean` 清理上次运行的执行数据，`-Pintegration` 启用 Failsafe 和集成覆盖率报告。
   ```sh
   mvn -f backend/pom.xml clean verify -Pintegration -Dit.envFile=/absolute/path/to/integration.env
   ```
2. 检查 `backend/backend-app/target/failsafe-reports/failsafe-summary.xml` 中的用例数、失败、错误和跳过数。
3. 读取 `backend/coverage-report/target/site/jacoco-integration/jacoco.xml` 中的全局及模块计数。核对汇总 POM 的数据文件过滤条件 `target/jacoco-it.exec`，并确认模块计数之和与全局计数一致。
4. 在测试报告记录全局及各模块的行、分支覆盖率。`evidence/` 根目录只保留最新的 Failsafe 汇总和校验值，不为证据建立编号子目录。CI 运行摘要记录全局行和分支覆盖率。

[执行报告与原始证据](reports/integration-coverage/测试报告.md)

### 关键分支回归

| 分支 | 集成断言 |
| --- | --- |
| `TaskWorker` | 业务失败后保存重试和错误码并释放租约。失效任务直接取消，重复就绪信号可确认且不重复执行。 |
| `WriteExecutor` | 已提交操作重放时重新检查权限。拒绝返回原操作 ID，后续合法重放仍返回同一结果，审计只写入一次。 |
| 交易取消决策 | 对方才可拒绝取消，提议人才能撤回。合法决策后交易保持进行中，商品仍被占用，会话未归档。 |
| 私聊权限与分页 | 非成员读取返回 404；两个方向的游标互斥；成员分别获得各游标方向的消息。 |
| 文件引用 | 已绑定头像可通过所属账户的引用读取，其他目标和解除引用后的读取均返回资源不可见。 |
| 分类引用 | 关联商品的分类允许停用，停用前后均拒绝删除，商品的分类关联仍有效。 |

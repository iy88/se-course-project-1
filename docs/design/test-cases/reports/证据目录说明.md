## 归档内容

每批使用 `evidence/RUN-*` 保存一次完整业务的证据，而不是每个原 TC 一个目录。一个 RUN 可以覆盖多个执行项。

| 类型 | 示例 | 要求 |
|---|---|---|
| 页面截图 | `RUN-A2-03-review-rejected.png` | 显示角色、页面和判定结果；覆盖敏感字段 |
| 测试邮件 | `RUN-A1-smtp-code.txt` | 只保留邮件主题、时间和脱敏验证码状态 |
| 浏览器网络 | `RUN-C1-network.txt` | 能对应关键请求／响应、状态码和错误码 |
| 数据库检查 | `RUN-C2-db.sql`、`RUN-C2-db.log` | 记录交易、商品、事项、通知等关键状态；脱敏 |
| Redis／实时日志 | `RUN-D3-realtime.log` | 记录连接、重连、游标和已读事件摘要 |
| OSS 日志 | `RUN-B2-oss.txt` | 记录对象用途、状态、删除／引用结果；去掉签名参数 |
| 测试命令 | `batch-tests.log` | 记录 commit、命令、时间、通过／失败数量 |
| 性能原始报告 | `P-RUN-2/*.json` | 保留环境、参数、阶段、实际速率、P50／P95／P99、错误、pending、资源与规模；删除 manifest、Cookie 和逐请求样本 |
| 性能日志摘要 | `P-RUN-3/run-log.md` | 按时间归纳 smoke、正式验证、容量边界、测试器偏差和清理，不复制大段终端输出 |
| 驱动与环境摘要 | `P-RUN-1/env-setup.md` | 记录代码版本、驱动／后端摘要、依赖版本、实例拓扑和网络条件 |

禁止提交 `.env*`、密码、验证码原码、Cookie、CSRF Token、AccessKey、SMTP 授权码、带签名的完整 URL 或真实个人信息。

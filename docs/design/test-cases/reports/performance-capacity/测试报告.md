# TC-PERF-001 性能与容量测试执行报告

本次在干净 PR 提交 `2685182d` 上重建后端、维护工具和驱动，使用隔离 PostgreSQL、Redis、真实私有 OSS 和 nginx 分流。种子规模为 100 普通用户及 10,000 商品。容量矩阵每档从同一个数据库快照恢复，稳态复核以相同参数重新生成隔离种子。袁尚峰（`iy88`）执行。参见[Issue #177](https://github.com/iy88/se-course-project-1/issues/177)、[测试案例](../../性能与容量.md)、[环境与构建](evidence/env-setup.md)及[执行命令](evidence/commands.md)。

## P-RUN-01 · 代表性稳态

API、WS、worker 各 1 个。30 秒预热、120 秒采样、场景间隔 1 秒。20 个操作槽包含 6 个首页、5 个搜索、5 个详情、1 个发布、1 个交易、2 个 IM。

**API／WS 验收通过。** 21,254 个测量 HTTP 请求，177.12 HTTP/s。必需 HTTP 操作 P95 最大 384.20 ms，IM 发送／送达／回读 P95 分别为 304.40／338.33／5.38 ms。HTTP 错误 0，WS 断连 0、重连失败 0。以上为复核通过批次；首次同参数稳态运行未通过，错误及证据缺口见[运行记录](evidence/run-log.md)。判定按常用交互 P95 3 秒、IM 送达 P95 2 秒及驱动的错误、样本与连接检查。[JSON](evidence/P-RUN-01/baseline-100u-10k-clean.json)

IM 送达从发送 POST 前计时，到接收方 HTTP 回读正文完成。驱动核对消息 ID、seq 和正文，回读先完成时保留回读时间戳。IM 回读指标从接收方 hint 起算。

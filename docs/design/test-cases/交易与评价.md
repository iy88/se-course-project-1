## 用例

### TC-TRD-001 竞争接受与唯一占用

| 项目 | 内容 |
|---|---|
| 目标 | 同商品两个待接受请求只有一个被接受；另一个关闭；不产生双占用 |
| 初始与角色 | P1 无占用；B1、B2 各对 P1 有待接受请求 R1、R2；S1 为卖方 |
| 操作序列 | S1 并发接受 R1／R2；S1 以 `expected_version` 接受 R1；随后再接受 R2 |
| 最终状态与历史 | R1 进行中，P1 `occupancy_trade_id=R1`；R2 `closed`，`close_reason=other_user_locked`；R2 会话归档；R1 快照生成；两条 `request_*` 历史与系统消息；R2 接受返回 `REQUEST_ALREADY_ENDED`；通知 B2 关闭原因 |
| 环境 | 真实 PostgreSQL 多连接；两个接受事务并发；核对锁后重读、唯一占用与回滚 |

### TC-TRD-002 同买方重复请求与并发

| 项目 | 内容 |
|---|---|
| 目标 | 同商品同买方不能同时存在两条待接受请求 |
| 初始与角色 | P1 无 B1 待接受请求；B1 为买方 |
| 操作序列 | B1 连续提交两次购买请求；另开连接并发提交同一 B1 请求 |
| 最终状态与历史 | 仅一条 `pending_acceptance`；其余返回 `REQUEST_DUPLICATE`；两项均不创建第二条会话、不重复通知 |
| 环境 | 单连接重复 + 双连接并发；核对唯一约束与幂等 |

### TC-TRD-003 接受请求幂等重试

| 项目 | 内容 |
|---|---|
| 目标 | 同一接受动作同键重试只产生一次占用、一次快照、一次系统消息 |
| 初始与角色 | P1 有 B1 待接受请求；S1 为卖方 |
| 操作序列 | S1 以 `Idempotency-Key=K1` 接受；同键同负载重试；同键不同 `expected_version` 重试 |
| 最终状态与历史 | 第一次成功；同键同负载返回第一次结果；同键不同负载返回 `IDEMPOTENCY_PAYLOAD_CONFLICT`；占用、快照、`request_accepted`、通知各一条 |
| 环境 | 单实例；检查幂等记录与事务回滚 |

### TC-TRD-004 约定变更生效重置确认与计时

| 项目 | 内容 |
|---|---|
| 目标 | 变更生效清空当前确认、结束计时、保留历史；重新确认后完整 7 天 |
| 初始与角色 | T2：A1 已生效，B1 当前确认、S1 未确认，计时剩余 5 天；B1 为提案方，S1 为对方 |
| 操作序列 | B1 提出变更 A2；S1 同意；B1 重新提交完成确认 |
| 最终状态与历史 | A1 `superseded`，A2 `effective`；B1 原确认 `invalidated_at` 有值、原记录保留；旧计时 `ended_at` 有值；B1 新确认启动完整 7 天；历史含变更、决定、确认事件；T2 仍进行中 |
| 环境 | 核对 `AgreementDecision`、`business_event_id` 唯一与通知 |

### TC-TRD-005 变更被拒保持原约定与计时

| 项目 | 内容 |
|---|---|
| 目标 | 变更被拒后原约定、原确认、原计时不变 |
| 初始与角色 | T2：A1 生效，B1 当前确认、S1 未确认，计时剩余 5 天；B1 提出 A2，S1 拒绝 |
| 操作序列 | B1 提出变更；S1 拒绝；定时任务继续计时 |
| 最终状态与历史 | A1 仍 `effective`；A2 `rejected`；B1 当前确认仍有效，S1 无当前确认；计时继续；无新确认、无重置；历史含提案与拒绝决定 |
| 环境 | 核对业务状态与计时读值 |

### TC-TRD-006 单方确认超时转异常

| 项目 | 内容 |
|---|---|
| 目标 | 仅一方确认且满 7 天转异常、冻结；不自动完成、不自动取消 |
| 初始与角色 | T2：A1 生效，B1 当前确认、S1 未确认；等待累计至满 7 天；无冻结、无争议 |
| 操作序列 | 后台扫描到阈值；A1 查看；管理员处理事项 |
| 最终状态与历史 | T2 `abnormal`；`TradeFreeze(source=timeout, ended_at=null)`；计时结束；B1 当前确认保留；管理事项创建；系统消息 `trade_abnormal`、`trade_frozen`；不产生完成／终止 |
| 环境 | 数据库时钟；多实例仅一个扫描任务生效；核对幂等 |

### TC-TRD-007 冻结暂停与解冻续算

| 项目 | 内容 |
|---|---|
| 目标 | 冻结暂停计时，全部冻结解除后续算剩余；多冻结不提前续算 |
| 初始与角色 | T2：等待剩余 5 天；存在冻结 F1（处置） |
| 操作序列 | F1 生效 2 天；新增 F2（封禁）1 天；解除 F1；再解除 F2；继续等待 |
| 最终状态与历史 | F1、F2 有效期间 `active_since` 为空，累计不增长；仅 F2 解除后恢复计时；剩余仍为 5 天；无确认清空、无状态变化；历史含 `trade_frozen`、`trade_unfrozen` |
| 环境 | 核对多冻结集合与计时秒数 |

### TC-TRD-008 争议开始、解决与恢复

| 项目 | 内容 |
|---|---|
| 目标 | 争议结束原计时；解决清空确认、恢复不启动计时 |
| 初始与角色 | T3：有争议，B1 当前确认、S1 未确认；A1 认领事项 C1 |
| 操作序列 | 双方确认争议解决；分别查看确认与计时；B1 重新提交完成确认 |
| 最终状态与历史 | 争议 `resolved`；B1 原确认 `invalidated_at` 有值、历史保留；计时不启动；T3 回进行中；B1 重新确认后启动完整 7 天；历史含 `dispute_resolved` 与新确认 |
| 环境 | 双人确认；核对当前确认的唯一部分索引 |

### TC-TRD-009 四类取消路径

| 项目 | 内容 |
|---|---|
| 目标 | 首约前直接取消、首约前卖方申请、约定后协商、拒绝／撤回均落正确终态 |
| 初始与角色 | T1 首约待确认；T2 约定已确认；B1、S1 为双方 |
| 操作序列 | ① B1 直接取消 T1；② T1 结束后在同一商品 P2 新建 T1a，S1 申请，B1 同意；③ T2 由 S1 申请，B1 同意；④ T2 结束后在 P3 新建 T2a，B1 申请，S1 拒绝；⑤ T1a 结束后在 P2 新建 T2b，B1 申请后撤回 |
| 最终状态与历史 | ①②③ 终止；① 无确认，② 无确认，③ 保留当前确认；④ `rejected`、⑤ `withdrawn`，交易继续；终止路径写 `cancellation_*` 决定与 `trade_terminated`；拒绝／撤回只写决定，不改交易状态 |
| 环境 | 分别执行；核对取消模式与阶段条件 |

### TC-TRD-010 双方完成确认

| 项目 | 内容 |
|---|---|
| 目标 | 第二方确认后完成、释放、归档、解除冻结、商品下架 |
| 初始与角色 | T2：A1 生效，B1 当前确认，S1 未确认；无冻结 |
| 操作序列 | S1 提交完成确认；查询 TradeView；查询商品与会话 |
| 最终状态与历史 | T2 `completed`；占用清空、商品默认下架；双方当前确认保留；计时结束；本笔冻结全部解除；`TradeConversation` 归档只读；系统消息 `completion_confirmed`、`trade_completed`；通知双方与评价入口 |
| 环境 | 核对原子提交与通知投递 |

### TC-TRD-011 终态不可恢复与未结束恢复

| 项目 | 内容 |
|---|---|
| 目标 | 已完成／已终止不能恢复；有争议／异常可恢复；恢复不重取占用、不重开会话、不启动计时 |
| 初始与角色 | T5 已终止、B1 当前确认保留；T3 有争议；T4 异常冻结；A1 有事项依据 |
| 操作序列 | A1 尝试将 T5 恢复进行中；A1 按 T2-24 解决 T3 争议；A1 按 T2-29 恢复 T4；A1 按 T2-27 解除 T4 冻结；B1 在 T3／T4 重新确认 |
| 最终状态与历史 | T5 返回 `TRADE_TERMINAL`，状态、商品、会话、冻结均不变；T3 争议 `resolved`、T4 回进行中，二者占用保持、会话不重开、计时不启动；T4 冻结在 T2-29 后保持、由 T2-27 解除；B1 重新确认后启动完整 7 天；历史含 `dispute_resolved`（T3）与 `trade_restored`（T4） |
| 环境 | 管理路径；核对终态拒绝与未结束恢复的差异 |

### TC-TRD-012 管理员调整完成／终止

| 项目 | 内容 |
|---|---|
| 目标 | 管理员可从非终态完成／终止；不伪造确认；结束释放占用并归档 |
| 初始与角色 | T1 进行中，无确认；T3 有争议，B1 有当前确认；A1 认领事项 |
| 操作序列 | A1 完成 T1；A1 终止 T3；再尝试调整 T1 |
| 最终状态与历史 | T1 `completed`、T3 `terminated`；T3 保留 B1 当前确认；T1 无伪造确认；占用释放、商品下架、会话归档、冻结解除；再次调整 T1 返回 `TRADE_TERMINAL`；历史 `trade_completed`／`trade_terminated` |
| 环境 | 管理路径；核对 `terminal_reason` 与历史 |

### TC-TRD-013 评价唯一性与边界

### TC-TRD-014 接受与下架／封禁竞争

| 项目 | 内容 |
|---|---|
| 目标 | 接受与商品下架、卖方封禁竞争时最多一方成功，不产生占用与终态矛盾 |
| 初始与角色 | P1 有 B1 待接受请求；S1 正常；A1 可封禁 |

| 环境 | 真实 PostgreSQL 多连接；核对商品行锁、账户资格锁与状态重读 |

### TC-TRD-016 六类来源引用与 business_event_id

| 项目 | 内容 |
|---|---|
| 目标 | 六类 source_ref 指向本交易不可变记录；跨交易拒绝；事件 ID 去重 |

| 操作序列 | 依次写六类系统消息；用 T9 的记录作为 T2 的 source_ref；同 `business_event_id` 重放；修改当前提案后读取历史消息 |

## 确认与复核

第 5 批由孙含佳编写，袁尚峰审查；交叉审查姓名与日期随 PR 登记。审查重点：初始数据是否可构造；并发序列是否覆盖锁与唯一约束；终态、恢复、确认、计时是否符合 T1／T2；六类 source_ref 与 `business_event_id` 是否可核验；与 TASK-004 的会话／处置交界是否一致。

## 分执行项

| 执行项 | 目的 | 输入与判定 |
|---|---|---|
| P01 | 验证需求规定代表性负载 | 100 用户、10,000 商品、30/120 秒、think 1 秒；必需 HTTP 与 IM 操作按各自 P95 阈值、零错误、完整规模判定 |
| P02 | 验证 `capacity` 默认值 | Single Search，起点 200、上限 400 HTTP RPS、5 秒预热、30 秒阶段、300 秒验证；分别验证 API 1／2／4 |
| P03 | 定位性能上限与扩容收益 | Search 固定 600／800 RPS；IM 200／400／600／800 场景每秒；mixed 100／200 场景每秒；记录实际速率、P95、pending、错误和资源峰值 |
| P04 | 判断是否增加 worker | 同 mixed 条件下 worker 1／2，比较结果、`work_stream`、pending 与 CPU；不以 IM 或上传路径推断 `TaskWorker` 容量 |

## 判定边界

- 400 HTTP RPS、300 秒是本次正式容量验证；20 秒上限档只用于边界定位，不作为长期 SLA 承诺。
- 测试器自身发生 in-flight 饱和、late arrival 或样本不足时，结果标记为不可判定，不自动归因服务端。
- 同机 loopback 的正向结果不代表 WAN、浏览器渲染或云网络条件；文件上传不套用普通交互 3 秒阈值。
- SMTP 不在本次读写与 IM 操作配比内，明确记为不适用，不伪造邮件投递证据。

# 前端浏览器自动化回归案例

依据包括[质量要求](../../requirements/06-质量要求.md)、[验收与验证](../../requirements/07-验收与验证.md)和[前端开发说明](../../../README.md#前端开发)。

本案例作为独立的前端浏览器回归测试，不改变 108 个业务 TC 或 72 个人工前端执行项的数量。它使用 Playwright 和本地模拟 API 验证用户端、管理端在真实 Chromium 中的路由、交互、请求载荷和可观察状态；不替代真实后端、并发数据库、Redis、OSS、SMTP、公网部署和人工业务验收。

执行报告见[TC-FE-001 前端浏览器自动化回归测试报告](reports/frontend-playwright/测试报告.md)。

| FE-E2E-04 | 发起购买请求 | 从商品详情提交购买说明；请求包含页面内容版本和唯一幂等键；跳转到待接受交易 | TC-TRD-002 的前端请求子集 |
| FE-E2E-05 | 发布商品 | 选择分类并提交标题、描述和价格；请求价格使用整数分；成功后进入本人待审核商品详情 | TC-PRD-001／002 的前端发布子集 |
| FE-E2E-06 | 接受交易请求 | 卖家按页面版本接受请求；界面切换为交易中并显示约定入口 | TC-TRD-001／003 的前端接受子集 |

## 执行口径

全部用例使用 Playwright 的角色、标签和可见文本定位，不使用固定等待或生产数据。用于制造竞态、重复提交和网络失败的请求门只存在于测试夹具中，不写入产品代码。

前端用例通过模拟 API 证明页面行为和请求契约，不证明后端事务、唯一约束、真实 Redis 游标、OSS／SMTP 或跨实例并发。对应完整业务 TC 仍需由原有人工批次、集成测试和验收证据完成。

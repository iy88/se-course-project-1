# 1. 设计依据与目标

## 需求输入

需求输入为[需求规格说明书](../../需求规格说明书.md)、[需求基线](../../requirements/08-需求基线.md)及其详细材料；两份需求阶段报告提供既有确认与验证依据。需求阶段的历史输入为 `ff491a6`，现行版本见需求基线，分类统一表述为一级分类，商品可关联多个分类。功能覆盖 FR-01—FR-14，质量目标按第6、7章执行。

## 交付形态与技术方向

统一仓库组织用户端、管理端、后端及设计材料。用户端采用移动优先的响应式网页与 PWA，同一应用适配桌面宽屏并保留业务操作；管理端采用 PC 网页；两个前端应用独立构建和发布。

后端通过HTTP适配、契约校验、事务与持久化、迁移和类型化配置能力实现；实现采用 Java、Maven、Spring Boot、Spring Data JPA、PostgreSQL 与 Flyway，工程映射见 [ADR-010](../decisions/adr/ADR-010-RESTful契约与技术栈.md#spring-data-jpa-与-postgresql)。前端采用 Vue 3、TypeScript 与基于 Rspack 的 Rsbuild，采用 Oxlint 和 Oxfmt，浏览器 HTTP 请求采用 Axios 的 XHR 适配器，接口类型由 OpenAPI 契约生成。管理端的跨页面操作提示由 Pinia 管理。具体依赖版本在实现输入基线中登记。

## 设计目标

业务按主体及其强关联数据组织，统一数据库保障权威业务状态。支持单机多服务实例，通过共享机制协调会话、事务、IM 与任务；当前部署验收采用单机多实例，性能结果作为部署变化依据。

必需业务能力完整实现，启动时校验必要配置。代码明确权限、状态、事务及失败语义，白盒审查核对业务逻辑；运行时测试覆盖静态检查之外的并发、复杂关联、网络和跨实例行为。

# 技术栈独立的应用架构

依据：袁尚峰于2026-11-17要求采用技术栈独立的应用架构描述，并将技术栈解耦纳入design；各公共能力的扩展细化随对应PR交付。

## 稳定契约与技术映射

模块化单体、主体事实归属、统一业务事务、资格与业务锁序、幂等、审计及事件同事务、任务租约与接管属于稳定架构契约。HTTP／WebSocket、OpenAPI、UTC时间、对外字符串ID及既有错误语义保持一致。PostgreSQL、Redis、OSS、SMTP与现有部署隔离决定继续作为基础设施输入；应用语言独立与基础设施无关分别描述。

后端选型及兼容性证据采用[ADR-010](../decisions/adr/ADR-010-RESTful契约与技术栈.md#spring-data-jpa-与-postgresql)。主 ORM 采用 Spring Data JPA 与 Hibernate；数据库特定的锁和写入路径按公共契约使用显式 SQL，Flyway 维护数据库结构。HTTP适配、契约校验、事务管理、持久化、迁移、任务执行与静态检查能力按所选技术栈映射到具体工具。文档生成脚本的语言不限定后端语言。

接口采用语言无关的操作名、具名输入／结果及错误表。EntityId、ResourceRef、ExecutionContext、Transaction、LockPlan及Allowed为概念类型；list、可空值和具名结构表达集合与数据契约。方法签名不要求Python类、Java继承体系、装饰器或特定依赖注入容器。实体与外部响应模型分别承担持久事实和传输职责。

## 选型及验证

技术选型记录实际语言、框架与版本，以及每项稳定契约的实现位置。迁移、类型与质量检查采用所选技术栈对应工具；数据库并发、多实例身份、事件恢复、任务接管和外部I/O故障验证采用相同业务输入及可观察预期。编码准入检查技术映射完整性，运行证据登记实际技术栈。

# 4. 数据架构

## 权威数据与存储

PostgreSQL 统一保存业务数据、账户凭据版本、历史、幂等、通知及待投递事件。Redis 保存有效 Session、共享控制状态及消息传递状态。OSS 保存文件内容，数据库保存文件状态和业务引用。每类数据有明确权威位置。

数据库内部复制或分布式一致性由数据库架构承担；应用明确所需事务、读写语义和业务不变量。

## 公共表示

主体业务记录使用数据库生成的整数 ID，对外用字符串；请求、操作、任务、事件标识使用 UUID。金额采用整数分。时间使用带时区类型、按 UTC 处理，接口输出带时区 ISO 8601。

生命周期、确认进度、冻结和展示资格分别表达。主体数据按需求逻辑删除，编辑、审核、约定、确认及处置保存各自历史及操作者、时间和依据。

## 约束与规则版本

唯一性、外键和结构不变量由数据库及代码共同保障。可调整长度、大小、次数和期限读取后端配置，存储容量按可支持范围设计。

新操作采用当前配置；已签发验证码、上传授权和交易计时保存当次期限、必要参数或规则版本。历史读取保留原内容，后续修改按当前规则校验。影响既有业务的调整登记变更、处理方式和验证依据，审计关联适用版本。

## 文件生命周期

申请授权→浏览器直传 OSS→后端核验对象→登记可引用→业务事务建立引用。对象采用私有访问，读取时校验业务资格并签发短期地址；过期无引用暂存对象按授权及引用状态回收。对象存储与数据库通过可重试状态流程衔接。

## 详细设计输入

各模块细化属性、关联、唯一约束、索引、版本字段及历史结构。统一锁序、账户凭据版本校验和文件引用协议由 TASK-001 统筹。

## 字段与统一规则检查

按[设计约束与检查规则](../设计约束与检查规则.md)的 DATA-01—04、RULE-01—04 及 DOC-01 检查字段来源、主体类接口、锁后判定、查询等价性和同源传播。实体与共享视图保留事实及必要关联，展示、搜索及动作资格通过所属类接口统一计算。

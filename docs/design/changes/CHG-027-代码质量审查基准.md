# CHG-027 代码质量审查基准

2026-11-28，袁尚峰确认将文件粒度和复杂度作为代码审查参考。每次重构由具体维护问题推动，先判断职责、变更原因和验证成本，再决定是否拆分。现有高内聚文件、基础设施和复杂业务允许保留当前粒度，审查时说明理由。指标用于选题和复核，当前采用人工审查。

## 审查参考值

| 指标 | 参考值 |
|---|---|
| 生产源码文件 | 常规目标 200～400 SLOC，参考中心 300。超过 500 时关注。超过 600 时重点核对职责，超过 1,000 时优先评估可独立拆出的用例。 |
| Java 和前端文件类型 | 按职责调整。配置、DTO 和工具通常较短。应用服务和 Vue 单文件页面可容纳较多协作逻辑，超过约 800 SLOC 时优先检查能否拆出完整用例或交互区块。 |
| 方法 | 10～30 SLOC 为常规目标。超过 50～60 时检查复杂分支，超过 100 时重点评估。 |
| 控制流 | 圈复杂度 10、认知复杂度 15、嵌套深度 3 为参考值。 |
| 项目分布 | 中位数 ≤150、P90 ≤400、P95 ≤600、超过 600 SLOC 的比例 ≤5%、最大三个文件占比 ≤10%。普通生产源码超过 1,000 SLOC 的文件长期以零为方向。 |
| 测试 | 单独观察。具体业务流程所需的前置、断言和测试数据可完整保留。 |

| Vue 普通组件 | 50～200 | 300 | >500 |
| Vue 复杂交互组件 | 150～350 | 600 | >800 |
| Composable、API Client | 50～150 | 250 | >400 |
| Pinia Store | 50～200 | 350 | >500 |
| TypeScript Utility | 30～150 | 250 | >400 |

| Java 和前端测试 | 100～400 | 600 | >1,000 |

## 重构和记录

1. 一处完整职责对应一个实现提交。Java 优先沿用原应用入口、事务和锁边界提取用例，Vue 优先沿实际交互边界拆分。
2. 按已有测试和接口契约验证行为。范围涉及事务、并发或跨模块回调时，运行对应集成测试。前端涉及交互时核对状态生命周期及原有反馈。
3. 在实现提交或关联 PR 记录重构动机、影响范围、验证结果和必要例外。重构要求或审查基准发生变化时，可以在 `docs/design/changes` 登记 CHG。
4. 生成代码和第三方代码排除；测试独立统计。文件偏长且职责完整时允许保留，避免仅为降低行数增加转发层或拆散同一事务流程。

## 数据访问

2026-11-28，袁尚峰补充要求，非必要避免手写原生 SQL。优先使用已有仓储方法、Spring Data 派生查询、JPQL 或项目已有查询抽象。确有数据库特有语义，或有针对性的查询计划、并发或原子性要求时，在变更记录说明框架查询不足之处，并采用参数绑定和相关集成测试。现有 SQL 随具体业务变更评估。

本次登记审查方法和实测基线，业务源码与 CI 配置沿用原版本。

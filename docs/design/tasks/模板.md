# 阶段任务卡模板

D0 在 `design` 完成设计集成和交界复核。合入 `main` 后，阶段任务以最新 `main` 的需求及设计为输入，通过阶段准入批准后开始编码。

后续编码任务使用本模板的实现字段，并引用 `main` 中已合入的设计。

| 字段 | 内容 |
|---|---|
| 任务编号/名称 | TASK-编号／名称 |
| 负责人/审查人 | 填写姓名；审查交界 |
| 关联阶段、需求、ADR、接口和测试 | 阶段、FR／BR／TR、ADR／Q、API、TC |
| 目标 | 一句话说明可观察结果 |
| 输入基线 | 以最新 `main` 为准，引用适用文档；关联任务可使用[关联 PR 联调基线](索引.md#提交与集成)；实际采用版本随对应 PR 或阶段准入记录登记。 |
| 允许修改 | 具体模块、源文件及交付位置 |
| 协同变更范围 | 其他任务源文件由对应任务维护；需求、规则及验收预期通过评审变更 |
| 前置依赖 | 任务、Q、公共契约版本及环境 |
| 事务、权限、幂等约束 | 本任务适用约束 |
| 必执行测试 | 具体检查、场景、环境及回归；设计阶段说明预期核验和后续执行安排 |
| 完成标准 | 按交付类型列明产物、证据、文档同步及人工审查 |
| 变更评审触发条件 | 登记需求／接口／架构／迁移／依赖变化，确认后继续对应子项 |
| 提交方式 | 每批独立分支与 Draft PR，每个 PR 包含多个单一职责小 commit，注明交付批次及 PR 目标 |
| 协作入口 | 关联 GitHub Issue／PR 链接 |

## 扩展字段

- 交付类型：设计细化／编码实现。
- 多批次交付表、每批指定分支、design 起点提交、PR 目标与 Issue 关联。
- 待完成子项：每项明确交付文件、内容及完成判据。
- 依赖矩阵：公共输入、可先行部分、具体受阻子项及解除依据。
- 分批审查按[提交与集成规范](索引.md#提交与集成)执行，关联引用、案例及生成物随对应改动同步。
- 检查与证据：实际命令、版本、环境、结果、待执行及原因。

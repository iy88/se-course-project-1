## 提交与集成

设计和编码任务均按可独立审查的批次提交。每个批次使用独立分支，首个可审查的 commit 提出 Draft PR，后续以多个小 commit 补齐该批交付。每个 commit 聚焦一个目的，相关需求引用、接口、案例和生成物随对应改动同步。独立增量从最新 `main` 开工并面向 `main` 提交 PR。关联任务可合入一个或多个 PR 的明确提交建立联调基线，向对应基线提交 Draft PR。阶段临时基线、更新传递及切换按[阶段开发基线](../implementation-plan/03-阶段准入与验收安排.md#阶段开发基线)执行，Issue 和 PR 记录依赖、提交、基线分支及验证结果。依赖正式进入 main 后，依据新基线核对可单独提交的差异，再调整 PR 目标。

公共源文件及拼合清单由 TASK-001 集成，其他任务维护各自模块源文件。TASK-001 同时维护公共数据模型、聚合及管理查询接口、需求到阶段的覆盖映射、统一设计基线，以及基于已合入 `main` 的设计准备阶段编码任务与准入材料；其C9／C10按专题输入独立分批交付，C11在四任务设计交付与评审集成后组织固化，随后C12准备编码任务卡及准入材料。复核按商品—交易、交易—会话、事项—主体交界登记实际姓名和记录。部署工作由 TASK-001 承接。

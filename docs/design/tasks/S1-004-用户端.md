# S1-004 用户端

| 字段 | 内容 |
|---|---|
| 负责人／审查人 | 孙含佳（`shjj11`）；袁尚峰（`iy88`） |
| 范围与依据 | S1，FR-01／02／03／04 商品部分、FR-09／13、FR-11／12 当前部分；[S1 动作映射](../detailed-design/01-需求与接口映射.md)中的账户、文件、商品、分类、通知与本人查询 |
| 目标 | 实现用户从账户入口到发布、查询、评论收藏、通知及本人管理的 S1 界面。以手机为主要使用场景，同一应用响应式适配桌面 |
| 输入基线 | 以最新 `design` 为准，参见[总体设计与决策](../基线索引.md)与[S1 阶段准入](../acceptance/S1-阶段准入.md)。 |
| 允许修改与协同 | `frontend/user-web` 的业务路由、页面、适配及测试；共享 Axios XHR 客户端与工程配置由 S1-001 维护，接口响应与商品资格同 S1-002 核对 |
| 前置依赖 | S1 准入、S1-001 骨架及 OpenAPI；受控响应可先用，真实联调需账户、文件、商品及审核服务可用 |
| 事务、权限、幂等 | 按后端能力和当前响应展示操作资格及状态；保留接口约定的提交幂等键，按错误语义处理失效和可重试失败 |
| 必执行测试 | 优先以受控响应对错误映射、查询参数和页面状态转换做单元测试；人工前后端联合验证入口、上传失败和重试、审核后展示、搜索范围、评论收藏、通知及本人视图；遇到共享客户端契约风险时补集成测试 |
| 完成标准 | 用户端通过 Oxc、类型与构建检查；S1 页面接入真实接口，手机与桌面宽度均可完成主要操作，并有正常路径和关键异常的人工联调记录 |
| 变更评审触发条件 | OpenAPI 请求及错误、权限展示、文件直传协议或共享客户端生成方式发生变化 |
| 提交方式 | 按可审查批次建立独立分支和 Draft PR，每个 PR 包含多个单一职责小 commit，遵循[提交与集成规范](索引.md#提交与集成) |
| 协作入口 | [TASK-003 #40](https://github.com/iy88/se-course-project-1/issues/40)，派发后关联编码 Issue／PR |

先按约定类型开发路由和页面，再用真实 API 对照后端响应联调。开展上传以及审核后展示检查时，与管理端负责人共用指定的测试商品和账户。手机布局优先照顾触控导航、表单和上传。桌面宽度可扩展商品网格，并调整筛选、导航和表单宽度。两种布局共用路由、操作资格及 API。联合测试检查列表、详情、发布表单和关键反馈在两种宽度下均可用，页面无意外横向滚动。系统端到端用例在开发完成后执行。

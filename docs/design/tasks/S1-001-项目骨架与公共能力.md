## 交付批次

| 批次 | 范围与交付 | 完成检查 |
|---|---|---|
| 1. 后端构建与装配 | 创建 Maven 根 POM 和构建包装器，统一 Boot 依赖、Java 编译基线和构建插件。按[模块表](../architecture/02-总体架构与模块职责.md#maven-模块与服务边界)建立 `backend-app`、`backend-core`、七个主体模块、`file-storage`、`messaging`。装配模块提供可执行 JAR、健康检查、角色及配置入口；各主体用服务接口和 DTO 交互。 | 根构建能验证子模块依赖；应用在开发环境启动并报告健康；模块服务可由应用装配。 |
| 2. 前端工程与共享客户端 | 在同仓初始化 `frontend/user-web` 与 `frontend/admin-web`，采用 [ADR-010 的官方 Vue 模板](../decisions/adr/ADR-010-RESTful契约与技术栈.md#vue-3rsbuild-与-oxc)。两端提供独立开发、构建、类型检查入口。共用 Oxlint、Oxfmt 配置与 OpenAPI 生成类型，统一封装 Axios XHR、站内会话及 CSRF、基础错误、身份引导和 Rsbuild HTTPS 开发代理；统一使用同源 `/api/v1`，OSS 直传使用独立请求配置。 | 两端可分别启动和构建；生成物可从同一契约重建。调用者取得配置示例和受控响应入口；用户端有移动优先且适配桌面的基础布局。 |
| 3. 公共运行约束 | 实现类型化配置、`.env.example`、统一错误与 HTTP 上下文、鉴权与统一 CSRF 入口、事务与幂等、Flyway 启动迁移、通用请求日志及脱敏。AOP 处理横切日志和上下文，业务用例显式登记审计和待投递事件，由同一事务持久化。 | 从空库迁移启动；无效配置失败并指出字段；提交与回滚在真实 PostgreSQL 核对；请求日志和事务审计有各自证据。 |
| 4. 账户、文件与通知 | 落实注册邮箱验证、登录／退出、改密／找回、换绑邮箱及本人资料，接入 Redis Session、邮件任务与约束。提供文件授权、完成核验、引用和回收服务；接入通知持久化、已读、事件投递与恢复；按 S1 范围组装本人查询和审核待办。 | 按 OpenAPI 发布服务接口、响应与异常；供商品／审核和双前端调用。 |
| 5. CI 与运行交接 | GitHub CI 在锁定工具链下执行 Maven 校验、两端依赖锁安装、lint／格式／类型及构建检查，执行纳入回归的测试。准备 API 与任务进程的本地启动；按 [ADR-011](../decisions/adr/ADR-011-单机多实例CI-CD.md)接入 Jenkins、systemd、Nginx 所需的产物结构及发布入口，保持两端同源 `/api/v1`、原始 Origin 和后端私有监听。 | 在目标 Linux 工具链验证 Java 27 及主要依赖；发布前记录命令、版本、构建产物及实际运行结果。 |

## 开发验证

- **单元优先。** 用固定时钟和显式配置覆盖配置边界、邮件验证码有效期与错误条件、账户资格、文件用途和事件投递判定。静态检查核对模块依赖、前端生成的契约类型和提交产物。
- **必要集成。** 以[公共案例](../test-cases/公共能力.md)为准。真实 PostgreSQL 的同事务回滚应撤销 JPA 写入与 JDBC 审计／待投递记录（TC-COM-001／007／032）。真实 PostgreSQL 和 Redis 验证退出或凭据变化后旧 Session 无法重新授权（TC-COM-015—017）。按 [ADR-004 Java 适配](../decisions/adr/ADR-004-RedisStreams与Taskiq.md#java-适配与-s1-验证)验证 Redis Streams 的独立消费、消费组和显式确认，邮件受理与任务恢复采用 TC-COM-018／019／027，按文件核验及引用选取 TC-COM-011—014，记录可控替身和真实依赖各自覆盖的行为。
- **人工联调。** 启动两端和开发 API，以准备的用户及管理员验证注册／登录、会话失效、文件授权与失败提示、本人通知和审核待办。用户端在手机与桌面宽度各联调关键操作。核对页面表现、接口响应和相关数据／日志，标记账号、前置数据及结果。按 TC-COM-020 验证开发代理与生产式 Nginx 路由下合法写入，以及缺失或无效 Origin／Token 被拒绝且无业务副作用。

# S1 阶段准入

任务输入以最新 `design` 为准，采用 TASK-001 第 10 批技术决定。准入记录登记实际批准的提交、接口版本及四份任务的 Issue。

| 检查项 | 核对依据 |
|---|---|
| 链路与责任 | [阶段范围和工作顺序](../implementation-plan/01-阶段划分与依赖.md#s1-工作顺序)，[四份编码任务卡](../tasks/索引.md#s1-编码任务) |
| 前置决定 | [决策与 Q 索引](../decisions/01-确认与决策索引.md)中的 ADR-001—011 和 Q-001—004，按各任务涉及范围核对 |
| 接口、事务与权限 | [动作映射](../detailed-design/01-需求与接口映射.md)中的 S1 行。账户、文件、商品分类、审核认领、通知与查询的提供方和调用方共同核对输入、错误码、锁集合与审计提交边界 |
| 开发验证输入 | 各任务卡的人工联合测试场景、优先单元测试和必要集成用例，关联现有 TC。准备独立测试数据库、Redis 前缀、测试账户和管理员、商品／分类审核数据、受控邮件及文件环境 |
| 运行与配置 | OpenJDK 27、Maven、PostgreSQL、Redis、Node.js、前端锁文件与环境配置；采用 ADR-011 的 Jenkins、systemd 和 Nginx 发布路径，准备同源 HTTPS 开发代理、Nginx 测试入口及分环境 Origin 配置。准入核对目标 Linux／CI 的 OpenJDK 27 获取方式、PostgreSQL 与 Redis 的隔离测试资源、OSS／SMTP 测试入口及责任人 |
| 准入记录 | 按[准入模板](阶段准入记录模板.md)登记实际批准人、日期、输入提交、接口及测试预期复核依据 |

## 接口交接与联调主链

| 场景 | 提供方与调用方 | 契约及联调确认点 |
|---|---|---|
| 邮箱验证、登录与会话 | S1-001 → S1-003／004 | AUTH-001—009、MAIL-001、CONFIG-001。两端走同源 API，验证入口与会话凭据绑定、登录退出、账户资料及过期提示，参见 TC-COM-015—021／032 |
| 上传与提交审核 | S1-001 文件、S1-002 商品 → S1-004 | FILE-001—003、API-PRD-001—004／022／023。图片核验完成后引用，验证正常提交、拒绝修改重提、认领前撤回，参见 TC-COM-006／007／011—014、TC-PRD-001／002／005—009／036／040 |
| 认领、审核与分类生效 | S1-003 认领、S1-002 商品分类 → S1-001 应用装配及管理端 | QUERY-004、API-CASE-004、API-PRD-005／006。由不同管理员验证共享池、固定归属与资格；检查审核通过时商品、获批分类、历史和通知的提交结果，参见 TC-CASE-001、TC-PRD-036／037 |
| 检索、详情与互动 | S1-002 → S1-003／004 | API-PRD-007—021／024—031 的对应管理端或用户端入口。核对分类目录、禁发范围、检索、上下架、商品详情、评论及本人收藏；用户端手机和桌面均检查关键操作 |
| 本人查询、通知与恢复 | S1-001 聚合与事件、S1-002 商品收藏 → S1-003／004 | QUERY-001／002／003、NOTIFY-002—004、RT-001—003 的已启用通知范围。核对商品及收藏、未启用类型的响应、打开具体通知后的已读语义、通知重连补取，参见 TC-COM-022—025／029／030 |

准备一名卖方、一名普通浏览用户、两名具审核资格的管理员及分类、图片、商品审核数据。联调记录从卖方提交一笔附图片的分类申请开始，关联审核、商品、通知与文件标识，保存实际页面行为、接口结果与对应状态。使用隔离测试数据以便重复执行。

## 工程启动核对

- 初次搭建从无遗留文件的工作树核对源码、锁文件、迁移与启动脚本。
- 首个共享交付提供根 Maven 入口、两端独立启动和构建入口、OpenAPI 版本与类型生成命令、`.env.example` 和可重复准备的测试数据。提供方与调用方使用同一份 OpenAPI 和错误响应示例。
- 核对本地与 CI／Jenkins 使用的实际 JDK、Maven、Node.js 与依赖版本，分别记录本机探针和目标 Linux 证据。登记 PostgreSQL 测试库、Redis 命名空间及测试 OSS／SMTP 的资源标识。

开发期间应用[开发阶段用例选择](../implementation-plan/02-测试策略与依据.md#开发阶段用例选择)。开发证据随任务 PR 收集，开发完成后的系统验证与人工验收采用[阶段验收安排](../implementation-plan/03-阶段准入与验收安排.md#审查与阶段验收)。

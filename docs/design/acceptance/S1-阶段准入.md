# S1 阶段准入与并行开工检查

工程输入以最新 `main` 为准。实际批准版本、负责人和各编码任务 Issue 采用[准入模板](阶段准入记录模板.md)记录。

## S1 准入

| 检查项 | 预期及输入 |
|---|---|
| 责任和范围 | [S1](../tasks/S1-工程骨架与基础设施.md)的 Hello World、前后端、通用文件／事务／审计／调度／邮件设施、两套流水线及维护工具 |
| 运行环境 | 核对 Linux／OpenJDK 27、Maven、Node.js、GitHub Actions 和 Jenkins 的实际版本及入口 |
| 隔离资源 | 准备独立测试 PostgreSQL、Redis 应用前缀、OSS 独立范围与 SMTP 测试收件箱，登记资源维护人及凭据引用 |
| 预期及数据 | 示例迁移、Hello World 接口响应、两端构建和发布验证，初始化、清理及重试的独立数据 |

## S2—S4 同时开工检查

完整 S1 交付是 12 个子任务的共同工程前置。各子任务在同一交付点获得已运行验证的通用设施、共享契约、测试装配入口和隔离资源。

| 交接 | 预期 |
|---|---|
| 工程底座 | 干净工作树能运行根 Maven 构建、两个应用、依赖探针和测试维护入口，已核对 CI 及 Jenkins 证据 |
| 公共基础设施 | 用受控资格跑通真实 OSS 直传、核验、引用和读取；用示例用例验证事务、审计、幂等、Redis 投递、worker／scheduler 接管及 SMTP 发信。登记配置、独立检查入口和实际结果 |
| 公共契约 | 三个目标复核账户资格、商品占用、交易执行、三类会话、认领、通知、调度和文件接口的输入、结果、错误、锁序和幂等语义 |
| 独立验证输入 | 约定各子任务所需账户、角色和业务样例，以及共享接口的正常和失败语义。S1 提供前端占位和后端加载测试数据的方式；各子任务随实现编写其业务数据、替身及测试 |
| 责任与协作 | 逐项确认 12 个子任务的公开契约、修改边界、独立装配方式和数据计划。子任务使用 S1 的真实设施、公共契约、自身实现及其他业务的测试替身；其他子任务的完成或合并属于统一联调条件 |

每个子任务的独立启动、替换项、数据及预期见 [S2](../tasks/S2-商品与交易.md#独立启动与测试)、[S3](../tasks/S3-账户与沟通.md#独立启动与测试)、[S4](../tasks/S4-治理与管理.md#独立启动与测试)。开工前约定可调用的签名和测试装配方式。业务用例与前后端开发同步。子任务的 PR 从 S1 干净检出应用该任务改动，记录构建、启动、单元测试及必要检查的命令和结果，同时登记使用的替身及真实依赖。测试资源按任务隔离，测试配置和数据随任务维护。

S2、S3、S4 各自完成静态、适用单元／集成及人工联合检查后，统一验证真实交易、会话、通知、文件和处置链路。系统测试和验收在开发完成后按[测试策略](../implementation-plan/02-测试策略与依据.md)开展。

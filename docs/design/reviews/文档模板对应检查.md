## 字段与协作入口

模板字段覆盖表示记录结构完整。任务执行姓名与账号已登记；实际审查、提交、API／TC 编号、预期核验与执行证据在相应工作发生时登记；正式派发和阶段准入按实际条件核验。任务列待完成细化内容，已确认方向作为输入引用。

## 检查命令与记录

`python3 scripts/cli.py report --documents design` 生成整合材料；`python3 scripts/cli.py check --documents design` 核对一致性与本地引用。字段核对通过本轮一次性检查执行，具体运行结果随会话登记。编码及运行验证在其任务中执行并登记。

## 正向表述与并行检查

范围管理、变更评审和依赖条件采用正向等义字段，保持模板 A／G／H／I 的责任、范围、进度及审查语义。业务错误、事务回滚和实际测试结果按技术含义登记；协作流程由 GitHub Issue／PR 维护。

交界由唯一任务定义：TASK-003 维护商品交易联动，TASK-004 维护会话及处置执行，TASK-001 维护公共技术契约，TASK-002 维护商品分类本体。相关任务引用同源交付并完成本域适配，PR 指定一位交叉审查人。输入版本和接口准入按实际交付登记。

## 流程字段映射

依据当前协作要求，模板 A／B／G 的流程字段通过 GitHub Issue／PR 协作入口承接，索引登记材料范围及链接。业务状态、HTTP 状态、实际决定、测试结果、审查与验收事实保留在各自记录中。

## A.4 状态转换说明

### A.4.1 状态划分

商品的生命周期包括待审核、审核未通过、公开可交易、交易中和已下架。展示资格独立记录，管理处置撤销公开访问不等同于交易结束。交易记录包括待接受、已拒绝、已撤回、已关闭、进行中、有争议、已终止、已完成和异常交易；当前确认进度及冻结标记分别表达，不额外充当终态。

审核、举报、账户限制和通知分别保存各自结论或进度。审核记录承载当次内容、审核者、时间、结论及理由，商品承接审核后的业务状态；通知已读不改变来源业务对象。详细对象职责见[类分析索引](appendices/class-analysis/index.md)，状态定义见[行为与状态](requirements/05-行为与状态.md)。

### A.4.2 商品转换

| 规则 | 事件、角色与条件 | 状态及业务结果 |
|---|---|---|
| TR-01—TR-02 | 管理员处理本人认领的待审事项 | 待审核转为公开可交易或审核未通过；不通过须提供原因，审核结论留痕 |
| TR-03 | 卖方修改本人审核未通过的商品并重新提交 | 转为待审核，保留既往审核记录 |
| TR-04 | 卖方编辑允许修改的公开商品 | 保持公开，保存历史并通知相关买方，不二审、不关闭请求 |
| TR-05 | 卖方接受一条待接受请求 | 商品转为交易中，关闭其余待接受请求并记录原因 |
| TR-06—TR-08 | 交易完成或有效取消／管理终止；卖方决定是否继续上架 | 解除本笔锁单，默认下架；明确继续上架仍须满足审核及当前限制条件 |
| TR-09—TR-10 | 管理员有依据实施处置，或解决问题并解除限制 | 处置撤销公开访问并联动冻结、权限和待接受请求；解除后恢复原展示资格，不把原非在售商品自动改为在售 |

### A.4.3 请求与交易转换

| 规则 | 事件、角色与条件 | 状态及业务结果 |
|---|---|---|
| TR-11—TR-13 | 卖方接受或拒绝待接受请求，买方接受前撤回，或其他请求获接受 | 分别转为进行中、已拒绝、已撤回或已关闭；同商品仅一笔进行中交易 |
| TR-14 | 进行中交易发生单方完成确认，另一方7天未回应 | 先保留进行中并记录确认进度；超时转异常交易，按规则冻结并进入管理处理 |
| TR-15 | 已有有效约定，双方均确认交付及支付完成 | 转已完成，归档本笔交易分支，解除本笔冻结，商品按结束选择处理 |
| TR-16 | 任一交易方发起争议并说明原因 | 转有争议，继续锁单，不自动冻结或取消用户原权限 |
| TR-17 | 约定前买方取消或卖方申请获买方同意；约定后双方同意 | 有资格且未冻结／封禁时转已终止，解除本笔锁单及冻结并保留历史 |
| TR-18 | 有争议交易的双方有资格、未冻结且均同意取消 | 转已终止，不另要求管理员批准，其他有效限制保留 |
| TR-19 | 双方确认争议解决，或管理员解决本人认领事项 | 恢复进行中，保留锁单及有效约定，清空当前完成确认但保留历史；未解决则保持有争议 |

争议发生后原未回应计时结束；恢复进行中不立即启动计时，重新单方确认后才启动完整7天计时。恢复正常不等于完成、终止或自动解除其他限制。普通交易方完成交易前须先解决争议；管理员基于认领事项及处置依据调整状态另按管理规则处理。

上述转换的完整资格及拒绝条件以[规则与权限](requirements/04-规则与权限.md)为准。非本人操作、资格不满足、交易中编辑、重复接受已失效请求等情形不产生相应有效转换；业务记录和拒绝原因须与实际结果一致。

## ADR-004 Redis Streams 与 Taskiq

| 字段 | 内容 |
|---|---|
| 编号/标题 | ADR-004 Redis Streams 与 Taskiq |
| 协作入口 | [任务 Issue](https://github.com/iy88/se-course-project-1/issues/38) |

| 比较 | 见下表可行方案及影响 |
| 决定 | 采用 Redis Streams及任务执行适配器；IM 各实例独立游标读取并分发本机连接，worker 同组分担，数据库事件及调度记录支持认领和接管。 |

| 重新评估条件 | 实测路由、积压隔离或恢复成本显著变化。 |
| 替代关系 | 首次登记；后续替代关联新旧 ADR |

### 可行方案比较

| 方案 | 收益与代价 |
|---|---|
| 方案 A | Redis Streams 复用既有 Redis，需明确独立读取／消费组与恢复 |
| 方案 B | RabbitMQ 提供路由与投递机制，增加一套部署及运维组件 |

任务执行层通过适配器接入Redis；Taskiq是Python候选映射，最终任务库随后端技术栈选定。

### 第4批协议细化

[实时与任务](design/detailed-design/key-designs/实时与任务.md)定义数据库账户序号及恢复边界、Redis发布与每IM独立XREAD、连接ACK／背压、Taskiq同组任务分担、持久认领及token约束。Redis确认、客户端传输确认与主体已读分别维护。邮箱及文件等来源工作复用其自身持久记录；通用业务调度采用TaskSchedule。验证采用TC-COM-023—028，实际依赖版本随实现锁定。

## ADR-005 持久 Cookie 与 Redis Session

| 字段 | 内容 |
|---|---|
| 编号/标题 | ADR-005 持久 Cookie 与 Redis Session |
| 协作入口 | [任务 Issue](https://github.com/iy88/se-course-project-1/issues/38) |
| 背景 | FR-01；账户凭据失效及多连接。 关联 Q：Q-001。 |
| 比较 | 见下表可行方案及影响 |
| 决定 | 持久 HttpOnly Cookie＋Redis Session；绝对与空闲期限、有效活动节流续期；PostgreSQL 保存账户凭据版本及资格，每次鉴权核验；支持账户多 Session 和 Session 多连接。 |
| 理由 | 统一退出及身份依据，以 Redis 承担 Session 查询、续期和过期回收。 |
| 代价 | 账户校验仍有数据库读取；普通退出的故障恢复边界由 Q-001 明确。 |
| 验证 | 跨实例退出、改密失效、续期竞争及 Redis 故障恢复。 预期由对应任务的实际审查人核验，执行版本、环境、命令和结果在任务证据中登记。 结果位置随任务证据登记。 |
| 确认 | 本会话已明确采纳；确认姓名：袁尚峰；实际确认日期按会话记录登记，整理日期2026-11-13；交叉复核姓名及日期待登记。 |
| 重新评估条件 | 身份客户端、性能或撤销要求变化。 |
| 替代关系 | 首次登记；后续替代关联新旧 ADR |

### 可行方案比较

| 方案 | 收益与代价 |
|---|---|
| 方案 A | JWT 本地验签可减少会话查询，及时撤销需补充机制 |
| 方案 B | 服务端 Session 集中维护失效；Redis 支持共享查询及 TTL |

数据库 Session 便于持久查询，额外承担会话更新及清理；选 Redis Session 并以账户版本保障账户级失效。

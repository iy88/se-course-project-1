## 技术栈与结构

- 仓库布局：`backend/`（FastAPI）、`frontend/admin/`（管理端，仅桌面 Web）、`frontend/mobile/`（用户端移动 PWA）；运行期数据全部放 `var/`（Git 忽略）。
- 后端：Python 3.12 + uv 管理依赖；FastAPI + SQLAlchemy 2.0（async）+ Pydantic v2 + PyJWT + bcrypt；开发库仅 SQLite（`var/db/app.db`），启动时 `metadata.create_all`，本阶段不引入 MySQL 驱动与 Alembic 迁移（用户明确生产对接不在本期）。
- Redis：可用（本机已运行）。验证码等短时 KV 通过统一 `KeyValueStore` 抽象访问：配置 `REDIS_URL` 时用 redis，否则内存实现兜底；不编写其他中间件对接代码。
- 对象存储：`StorageBackend` 抽象（save/open/delete/public_url）。开发实现 `LocalStorage`，根目录 `var/storage/`（Git 忽略）；`OssStorage` 仅保留接口桩（阿里云 OSS 对接不在本期，用户明确）。文件访问走签名 URL（HMAC + 过期时间），配合 BR-22 未登录不可见业务内容的口径。
- 认证：JWT Bearer（ HS256，载荷 uid/role，默认 7 天）；密码 bcrypt。首版不做刷新令牌与登录失败锁定（BR-21 明示首版不设）。
- 实时消息：FastAPI WebSocket（`/ws`，token 鉴权）+ 进程内连接管理器；消息落库为准，WS 仅推送提醒。多实例部署的跨进程广播留待生产阶段。
- 前端：Vue 3 + Vite + Pinia + vue-router；管理端 Element Plus（桌面布局，窄屏提示），移动端 Vant 4 + `vite-plugin-pwa`（manifest + Service Worker，可安装）。开发代理 `/api`、`/ws` 到本机 8000 端口。
- 价格：库内以"分"（整数）存储，展示层转元，避免浮点误差；MySQL 阶段可平滑改 DECIMAL。

## 关键实现口径（需求 → 实现）

- 交易与请求同对象（`trades` 表），状态：待接受/已拒绝/已撤回/已关闭/进行中/有争议/异常交易/已终止/已完成；进行中内部以"当前有效约定"区分约定待确认/约定已确认待完成；冻结为独立布尔标记；单方确认进度用当前有效确认记录 + `confirm_wait_started_at` 计时。
- 商品状态：待审核/审核未通过/公开可交易/交易中/已下架；违规撤销公开为独立展示限制字段，与生命周期分开（4.10）。
- IM：`conversations`（NORMAL 按双人复用唯一；TRADE 按 trade 唯一）+ `messages`；未读按会话级 `last_read_message_id` 计算，仅打开会话时推进（BR-18）；交易结束自动归档分支；冻结按"用户对"判断（存在任一有效冻结即该双人两类 IM 禁发，BR-33）。
- 通知（4.17 全事件清单）：`notifications` 表，打开才已读；WS 同步未读数。
- 超时识别：后台任务每分钟扫描单方确认超 7 天（可配）转异常 + 冻结 + 共享池待办（TR-14）。
- 管理事项：`disposal_cases` 统一承载商品审核/举报/争议/异常/封禁事项的认领、问询、说明、申辩、结论与沟通单消息；唯一认领人约束在服务层校验（BR-34）。
- 评论长度与频率阈值、会话多端退出：8.4 明示设计阶段确定，本实现取保守值（评论 ≤500 字、同一商品 60 秒内限 3 条），登记于此。

### 后端 `backend/notification` 与通知入口

- `V5_75__create_notifications.sql`：`notification` 表以 `(recipient_account_id, intent_key)` 为唯一作用域，`read_at` 只记首次，不存展示摘要（摘要按读取人当前可见性投影）。编号沿用 #77 的 `V5_77` 工作区后缀约定，Flyway 视为 `5.75`，排在 `V5` 之后、`V6` 之前。
- `NotificationApplication.createNotifications`：同一事务写入通知与投递意图；重放返回已有记录，同键异内容返回 `NOTIFICATION_INTENT_CONFLICT`（409）。
- `NotificationApplication.markRead`：只写首次已读并登记一次 `notification_read` 事件；通知行经 `WriteTransaction.lock` 按公共锁序加锁；非接收人返回 `RESOURCE_NOT_VISIBLE`（404）。
- `NotificationQueries.list／get`：只读本人；`read`／`event_type` 过滤先于分页，`unread_count` 为本人全部未读、不受过滤影响；来源不可见时只返回获准提示且不提供跳转。
- `NotificationSourcePort`：来源投影端口，由商品／交易／事项模块实现。
- `ReviewNotificationAdapter` / `EnforcementNotificationAdapter`：与 #77 `ReviewNotifications.reviewDecided`、#81 `EnforcementNotifications.create` 签名一致，装配时用方法引用绑定即可；事件类型点分名按 S1 `EventIntent` 的 `[a-z][a-z0-9_]*` 规则折叠为下划线。
- HTTP 入口：`GET /api/v1/account/notifications`、`GET /api/v1/account/notifications/{id}`、`PUT /api/v1/account/notifications/{id}/read`。已读走 `WriteExecutor` 用例（声明 `NOTIFICATION` 锁键、事务内锁行、按 `Idempotency-Key` 重放）。身份经 `NotificationActorResolver` 端口解析，未装配时返回 503 `AUTHENTICATION_UNAVAILABLE` 而非放行。
- 装配：`notification` 已加入 `backend-app` 依赖；模块内 JPA 存储与配置均为 lazy，排除了数据源的探测上下文仍能启动。已读绑定只在 `infrastructure` profile 下注册。

## 未覆盖与待联调

- 前端未在真实浏览器中做人工走查（本轮无浏览器环境）；`mock` 数据源下的链路已由用例覆盖，`live` 数据源需在 #74 合入后走查。
- `frontend/shared/openapi.json` 本轮未改动，用户端消费的接口以 `src/api/contracts.ts` 的临时契约描述；提供方发布 OpenAPI 后应替换为生成类型。
- 真实 OSS、SMTP、Redis 未参与：文件上传在模拟数据源下不访问 OSS；真实直传与核验待 #74／#84 的文件 API 合入后联调。
- `mvn -f backend/pom.xml verify` 的 `backend-app` 重打包步骤因本地开发进程占用了 `backend-app-0.0.1-SNAPSHOT.jar` 而失败；本轮以 `mvn test` 完成全模块测试。停止本地开发进程后可重跑 `verify`。
- 前端单元测试已接入 CI：`ci.yml` 的前端 job 在 lint／格式之后增加 `pnpm run test`，README 的「CI 与发布」同步更新。

## 跨模块影响与后续条件

1. **通知身份端口**：`api.notification.NotificationActorResolver` 与交易侧 `TradeActorResolver` 形状一致（`accountId`、`sessionId`、`credentialVersion`）。建议 #74 提供一个基于 Session Cookie 的适配器同时绑定两者，或改为 `api` 包下的公共 `SessionActorResolver` 供各控制器复用；届时通知接口自动由 503 转为正常，无需改本模块。
2. **通知接入口**：#77 在审核决定事务内绑定 `ReviewNotificationAdapter::reviewDecided`，#81 绑定 `EnforcementNotificationAdapter::create`。意图键为 `product_audit.decision:<audit_id>`，收件人只取卖方。
3. **CSRF**：通知已读是浏览器写请求，需要 #74 绑定的 `CsrfGuard.Verifier`；未绑定时按设计返回 403。
4. **`frontend/shared/openapi.json` 的归属**：账户、商品、会话、事项接口目前只在设计文档与临时契约里。建议由各提供方在其批次内发布 OpenAPI；在此之前 `contracts.ts` 是唯一来源，变更须同步。
5. **实时协议**：`app/realtime.ts` 的 `hello`／`ack`／`resume` 帧形状来自 README 的投递描述，未在 OpenAPI 中登记，需与 S3-01 核对后再启用对真实服务端的连接。
6. **占位插槽**：`ProductCommentSection`、`ProductFavoriteControl`、`TradeReviewSection` 需由 S2-04／S3-04 的同名真实组件替换，替换前收藏与成交评价在界面上显示为「待接入」。

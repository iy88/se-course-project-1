# 开发环境真实 API 测试与生命周期数据

本文保留历史开发过程。测试代码现已收敛为唯一真实UC/US/SC全量入口及统一seed；下列旧smoke/SQLite/单元测试命令与计数仅描述当时状态，不作为当前执行指令。当前用法见[开发文档](../docs/development/README.md)。


- 任务：用**开发环境**做真实 API 测试，补充 14 个用户故事、12 组场景所需数据，并模拟完整使用生命周期；
  用户补充要求"图片也要"，商品图与举报证据图均走真实上传并校验签名 URL。
- 时间：2026-10-29（开发环境运行标识 `20261029-150527`）。
- 边界：只对运行中的开发后端 `http://127.0.0.1:8000` + 开发库 `var/db/app.db` + 本地存储执行；
  未修改后端、前端或需求文档；未 commit／push。开发库数据为演示数据，不进入生产。
- 结论：**321 PASS／4 FAIL／5 SKIP**（330 条检查项 + 补充核验 10/10），**0 次服务器 5xx**，
  2318 次真实 HTTP 调用；4 个 FAIL 归并为 **3 个需求-实现缺口**，均保留复现条件（见 §5）。
  开发库现有：35 个账户（含 1 个封禁样本）、88 件商品、65 笔交易、115 个处置事项、16 条举报、
  436 条站内通知、71 个 IM 会话、90 张商品图片、2 条带证据图的举报。
- 复核边界：本节至 §2 的数字均为 2026-10-29 历史运行 `20261029-150527` 的结果。此后对 harness 断言、
  覆盖统计工具、运行路径和本报告口径的修复属于复核与工具修复，**没有重新执行真实开发环境**；
  不得把修复后的代码、工具输出或静态检查写成新的通过结果。

## 1. 执行方式

1. 备份开发库与存储到 `var/backups/`（预检前、正式运行前各一次；`/var` 已 Git 忽略）。
2. 先在**隔离副本**（种子库副本 + 独立端口 8020 + 独立存储、内存 KV、默认 60 秒扫描）完整预演，
   结果同为 321/4/5、耗时约 94 秒；确认与开发库同基线后再对 8000 正式执行。
3. 正式运行命令（在 `backend/tests/e2e_lifecycle/`）：
   `../../.venv/bin/python e2e_runner.py --base-url http://127.0.0.1:8000 --results-dir <结果目录>`
   （`--db-path` 默认仓库 `var/db/app.db`；后端使用其他库时才显式传入。）
4. 全部数据只经真实 HTTP 接口创建；唯一非 HTTP 动作是 p08 的计时起点前移（见 §7）。
5. 运行后只读接口复核清单对象状态、只读 SQLite 快照、把覆盖矩阵与结果自动比对，
   并补跑 10 项真实 API 补充核验（含前端 5173／5174 同源代理、签名图片读取）。

复现入口：`../backend/tests/e2e_lifecycle/README.md`；结果产物：
